## SourceBaseline

Fields: repository-relative path; full implementation base SHA once isolated; byte length; UTF-8/BOM and newline facts; SHA256 of exact bytes; scan timestamp. Planning pins are recorded separately from the final frozen move base. Any changed source pin requires explicit map reconciliation before moving content; a line number alone never identifies content.

## Module

Fields: stable topic stem from approved spec; exact flat rule/example paths; `Read when`; prerequisites/dependency stems; permitted authoring surfaces; forbidden writes; exact example/contract references; relevant delivery scope. There are ten afterlife and seven Block_5 pairs, plus common core and retained routers. Dependencies are references, never duplicated authoritative payload. Cycles may reflect existing shared contracts but must be explicit and finite; route closure must not hide an unrelated all-module mandate.

## SourceBlock / DestinationSegment

SourceBlock key is `(sourcePath, sourceOrdinal, payloadSha256)`, not a heading/rule ID assumed unique. Fields: byteStartInclusive, byteEndExclusive; complete contextual unit kind (paragraph, list group, table row, numbered example, named scenario, XML rule group, wrapper/separator); original heading/rule/example IDs; ordered JSON snippet digests and inferred valid/invalid classification; exact destination path and segment locator; source hash.

Every source byte has exactly one classified owner; source intervals are disjoint and their union is `[0, sourceLength)`. A numbered example with dependent response fragments is indivisible. Parent tags/CDATA/applicability and the extractor’s nearby INVALID marker belong to the complete content boundary. Nested XML rule/example IDs are metadata, not independent cuts that discard parent scope. Block_5 ownership uses exact hierarchical components, not textual prefix matching.

DestinationSegment distinguishes `movedPayload`, `newNavigation`, `newWrapper`, and `approvedReplacement`. Only moved payload participates directly in source reassembly. Added table headers/document titles needed to host a block are explicitly inventoried; original headers still have one original source owner. No duplicate full authoritative source is allowed behind a retained old path.

## NavigationEdit

Fields: editId, reason (`pathOrAnchor`, `approvedConditionalReading`, or separately approved `D01Resolution`); source block key and exact match offset; original bytes; replacement bytes; old/new target and anchor; approval/source reference; expected match count=1. Updates at multiple physical occurrences are separate rows. Edits cannot overlap. Reverse application on the exact destination segment must restore the source block hash. No regex-wide ignore, global newline normalization or unrecorded prose rewrite is permitted.

`D01Resolution` is unavailable until coordinator disposition; the inventory can record a proposed replacement while its status remains blocked and it is not applied. A new gameplay contradiction is a finding, not a NavigationEdit permission.

## ReadingRoute

Fields: situation name; existing request/realm/pending/repair predicates stated in prose; mandatory core applicability; selected module set; explicit prerequisite closure; exact example anchors; exclusions inherited from the actual task. This is a documentation table plus test fixtures. The live game does not evaluate a newly invented selector DSL.

Required route fixtures: bootstrap manifest/README only; ordinary afterlife; scheduler debt; two simultaneous pending families; narrow receipt-only task; issued wound A/B frontier; exact repair packet. Multiple contracts produce a union of dependencies, while receipt-only/bootstrap remain narrow according to existing authority.

## CoverageMapping

Fields retain the existing manifest’s scenario/contract IDs, runner, source-file/fragment association, validationKind/exemption, required text, ordered inputs/companions, expected modified/absent/unchanged files, and coverageLimit. Only documentation file/anchor/line locators are remapped. Duplicate snippets require occurrence keys (source block + ordinal), not SHA alone. Coverage equality compares all non-location fields and exact extracted ordered payload after reversing approved path edits.

## DeliveryRecord

Fields: source documentation relative path and hash; package operational-resources path/hash; daemon docSpecs role; session-local destination/hash; required links/anchors/dependencies; advertised directive origin; actual read scope; observed result. Source/package/session are three distinct facts. A repository file does not prove session delivery. Missing fixed-list copy must fail the bounded check, not silently disappear from the expected inventory.

## BlockEvidence

Fields: block A/B; tested source SHA and binary pins; planned/actual cases/descriptors; selected categories/reasons; complete raw artifacts; failures/skips/timeouts; owned root cleanup; independent source/selection/evidence verdict; coordinator readback; remote carrier SHA/recovery status. No record exists yet. Draft task counts are not execution counts.

## State transitions

Draft planning → coordinator-reviewed artifacts → reconciled frozen source map → test-first/source WIP → selected evidence → independently accepted A → B allowed → accepted B → coherent final handoff. Unresolved D01 blocks its own read-direction edit; base drift blocks moving the affected content; missing delivery/coverage blocks the relevant block acceptance. Issue closure/main/PR/merge are outside the authorized flow.
