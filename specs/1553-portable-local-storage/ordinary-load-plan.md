## Global constraints

- Trusted local single player; exact content/absence, current schema, allowed roots and type/link boundaries, one participating writer. No inode identity, protective hardlinks, anti-owner race defense, privileged service or new supervisor.
- Preserve existing original load schemas, handlers, generation readers and physical receipt controls for their original evidence. Original-handler-or-block precedes new admission. New scratch must never look like legacy evidence.
- Preserve every existing manual/autosave/checkpoint file, including the selected archive, across commit, rollback and cold recovery. External `client_profile/qte_showcase_rewards.json` remains outside this replacement set.
- Keep archive contracts: 8,192 entries; 2 MiB total UTF-8 entry names; 4 MiB manifest; 8 MiB soul state; 64 MiB ordinary entry; 512 MiB aggregate durable expansion; ratio 200 above 1 MiB grace. These are reader limits, not a compressed-ZIP ceiling or an existing-live-tree bound. Manifest remains schema 1 / SHA-256; its existing optionality and durable coverage rules remain.
- No second journal, whole-ZIP image materialization, multi-commit replacement, destructive unjournaled directory pruning, or gameplay replay to rebuild histories.
- Quiescent storage acceptance is separate from real GM/provider confirmed-stop integration. B4 remains open; leases alone do not prove a provider stopped.
- Category-only verification, complete results and owned cleanup; no full suite or sequential all-category sweep. Publish bounded WIP and verify remote SHA before lengthy verification/review; final acceptance also requires fresh restoration and independent review.

## Resolved behavior and dependent engineering design

1. **Topology conversion is required.** Current `AddDirectoryToArchive` (:766) recursively saves arbitrary files under the selected roots. Thus two valid current-produced snapshots can contain `lore/custom` as a file versus `lore/custom/entry.json`. This is not just a malformed archive. File-only B1 preflight/recovery cannot implement either file→directory or directory→file by ordering file deletion; `TrustedLocalFileScope.ValidateFile` (:99) rejects a directory and ancestor validation (:184) rejects a file. Preserve both valid conversions, including an empty or nonempty old directory, before public caller cutover and complete ordinary-load portability (T032-B2). Design/review a versioned namespace extension inside the same B1 decision/recovery protocol; do not pretend the current file-image adapter suffices or present a temporary rejection limit as completion. Incoming `a` plus `a/b`, and files at/above required directories, are intrinsically conflicting and should still reject before mutation. Harmless empty directories may remain where they do not obstruct a declared supported conversion.
2. **Both configs absent uses standard product defaults.** Present archive config means strict validation and exact imported bytes. Missing archive config means retain exact validated live persisted config bytes, not a preview/draft. If both are absent, retain disk absence and prepare a detached fresh `new GameSettings()` baseline; apply it to runtime only after committed replacement. This follows both actual products: `Program.cs:110` and `WebUi/LocalWebUiHost.cs:51` construct fresh settings, then `Core/GameEngine.cs:191` / host `:87` bootstrap before menus. `StateManager.cs:50–60` owns explicit default-config creation during bootstrap; `plan-history-through-b3a.md:197` documents defaults only for genuine absence. The constructor merely keeps its mutable injected object (`StateManager.cs:43–47`), not an immutable initial-profile authority. Existing no-config service fixtures also use `new GameSettings()` (`SaveLoadServiceTests.cs:69–72`). Do not invent an initial-profile API, capture runtime previews or persist config within load. Prove default runtime/cold-start parity through a focused test. No user-facing ambiguity or owner question remains.

Independent work while the topology extension is technically finalized: causal entry tests, portable extraction/inventory/projection, all three config cases, complete member planning and connected image/generation publication, metadata work and typed outcome tests. The topology extension is a required dependent gate, not a new owner-policy question. Do not claim full public load acceptance before its positive/cold conversion cases pass.

## B1 metadata: localized technical extension, not an owner-policy choice

Keep the existing v2 framing and JSON field/region semantics. Replace the save-only whole-header byte-array/DOM read with incremental parsing of the length-delimited metadata region, retaining required/duplicate/unknown field checks, exact region bounds/hashes, supported property order and generation policy. Keep only the complete path/image descriptor set needed for all-member preflight; avoid duplicate whole metadata buffers and redundant header/member arrays. The writer can stream the existing header/descriptor sequence and patch its private length slot as today. Keep original v1 decoding and existing ≤1 MiB v2 evidence readable; no format reinterpretation or second journal.

The declared metadata length must be checked against the actual file region before parsing, never used as an unchecked allocation size. Parsing consumes that region only, with bounded working buffers; unavoidable descriptor/path memory is proportional to the actual complete member set. The incoming envelope does **not** bound old live member count/name bytes. Do not merely raise 1 MiB to another arbitrary ceiling, silently discard old deletions, or partition publication into transactions. Qualify the actual legal archive maximum, long/escaped paths and a larger disjoint current tree. Controlled allocation/I/O failures must occur before live mutation or preserve authoritative evidence on recovery; safe resource failure is not proof that the full supported envelope loads. This codec change needs focused technical design/review before implementation, not a new anti-player validation system.
