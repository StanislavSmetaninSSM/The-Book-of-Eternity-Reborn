## M1: first implementation slice

One connected block, with three ordered implementation parts and narrow checkpoints:

1. **Production root/launch admission and packaged asset.** Add a consumed internal production main launch capability derived from the actual original main guard, exact root/generation and snapshot of existing GameSettings. It carries explicit NativeLineage, resolved PowerShell7 executable/argv, unchanged `GmCliLaunchCommand`, existing cwd and input profile. It cannot be minted from decoded main.json/status/PID, environment flags or a neutral/worker permit. Extend existing coordinator/factory methods to consume it; do not expose a second owner or weaken fixed-neutral admission.
2. **Existing launcher and real consumers.** Port Start-Bridge/Start-Daemon and the participating assembly resolver to the shipped layout on Linux. Connect portable transport selection at actual console/daemon/status/QTE/repair boundaries, gate Windows-only startup, and scope ordinary console bootstrap/health mutations. Preserve T042 operation identity, draft/takeover/cancel and typed unknown result; preserve F2 completion through finalization/lease disposal.
3. **Controlled qualification of that ordinary path.** Use an explicitly prepared isolated root/profile, configured persistent neutral CLI and shipped prebuilt helper. Invoke actual launcher/daemon entrypoints and real pipe accept loop with bounded guardians; prove two inputs in one CLI lifetime, exact stop and refused fresh launch/canonical mutation on retained uncertainty. No `--neutralPackage` escape path substitutes for production admission in these cases. Inert extracted PowerShell functions test the real consumer logic without starting provider or touching saves.

**Backend/configuration decision (technical proposal):** recognize one portable owned-bridge transport alongside the existing Windows `ConPTYBridge` name, with a separate main ownership request (`Auto`, `SystemdUser`, `NativeLineage`). M1 explicitly requests NativeLineage; it does not enable Auto or silently downgrade SystemdUser. Reuse the backend selection vocabulary, but do not turn worker `NeutralHost`/`WorkerRelease` into a main permit. Schema1 `LinuxSupervisor` describes this native implementation; status exposes actual NativeLineage and `ordinary-same-namespace-lineage`, run and retained uncertainty. Systemd main remains T041-SYSTEMD-MAIN, unimplemented/unqualified here; future adapter/record identity must distinguish its authentic scope. Windows ConPTY/Job is retained and native Windows qualification remains separate.

**Command/presentation:** preserve the game profile's arbitrary PowerShell command semantics: Linux root is resolved `pwsh -NoLogo -NoProfile -Command <exact configured command>` on the original held PTY; no extra bootstrap paste/Enter or Codex flags/model rewrite. It waits for the configured CLI and exits when that invocation ends; exact root exit is notification, followed by scoped stop. Resolve relative cwd against the existing session path, validate it before launch, and do not create configured directories before admission. Empty command refuses this configured-CLI route before creation. Profile/model changes apply to a later freshly admitted run, not a silent current-run restart.

The first Linux presentation uses existing `start-bridge visible` in the foreground of a caller-supplied terminal. Bridge owns that terminal's keyboard/raw output/resize; console client and daemon use their existing entrypoints in separate caller-supplied terminals/processes. They must not compete for one physical stdin. No Linux terminal emulator install/automatic windows, detached hidden manual-input promise or terminal multiplexing UX. A single-window experience is a later product choice if requested. The profile's application paste/submit gestures remain separate from outer-terminal clipboard gestures. Preserve the actual inherited TERM; do not advertise an unimplemented renderer or auto-answer terminal/trust/access prompts.

**Distribution:** use existing BoeNativePackageDirectory/BoeRequireNativePackage and package validator. A publisher builds the helper once from pinned source; release asset includes helper and package-manifest at `runtimes/linux-x64/native`, executable bit, measured glibc minimum, protocol2, source/compiler/binary provenance. Publish bridge and participating client plus existing Launcher/daemon/operational resources in one documented relocatable layout. Existing resolvers select installed assemblies first; source-tree build fallback is developer-only, not the shipped player path. Missing/mismatched/RID/ABI/mode failure refuses before Prepared/child creation; no compiler/download/install/service/PATH-helper fallback. Initial support is measured linux-x64/glibc; other RIDs need their own build/proof.

### Authority, publication and consumer order

Pure profile/package/executable/cwd validation has no child or canonical effects. Acquire original main guard; inspect main record without replay/recovery. Establish independent durable worker authority from the existing ledger/context, even with all helpers disabled, before canonical recovery or Prepared. An observed worker snapshot can refuse; only the original coordinator/lock may establish positive admission. Missing inventory may be initialized through that existing coordinator's admitted metadata path; malformed/nonterminal/debt refuses without clearing anything.

Hold one worker coordinator/root registration in the bridge for the original main lifetime. Do not open another exclusive worker coordinator in each remote C# operation helper. Original main pin admission validates the retained worker/storage conjunction; remote participating writes borrow the original live connection and quiescence held by that owner, rather than minting authority from status or inventory JSON. In a cold/quiescent client before main startup, acquire its own original main/quiescent worker admission for the bounded operation, then release it. All participating entrypoints must attach this admission before recovery; unregistered FS cannot silently treat a known worker namespace as safe. No production worker launches occur in M1, so retained worker quiescence cannot be released to start jobs. This connected production registration is required work, not an existing F3 claim.

Then original main admission → lifecycle → canonical/storage lease; confirm generation, publish Prepared; release canonical lease; prepare authentic held terminal; under the original metadata scope publish Running/readback and recheck generation; drop canonical/transition gates; single release. Keep the existing run/root identity through pumps/T042/status/pins. Release canonical/short transition gates before supervisor or bridge IPC, child waits, I/O/disposal and drain waits. Never await operation-pin drain while holding lifecycle. The original lifecycle lease may span held preparation/single release and owned retirement/I/O settlement/Stopped publication, exactly as in the accepted coordinator; this is not a ban on those owned-start/stop waits.

Startup/bootstrap/health and each real turn/QTE/repair/control/status mutation borrow bounded original pins before generation/recovery/leases; nested consumers share that context through closing and disposal. Durable Stopping closes ordinary writes; only accepted narrow no-recovery closing and already-linearized settlement remain. Stop seals input, drains original pins, stops the actual lineage, joins real I/O/keyboard/output/status/resize/disposal, then publishes Stopped/ACK. Any uncertain stop/I/O/authority/publication retains owner/slot/debt and blocks replacement/fresh launch. Physical guardian cleanup never changes logical Uncertain. Cold nonterminal records refuse; valid Stopped permits only a new epoch after independent conditions, with no old input replay.

Canonical replacement/clear/Load/generation-changing recovery still require original quiescent admission before lifecycle/replacement/canonical locks and through release/refresh. Preserve exact existing Committed/RolledBack/Uncertain outcomes. M1 keeps current low-level refusal during a live main; it neither auto-stops nor fresh-launches after Load. No protection against the player editing their own closed saves is introduced.

### Criteria and future verification selection

Concrete user-visible result: ordinary Linux launcher starts the configured persistent CLI with visible declared NativeLineage scope; manual and automatic inputs share it; another admitted CLI epoch begins only after confirmed original retirement. Proof is initially neutral/configured/isolated, not live gameplay.

- Causal RED→GREEN for ordinary Linux admission/launcher, installed-package resolution and actual daemon startup; successful neutral-only tests do not count as RED for this path.
- Distinct configured non-Codex command and sentinel model/arguments/cwd arrive unchanged; positive package relocation starts without source tree or native compiler invocation. Negative package/profile/admission cases: no child, input, Prepared or canonical recovery side effect (admitted owner metadata is reported separately).
- Real ordinary console startup/health then turn/QTE/repair consumer calls obtain original pins and preserve typed outcomes. A real daemon process on Linux starts without Forms/user32/window or clipboard fallback. Missing/unsupported profile, manual draft and unsupported view safely pause without submit; opaque connection loss preserves before/after ClosedObserved distinction.
- Persistent CLI: two inputs, Unicode, same run/root process, resize/EOF, draft/takeover/cancel via real pipe loop. Exact scoped stop/disposal/Stopped ACK; owner/metadata debt/cold nonterminal refusals and confirmed fresh epoch; no unknown-command retry.
- Independent unresolved worker or storage condition prevents main admission and participating recovery/mutation even when helpers are disabled; a second process cannot bypass the retained worker guard. All fixture guardians prove own ECHILD/resources; retained logical evidence is not deleted.

Propose two new narrow categories: `gm-main-production-admission` (pure package/config plus controlled actual main root/fence) and `gm-main-linux-launcher` (ordinary launcher/daemon/console/real pipe integration). Split only if measured budgets demand it; inspect exact membership before implementation. Real PowerShell function fixtures stay inert, native fixtures bounded and isolated. Use only `scripts/test-csharp.ps1 -Category <selected IDs>` for future RED/GREEN; catalog/PlanOnly discovery is not execution. Reuse F1–F3/terminal/T042/R1–R3, adding only exact regressions selected by changed shared helper/pin/storage contracts. No old-cohort union, full suite/Fast/PreMerge or native Windows/systemd claims.
