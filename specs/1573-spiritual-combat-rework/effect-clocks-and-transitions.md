## 1. Что действительно есть в смертной системе

- [Block_17](../../Rules/Block_17.txt),17.3: длительность действий в целых игровых
  минутах:0–1 для краткого,1–5 для небольшого,5–30 для среднего,30–120 для долгого.
  Несущественное время допускает0/null. Это не одна минута за любой ответ.
- [Block_13](../../Rules/Block_13.txt) различает полный раунд и часть раунда
  в FullParty. Фиксированные6секунд/15секунд/минута на раунд не обнаружены.
- [Effect contract](../../OtherGuides/Effect_Materialization_Contract.md),§5:
  turns, until_time, uses, scene, source_bound, condition_bound, permanent, manual
  являются разными профилями. until_time — deadline по игровым минутам;
  это не автоматический генератор тиков и не конверсия turns.
- [Примеры](../../Examples/E_CLI_Effect_Materialization.txt): Battle Focus
  +2 Dexterity на3 owner_turn_end; отдельно until_time.duration60 —60 минут.
- [Composer](../../BookOfEternityClient/Services/EffectAcceptedTurnInputComposer.cs):
  Автоматическая mortal-композиция выдаёт owner_turn_end по accepted ответу даже вне
  боя. Нулевой и60-минутный ответ дают один такой event. ReadCanonicalWorldTime
  читает absolute currentTimeInMinutes/root или setWorldTime, но не timeChange.
- [Scheduler](../../BookOfEternityClient/Services/EffectLifecycleScheduler.cs):
  turns уменьшается по phase; until_time истекает по deadline. Periodic routing
  [Planner](../../BookOfEternityClient/Services/EffectAcceptedTurnPlanner.cs)
  обрабатывает supplied events, без универсального поминутного catch-up.
  [Progression service](../../BookOfEternityClient/Services/ProgressionScheduleService.cs)
  отдельно умеет fallback+timeChange; общего надёжного absolute clock для всех
  форматов нельзя считать уже готовым.

Переносим владение эффектом, явные часы, игровой отсчёт и source-owned правила.
Не переносим случайное равенство «ответ=тик» или недоказанную конверсию.
Числа ниже — адаптация для духовного мира, не цитата смертных правил.

## 2. Короткие боевые эффекты: один оставшийся ход ↔ одна минута вне боя

У обычных боевых горения/яда, усиления, ослабления и барьера одна история срока.
В бою она продвигается на одну единицу **в конце следующей личной возможности
носителя**, вне боя — на одну единицу за духовную минуту. Это игровой коэффициент
срока, **не утверждение «раунд занимает минуту»** и не ускоритель мировых часов.

| Профиль | В бою (уже принято) | Вне боя с нуля (предложение) |
|---|---|---|
| T147 обычный DoT |3 следующих конца личной возможности; partial те же3 со слабее уроном |3 тика через1,2,3 минуты |
| T145 усиление / T141 барьер | До конца3-й следующей личной возможности |3 минуты |
| T146 полное ослабление |3 следующие возможности |3 минуты |
| T146 частичное ослабление |1 следующая возможность |1 минута |
| Короткий контроль T141 | Его принятые1/2 возможности, без новой длительности | Соответственно1/2 минуты; ограничения действий сохраняются |

Длинные профили §6 не получают эту конверсию по одному слову «яд»/«барьер».
Число других участников и ходов противника не ускоряет срок владельца.
Контроль/HP0 не исключает предусмотренную личную возможность из отсчёта.
Если эффект появился внутри уже начатой возможности цели, её конец исключён
(принятые T141/T145–147). Вне боя новый периодический эффект также не наносит
первый урон сразу: начинает с нулевого возраста; первая граница через минуту.

## 3. Остаток переносится, а не назначается заново

Для короткого профиля храним точный возраст a в условных единицах срока и общую
продолжительность N; остаток max(0,N−a). Переключение режима само по себе добавляет0.
Вне боя прибавляется прошедшее духовное время в минутах. В бою —1 за допустимый
конец личной возможности. Время, которое world clock отнёс к этому боевому
интервалу, второй раз в возраст короткого эффекта **не добавляется**.
Точный дробный остаток сохраняется; округление для UI не меняет состояние.

Тики обычного трёхтикового DoT назначены на a=1,2,3. Вне боя scheduler доходит
до точной границы; в бою прибавление1 исполняет пересечённую границу в конце
этой возможности. Последний тик выполняется до истечения. Исполненные ordinals
сохраняются. Округлять a к целому на каждом входе/выходе нельзя.

При частичном остатке в бою окончание происходит на первом допустимом конце,
который достигает N. Например,2.6 единицы — ещё3 конца личных возможностей;
после первого остаток1.6, а не заново2. UI не обещает «точно2.6 хода».
Это явно выбранная дискретность личного хода, не бесплатный новый полный срок.
Смена режима без времени/личных возможностей не может сохранить срок после
того, как одна из его границ уже наступила. Режим определяется состоянием
участника/схватки, а не переключателем игрока ради задержки тика.

Пример: наложили яд, прошёл первый допустимый конец (a=1, тик1). Бой завершился.
Прошло30 секунд вне боя (a=1.5). Начался новый бой. В конце следующей личной
возможности a=2.5, исполняется только тик2. Бой завершился. Через30 секунд a=3,
тик3 и удаление. Ничего не восстанавливается/не удваивается при смене сцены.

Другой пример: барьер потерял70 из100, ему осталось2 единицы. После минуты пути
останется30 ёмкости и1 единица срока. Новый бой не возвращает ни100 ёмкости,
ни3 хода. Рост максимума/загрузка/смена режима также не пополняют его.

## 4. Что считается временем и как исполняется длинное действие

Используем принятую игровую длительность действия, не часы реального компьютера,
число сообщений, открытий меню или частоту опроса. Нулевое игровое время даёт0
возраста. ГМ не может объявлять существенно длительные действия нулевыми ради
баффа; время соответствует Rules/сцене/профилю действия. Длительность применения
искусства определяется его действием/сценарием; этот проект не делает все
очищения мгновенными и не вводит всем искусствам минутное время подготовки.

Отдых/путь/обыск на20минут не заменяет три тика одним и не замораживает их:
клиент обрабатывает наступающие границы по порядку. Для управляемого игроком
персонажа **первый новый вредоносный тик прерывает длинное спокойное действие**
после разрешения события; показывается состояние и возможность потушить/очистить/
лечиться. Без нового выбора нельзя незаметно промотать до нуля HP. Урон,
не прошедший текущие защиты, всё равно расходует данный тик и сообщает причину;
не откладывается до исчезновения барьера. При продолжающемся осознанном ожидании
последующие события также исполняются; ожидание само по себе не снимает эффект.

HP0 прекращает действие независимо от других причин; действуют принятые
[распад формы/восстановление](zero-health-and-form-recovery-proposal.md).
Нет отрицательного HP/автоматического развеивания души/потери Маски. Часы эффекта
не замирают на HP0, будущие тики не восстанавливают уже поглощённый урон.
У неуправляемых/отдалённых целей нет паузы времени от закрытого UI: события мира
исполняются до нужной границы; сохраняются последствия и допустимые действия NPC.

Бесплатный отдых [T090](out-of-combat-recovery-proposal.md) применяется лишь к
реально прожитому допустимому интервалу: P+H_perm/20 ДЭ в минуту, HP25% за
часовой период. Не начислять весь20-минутный отдых до тика на первой минуте;
прерывание на минуте не даёт часовое HP. Выход из боя сам не лечит/не очищает/
не восстанавливает ДЭ. Камень всё ещё требует1минуту вне боя; готовый итог нельзя
выдать до завершения его использования. Это не новый запрет отдыха с эффектами:
профиль/обстановка решают доступность, а опасное событие останавливает промотку.

До входа в бой выполнить всё, что уже наступило за внебоевой интервал; после
выхода не повторять последний обработанный личный конец. Существующий fight
не завершён лишь потому, что игрок пожелал уйти; требуется конец/успешный отход.

### Общая граница и порядок

Порядок задаётся зарегистрированными phase/priority и устойчивой identity,
не порядком JSON/словами ГМ. Для нового clock-профиля:
1. Состояние/непрерывное допустимое восстановление продвигается до границы.
2. Исполняются назначенные на неё periodic события в зарегистрированном порядке;
   каждое использует текущую цель и сохранённый источник. Нельзя переставить
   HoT/DoT задним числом ради спасения/гибели.
3. Истекают завершившиеся lifetime. Финальный тик эффекта не теряется;
   барьер/усиление, истекающие на той же границе, ещё действуют для её тиков.
4. Завершения долгих действий, назначенные на эту же границу, разрешаются после
   этих событий, если действие не прервано. Очищение, завершённое раньше, снимает
   будущие тики. Завершённое ровно в момент тика не отменяет уже наступивший тик.

Прерывание действия фиксируется после опасного события, но новый выбор игрока
открывается после всех уже наступивших событий той же временной границы и их
expiry. Нельзя паузой отложить соседний одновременный тик; более поздние события
ещё не исполняются.

Это новая явная tie-policy для T148, не обещание, что mortal runtime уже её
реализует. Если повреждение оборвало выполнявшееся действие до результата,
нельзя выдать его завершённую награду. Ресурсы конкретного действия следуют
его контракту; этот блок не назначает всем предметам новый расход/возврат.

## 5. Ущерб и снятие не меняются при выходе из боя

[T147](periodic-damage-budgets.md): исходные3 тика, исход/крит/source snapshot,
свежие сопротивления цели→порог→остаток личного барьера→одно округление HP.
Нет второго status-R броска на каждом тике, нового crit/мастерства/награды.
Очищение/рассеивание, lawful recast и независимые группы сохраняют договоры
[T143](cleansing-proposal.md)/[T144](hostile-dispel-proposal.md).
Простой выход из боя не считается source loss для независимого DoT/баффа.

Тик наступил и был поглощён — он исполнен. Снять барьер позже не значит вернуть
этот тик. Повторный accepted-event/recovery/loading не продвигает часы и не
наносит урон снова. Source snapshot не пересчитывается из нынешней экипировки;
живые защиты цели могут измениться перед следующим событием.

## 6. Долгие яды, длительные усиления и источники

Не весь яд обязан заканчиваться через3 минуты. У искусства/предмета заранее
может быть другой, отдельно оплаченный/описанный профиль:
- «Яд на30 минут, урон каждые5минут» — пример absolute-time профиля, не новый
  утверждённый предмет/бюджет. Он продолжает тот же срок внутри боя. Не сжимается
  до3 ходов, не получает дополнительный тик каждый owner_turn_end.
- «Благословение на1час» — истечение по своему deadline в обоих режимах.
- Аура/эффект экипировки — связь с источником; проклятие до очищения — явное
  условие/manual; заряд — расход по uses. Иконка не делает их трёхходовыми.

У всех периодических вариантов отдельно заданы срок, частота/число тиков,
первое срабатывание, снятие, source-binding и порядок. until_time один не
создаёт периодического урона. Мощность/цена/частота новых долгих профилей ещё
не утверждены; нельзя заменить ими дешёвый короткий T147 без отдельного бюджета.

Для absolute-time боевое время задаётся общей принятой хронологией, не числом
чужих ходов. Этот проект не устанавливает универсальные секунды на раунд.
До production обязателен один нормализованный authority длительности в том числе
боевых сцен: отсутствие timestamp нельзя трактовать как истечение или бесплатную
заморозку, а timeChange нельзя подставлять вместо absolute current time.

[Духовные часы](living-world-events-proposal.md):1 духовная минута за365 смертных,
с сохранением долей, без повторного начисления уже учтённой жизни. Духовный
эффект остаётся прикреплён к своей душе/духовному clock domain; смертный ход не
становится её духовной личной возможностью. Нельзя копировать его тики на тело
без явно заданной связи. Сами переходы между духовными пространствами добавляют
только реально затраченное время, без сброса срока/остатков. Ни закрытие игры,
ни пауза пользователя не двигают игровой календарь сами по себе.

## 7. Подача игроку и зависимости реализации

В бою: «Горение: осталось2 срабатывания, следующее в конце вашего хода».
Вне боя: «Горение:2 срабатывания; следующее через30с, последнее через1мин30с».
Барьер: «30/100; осталось1мин» или «истечёт в конце следующего личного хода».
Длительный эффект: его реальные минуты/часы и момент следующего тика. Короткая
подсказка объясняет коэффициент1минута↔личная возможность; не скрываем конверсию.
Длинное действие заранее предупреждает о ближайшем известном вредном тике.
UI округляет вверх для отображения, не записи сроков.

Будущая реализация требует: единого normalized духовного clock authority;
явной source-owned policy короткого гибридного срока поверх общих effect
контрактов; сохранения дробей/first eligible opportunity/consumed ordinals;
обработки границ и прерывания long action до публикации его финального результата;
одного idempotent accepted transaction для clock/lifetime/resource/effect results.
Это не простая замена поля turns на until_time и не скрытый GM-таймер.

Статические definitions и source snapshot повторно используем через существующий
сервис/репозиторий/кэш. Текущие target defenses, HP/ДЭ, barrier remaining и revision
нужны свежие. Не сканировать каждую секунду долгой жизни: переход к следующей
значимой границе; агрегировать лишь доказуемо эквивалентные участки без боевых
пересечений/решений/изменений защиты. Не вводить новый параллельный кэш.

## 8. Проверяемые примеры

- a=1, затем0.5мин вне боя, затем одна личная возможность, затем0.5мин:1→1.5→2.5→3,
  ровно3 тика за всю историю. Дробь не исчезает при переключении.
- 0.4мин вне боя + один личный конец дают a=1.4, остаток1.6 из3; если выйти,
  следующий тик через0.6мин, последний через1.6мин.
- Остаток барьера30/100 после1мин из оставшихся2 единиц:30/100 и1, не100/100.
- HP80, яд по35: ожидание20мин останавливается после1мин сHP45; после осознанного
  продолжения второй тик даётHP10, третийHP0. Без выбора не списываются20мин.
- Три отдельных интервала по20сек и один интервал1мин дают одинаковый первый тик.
  Сотня UI-чтений/нулевых игровых ответов не даёт ни одного тика.
- 365 смертных минут одним интервалом или365 раз по1/365 духовной минуты дают
  ровно одну единицу внебоевого возраста, не0 из-за округления.
- На границе a=3 последний тик происходит, затем expiry; эффект с уже
  исполненным ordinal3 после recovery не наносит четвёртый тик.

Это арифметические сценарии проекта. Полный future scheduler/бои не запускались;
проверка не доказывает общий баланс и не означает принятие нового коэффициента.
