# Пять характеристик, культивация и духовное развитие D

2026-10-28, кандидат v1.2. Часть [spec](spec.md), задача [#1573](https://github.com/StanislavSmetaninSSM/The-Book-of-Eternity-Reborn/issues/1573).
**Разделение денежной награды и Просветления за жизнь принято; числа ещё
предложены для рассмотрения, production не изменён.**
Автор запросил стартовые значения, цены, окончательную связь Просветления/Сияния
с D и разрешил переработать культивацию. Это продолжение D7/D8, не разрешение
исполнить старые plan/tasks. HP/ОД, баланс искусств и полный lifecycle Обители
остаются отдельными темами. Принятые пять характеристик, сознательные вложения,
постоянное последовательное развитие и mortal-ядро проверки сохраняются.

## Выбор подхода и существующие основания

Рекомендуется оставить знакомые Перья средством вложения, разделить покупку
базового стата и развитие E/R, а D вычислять из накопленного развития. Отдельные
очки опыта/валюту характеристик не вводить. Сохранение старой культивации с новой
ценой статов не подходит: сейчас минимум20 Перьев даёт80 E при пороге вознесения60.
Автоматическая раздача статов за ранги противоречила бы сознательным вложениям.
Это рекомендация исполнителя, а не уже выбранный автором набор новых чисел.

Проверено в исходниках:

## 1. Создание души и покупка характеристик

Мощь, Чуткость, Воля, Цельность и Благоволение начинают с **5**. При создании
игрок распределяет **10 бесплатных пунктов**, не более10 в одной характеристике.
Исходная сумма после распределения35. Например10/8/7/5/5; равномерный вариант7/7/7/7/7.
Нельзя опустить исходные5, продать бесплатные пункты или превратить их в валюту.
Это однократный шаг создания души, не каждой смертной жизни/вознесения.

Старт E0/R0/D0, кошелёк0 плюс фактически заработанная tutorial-награда.
Расколотая маска применяет только свои согласованные бонусы при экипировке;
она не увеличивает базовую раздачу и не передаёт силу исторической роли.
Сильные NPC и исторический Маска получают собственные явные профили, а не
обязательный старт нового игрока. К ним применяется та же математика развития.

После создания каждое +1 базы покупается за Перья:

```text
цена повышения n−1 → n = 5 × n Перьев
цена a → b = 5 × (b(b+1) − a(a+1)) / 2
```

| Повышение | Цена |
|---|---:|
| 5→6 | 30 |
| 9→10 | 50 |
| 19→20 | 100 |
| 39→40 | 200 |
| 99→100 | 500 |
| 5→10 суммарно | 200 |
| 10→20 суммарно | 775 |
| 20→40 суммарно | 3050 |
| 10→100 суммарно | 24975 |

Цена определяется новой **базой**, не значением с экипировкой/эффектами. Одна
формула для пяти статов, без коэффициентов наставника/самообучения искусств.
Искры для этого не используются; расход не начисляет E, R или отдельный D.
Все пять можно со временем поднять до доступного предела: скрытого общего
бюджета или обязательного класса нет. Обычный интерфейс вложений доступен между
сценами боя в посмертии; покупка не является бесплатным усилением посреди боя.
Общая добровольная перераздача не вводится этим срезом; ошибочная транзакция
восстанавливается существующим rollback, а не новым игровым возвратом валюты.

## 2. Итоговый кандидат D

Сохраняются точные определения [раздела2 общей модели](combat-system-proposal.md):

```text
T_E = [0, 8, 18, 32, 46, 60]
T_R = [0, 20, 45, 75, 110, 160, 220, 300, 420, 560]

T[i] ≤ x < T[i+1]: Q_T(x) = i + (x−T[i]) / (T[i+1]−T[i])
x ≥ T[n]:         Q_T(x) = n + (x−T[n]) / (T[n]−T[n−1])

D = floor(10 × (Q_E(E) + Q_R(R)))
M = min(20 + 0.5×D, X) + floor(0.8×D)
```

Каждый полный ранговый интервал даёт10 D; внутри него D тоже повышается.
Это нормированное продвижение, а не конечный индекс названия ранга. После R560
сохраняется последний шаг140; каждые14 R дают ещё1 D без верхнего предела.
Сумма Q точная, floor один. D не выдаётся наградой и не расходуется.

| E / R | D |
|---|---:|
| 0 / 0 | 0 |
| 8 / 0 | 10 |
| 18 / 0 | 20 |
| 32 / 0 | 30 |
| 46 / 0 | 40 |
| 60 / 0 | 50 |
| 60 / 20 | 60 |
| 60 / 560 | 140 |
| 60 / 840 | 160 |
| 63 / 0 | 52 |
| 63 / 560 | 142 |

E развивается до первого полного принятого результата E≥60. Весь crossing gain
сохраняется, затем E закрыт. Например E59+4→63, D52. До законного вознесения R0;
вознесение открывает рост R и ничего повторно не добавляет к D. Возвращение в
Хаос/смертная жизнь сохраняют E/R и не открывают E заново. Пример E80/R27→D77
остаётся верным для законно заданного профиля; новая культивация не обязана
создавать именно такой профиль. Большое уже принятое значение не обрезается.

## 3. Культивация по выбранному объёму

Общая команда вкладывает Перья в **текущий доступный этап**. Нельзя выбирать
закрытое Просветление ради более выгодного обмена. Перед подтверждением игрок
видит количество единиц, итоговый E/R/D, открываемый предел статов и полную цену.
Доля кошелька, обязательный минимум20 и старое4 E/Перо удаляются.

**До завершения Просветления:** +1 E стоит `100 +25×floor(Q_E(E))` Перьев.
Цена берётся из состояния ДО приобретаемой единицы:

| Текущее E | Цена +1 E |
|---|---:|
| 0…7 | 100 |
| 8…17 | 125 |
| 18…31 | 150 |
| 32…45 | 175 |
| 46…59 | 200 |

Полностью купить E0→60 стоит9400 Перьев. Это существенная замена старого
20→80, предложенная сознательно. E7→9 стоит100+125=225. При E59 покупается
ровно последняя единица за200; неподходящая61-я не включается в расчёт и не
оплачивается. Органическая награда, заранее определённая как+4, при E59 остаётся
целой: различие следует из правил источника ДО начисления, не из обрезания D.

**После законного вознесения:** предлагается новый доступный игроку путь +1 R
за `140 +10×floor(Q_R(R))` Перьев. Это НЕ нынешний дешёвый автоплатёж NPC.
В первой полосе R0…19 цена140, следующей R20…44 цена150, далее160/170/…;
R420…559 —220, R560…699 —230, R700…839 —240 и так далее без предела индекса.
Используется продолжающийся Q, не ограниченный названием боевой/гражданский ранг.
R0→20 стоит2800, R0→560 —109700 Перьев. Искры этим обменом не расходуются.
Начальные140 выбраны так, чтобы первый интервал R стоил те же2800 за10 D,
что последний интервал E46→60. Вариант50 давал бы скачок выгодности в2.8 раза
при вознесении; он рассмотрен и не выбран. Дальнейшее равновесие со статами,
проектами и искусствами всё ещё требует баланса, это не доказательство темпа.

Этот новый путь нужен, потому что аудит существующих наград не установил
гарантированного непрерывно доступного роста R. Он не доказывает, что проекты
конечны навсегда: их циклы ещё требуют решения. Подходящие награды R сохраняются:
проект+10 за первый архетип в своей области учёта, discovery+20 по своему receipt.
Повторный вход в Обитель не возрождает уже полученную награду. Точный законный
цикл обновления проектов надо согласовать отдельно; культивация от него независима.
На стадии E завершено/R ещё закрыто культивация недоступна, плата не взимается.

Пакет сначала целиком моделируется с пересчётом каждой предельной цены и остановкой
перед недоступной единицей; затем подтверждается **одним атомарным результатом**.
Это не серия частичных публикаций. Недостаток средств блокирует предложенный
пакет: интерфейс может отдельно предложить доступный меньший объём с новой ценой.
Изменение профиля/фазы/кошелька между просмотром и принятием требует перерасчёта
и нового подтверждения, а не скрытой замены заказа или списания за недоступный рост.

## 4. Просветление за жизнь: отделить развитие от дохода

**Принято автором после пояснения:** денежная награда и автоматический прирост
Просветления — разные результаты жизни. Например, 300 Перьев не означают ещё
300 Просветления; отдельная награда E зависит от достижений. Перья сохраняются
и могут быть сознательно вложены в дополнительное развитие через культивацию.
Утверждён принцип разделения; прежний пример +2 E и таблица 0/1/2/4 не стали
согласованным численным балансом. Расчёт темпа ниже показал их чрезмерную
медленность; текущий кандидат заменяет их на 0/4/10/15. Это новое предложение,
не автоматически утверждённое предыдущим ответом. Остальные числа также
не утверждаются согласием с принципом разделения.

При предложенных порогах сохранение `FinalFeathers → E` давало бы огромный
первый crossing gain. Разделение выбрано как способ согласовать масштабы, а не
как единственная математически возможная схема: можно было менять коэффициент
или пороги. При реализации убрать эту связь; замену старой тысячной таблицы E
и синхронизацию потребителей завершить после согласования общего масштаба.
Формулу валютной награды в этом срезе заново не балансируем. Её множитель от
ранга обязан явно ссылаться на согласованный ранг E, а не старый уровень по1000.

Рабочая таблица отдельной **итоговой** награды E за жизнь, пока E открыт:

| E | Основание, подтверждённое принятыми событиями жизни |
|---|---|
| 0 | Нет завершённого содержательного достижения; один факт рождения/смерти не награждается |
| 4 | Завершена отдельная содержательная цель, но значимая жизненная линия осталась незавершённой |
| 10 | Полноценная содержательная жизнь: завершена значимая линия, преодолён конфликт/испытание с длительными последствиями для героя или окружающих |
| 15 | Исключительное достижение с устойчивыми последствиями масштаба мира или множества душ |

Берётся одна наивысшая подходящая категория, не сумма наград за каждый квест.
GM обосновывает категорию конкретными принятыми событиями; новый текст оценки
сам по себе не создаёт событие. Размер валютной выплаты/число повторённых действий/
одна смерть не доказательство категории. Повторная выдача по той же жизни запрещена.
Это новая предложенная калибровка, не обнаруженный код и не доказанное число жизней
до вознесения. Более подробные критерии масштаба требуют примеров на реальных
жизненных сценариях перед реализацией, иначе оценки GM могут расходиться.
Количество смертей, прожитых лет, уровень или богатство сами по себе не дают10 E;
это ориентир содержательного результата, не автоматическая плата за завершение.
E0 не отменяет нынешнюю гарантию минимум10 Перьев и новой реликвии за завершённую
жизнь (Block31:674–678). Другие явно определённые источники E не ограничиваются
этой таблицей итоговой оценки; общего нового потолка D или количества жизней нет.

Благоволение усиливает допустимую валютную награду на принятые0.5% за единицу,
но прямо не умножает E/R. При закрытом E оценка заранее обещает только остальные
подходящие награды; пропущенного/сгоревшего E в принятом receipt нет. Автоматическая
выдача R за жизнь не вводится: остаются собственные источники R и культивация.
Вложить полученные Перья в R после жизни можно по общим ценам.

## 5. Экономические следствия и границы доказательств

На200 Перьев можно купить стат5→10 или две ранние единицы E. Это выбор между
специализацией и общим развитием. E/R не заменяют характеристики и наоборот.
При росте Благоволения5→10 за200 прирост валютной награды составляет2.5%; для
возврата только этих Перьев требуется8000 базовых допустимых Перьев наград.
Отдельный пункт до n стоит5n и окупает себя на1000n базовых Перьев при прочих
равных. Искры и прочие роли Благоволения в эту простую оценку не включены.

Существующая формула жизни допускает очень разные доходы, вплоть до100000.
Поэтому нельзя объявлять9400 подходящей длительностью пути или обещать баланс.
Ниже рассмотрены условные сценарии разных доходов; до реализации нужны данные
игры и сравнение с затратами на искусства/реликвии. Богатая душа вправе купить большой прогресс
сразу по полной опубликованной цене; искусственный временной потолок не добавлен.

### 5.1. Рекомендуемый темп первого вознесения

**Цель дизайна:5–6 полноценных содержательных жизней при обычном распределении
вложений;4–5 при приоритетной культивации и достаточном доходе; около3 при серии
исключительных богатых жизней с сильным приоритетом развития.** Это предложение
темпа, не уже наблюдаемая статистика. Без культивации шесть наград по10 E дают60.
Слабые/короткие результаты по4 E требуют больше жизней. Низкий доход может
не сократить даже целое число жизней, хотя культивация раньше открывает ранги/D.

Цель позволяет освоить несколько воплощений и пользоваться развитием между ними,
не требуя десятков полноценных прохождений до открытия Обители. В часах это пока
не оценено: правила допускают неизвестную длительность жизни, типичный финальный
уровень/число квестов не установлены. Длинные кампании могут потребовать более
быстрого доступа; целевой диапазон нужно проверить по реальному игровому опыту.

Предыдущие2 E за содержательный результат требовали30 жизней без культивации.
В сценарии B ниже даже направление60% награды в культивацию давало14 жизней.
Это основание пересмотреть предложенную награду, а не объявлять старые числа
неизменным требованием и заставлять игрока тратить весь доход на E.

Расчётные профили дохода опираются на формулу Block31, но **не считаются
известными типичными жизнями**. L — финальный уровень, M/S — завершённые
смертные/душевные задания, K — принятый GM-коэффициент:

| Профиль | L / M / S | K | B=(10L+15M+30S)×K до ранга/Favor |
|---|---|---:|---:|
| A, малый доход | 10 / 5 / 1 | 1.0 | 205 |
| B, умеренный доход | 20 / 10 / 2 | 1.3 | 533 |
| C, высокий доход | 30 / 20 / 4 | 1.6 | 1152 |

Во всех строках сравнения ниже результат жизни оценивается в10 E; эта оценка
**не выводится** из L/M/S/денег. Однотипность дохода между жизнями — допущение
модели, а не гарантия мира или следствие покупки статов. Исходные E/кошелёк0,
Благоволение постоянно7, других доходов/источников E нет. Ранговый множитель
дохода1+0.1r использует предложенные пороги E и ранг ДО оценки текущей жизни.
Сначала floor(B×(1+0.1r)), затем согласованный бонус Favor3.5% с переносом
дробного остатка между наградами. Старая дополнительная ретронаграда при новом
ранге не включена: её судьбу/расчёт ещё надо согласовать с новой оценкой.
Это не полная симуляция нынешнего GM и не молчаливое удаление ретронаграды.

Из каждой фактической валютной награды выделяется floor(p×награда) в бюджет
культивации, остаток бюджета переносится. Сначала выдаётся отдельная награда E
за жизнь, затем, если E открыт, покупаются доступные +1 по новой цене текущего
ранга. Иные Перья остаются для остальных вложений. При E≥60 расчёт завершается,
новые единицы не покупаются; весь органический crossing gain сохраняется.

| Профиль, награда10 E за жизнь | Культивация0% | Культивация30% дохода | Культивация60% дохода |
|---|---:|---:|---:|
| A | 6 жизней | 6 | 6 |
| B | 6 | 6 | 5 |
| C | 6 | 5 | 4 |

Детализация B при60%: E после каждого завершённого цикла10+2=12,
12+10+2=24,24+10+3=37,37+10+2=49,49+10+1=60. Награды Перьев
551/607/661/716/772, всего3307; культивация250/300/525/400/200, всего1675.
Остаются1632 Пера для прочих целей; покупок за пределом60 нет. Таким образом
ускорение на одну жизнь не требует фактически потратить весь доход. Но эти
1675 конкурируют, например, с несколькими нынешними самостоятельными обучениями
по500; нельзя считать культивацию бесплатной или предполагать, что искусства
никак не меняют будущие результаты жизни вне модели.

Для C при60%:4 жизни,5483 Пера дохода,3250 на культивацию,2233 для иных целей.
Три жизни получаются в отдельном исключительном примере C с15 E за жизнь и
выделением90% в ранний бюджет: E22→44→60, всего4172 Пера, из них2400 потрачены
на культивацию. Большой бюджет не обязан израсходоваться, если цель уже достигнута.
Проценты — выбранная стратегия примера, не обязательная доля/налог/новый лимит UI.

Нельзя обещать минимум3 или максимум6 жизней. Уже существующая формула допускает
гораздо больший доход: при законной первой награде10 E и возможности потратить
8350 Перьев можно купить оставшееся до60 за одну жизнь. Это допустимое раннее
вознесение без искусственного счётчика. Если оно окажется обычным, исправлять
калибровку доходов/цен, не обрезать заработанные E/D.

Authority не задаёт минимальное число жизней: AfterlifeAscensionAuthority:13–57,
GameEngine.TurnLifecycle:4294–4329, validator LifecycleControlAndStateFiles:6610–6700.
Кроме готовности нужны Хаос, явный выбор Ascension и отдельный от life transition
ход; старые readiness shortcuts по имени/level уже исключены новым кандидатом.
Все числа таблиц означают достижение порога E, а сам переход требует этого шага.
Универсальная обязательная плата за новое обычное воплощение/первое вознесение
в проверенных путях не найдена; optional покупки и pending blockers сохраняются.

Приёмка этого среза — воспроизводимость условных расчётов и ясное различие между
целевым темпом, подтверждёнными правилами и неизвестной реальной статистикой.
До реализации дополнить сценариями смены дохода/других источников, критериями
оценки достижений и решением по ретронаградам. Часы игры и фактический баланс UNRUN.

## 6. Контракты реализации и приёмка после согласования

Один профиль владеет базами/E/R/фазой. Его создание, покупка и награда проходят
существующие authoritative accepted-turn/receipt пути; UI/GM/normalizer не могут
независимо начислять один результат повторно. Отказ проверяется до списания;
ошибка публикации не оставляет расход без роста. Новый цикл не сбрасывает базы,
E/R и бесплатное создание не повторяется. Не требуется поддерживать старые saves.
Гражданские пороги R0/100/220/380/580 и NPC profile tiers имеют иное назначение:
не подменять ими Q_R или право игрока на покупку. Автопрогрессия NPC не начисляет
`player_soul`; её полный баланс и рост характеристик NPC остаются отдельной работой.

При будущей реализации стабильный профиль/правила одной операции разрешения
переиспользуются через существующий Service–Repository cache: ключ включает
душу, revision профиля, редакцию правил и применимые источники; lifetime одной
операции, после мутации инвалидирование. Для дешёвой арифметики отдельный кэш не
нужен. Свежие ownership/balance/phase/publish проверки кэшем не заменяются.

Критерии проверки с дешёвыми типизированными фикстурами после утверждения:

1. Однократный старт5×5+10, все распределения в пределах10; новая жизнь не даёт
   новых бесплатных пунктов; роль воспоминания не пишет в настоящий профиль.
2. Предельные цены и суммы из таблиц; снятие реликвии не меняет цену базы;
   превышение рангового предела/нехватка средств не списывают валюту.
3. E7→9=225; E0→60=9400; покупка сверх60 не оплачивается; органическое59+4=63
   сохраняется целиком. D до/после вознесения одинаков, E не открывается вновь.
4. Точная Q-сумма: E80/R27 даёт77, а не76; каждый порог непрерывен до floor;
   R560/700/840 продолжают развитие/цены без clamp индекса или D.
5. Награда жизни не равна FinalFeathers; категории требуют evidence; Favor
   усиливает валюту, не XP; duplicate receipt, retries и reject не дублируют рост.
6. Пакетный quote равен сумме последовательно рассчитанных цен, но публикация
   одна; изменённая фаза/revision требует нового quote. Новая цена не применяется
   задним числом к уже принятому receipt, overflow не теряется.
7. Console/browser/GM показывают одинаковые стоимость, результат и причины
   недоступности. Изменённые источники/нормализация/шаблоны/примеры синхронизированы.

Сейчас проверены только арифметика примеров и связность документов. Runtime,
игровой баланс, миграция активных templates и перечисленные production-контракты
не реализованы и не проверены. До исполнения нужны рассмотрение точной spec,
пересборка [plan](plan.md)/[tasks](tasks.md) и consistency. T001 остаётся закрытым gate.
