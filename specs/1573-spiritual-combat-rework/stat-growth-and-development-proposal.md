## Выбор подхода и существующие основания

Рекомендуется оставить знакомые Перья средством вложения, разделить покупку
базового стата и развитие E/R, а D вычислять из накопленного развития. Отдельные
очки опыта/валюту характеристик не вводить. Сохранение старой культивации с новой
ценой статов не подходит: сейчас минимум20 Перьев даёт80 E при пороге вознесения60.
Прежнее возражение против автостатов за ранг отозвано уточнением5.5: сознательным
вложением может быть культивация, а её ранговый результат — автоматическое усиление.
Старт, цена статов и Q/D теперь выбраны автором; остальные рекомендации ниже
не становятся принятыми автоматически.

## 1. Создание души и покупка характеристик

Мощь, Чуткость, Воля, Цельность и Благоволение начинают с **5**. При создании
игрок распределяет **10 бесплатных пунктов**, не более10 в одной характеристике.
Исходная сумма после распределения35. Например10/8/7/5/5; равномерный вариант7/7/7/7/7.
Нельзя опустить исходные5, продать бесплатные пункты или превратить их в валюту.
Это однократный шаг создания души, не каждой смертной жизни/вознесения.

Старт E0/R0/D0, кошелёк0 плюс фактически заработанная tutorial-награда.
Расколотая маска применяет только свои согласованные бонусы при экипировке;
она не увеличивает базовую раздачу и не передаёт силу исторической роли.
Сильные NPC и исторический Маска получают собственные явные профили, а не
обязательный старт нового игрока. К ним применяется та же математика развития.

После создания каждое +1 базы покупается за Перья:

```text
цена повышения n−1 → n = 5 × n Перьев
цена a → b = 5 × (b(b+1) − a(a+1)) / 2
```

| Повышение | Цена |
|---|---:|
| 5→6 | 30 |
| 9→10 | 50 |
| 19→20 | 100 |
| 39→40 | 200 |
| 99→100 | 500 |
| 5→10 суммарно | 200 |
| 10→20 суммарно | 775 |
| 20→40 суммарно | 3050 |
| 10→100 суммарно | 24975 |

Цена определяется новой **базой**, не значением с экипировкой/эффектами. Одна
формула для пяти статов, без коэффициентов наставника/самообучения искусств.
Искры для этого не используются; расход не начисляет E, R или отдельный D.
Все пять можно со временем поднять до доступного предела: скрытого общего
бюджета или обязательного класса нет. Обычный интерфейс вложений доступен между
сценами боя в посмертии; покупка не является бесплатным усилением посреди боя.
Общая добровольная перераздача не вводится этим срезом; ошибочная транзакция
восстанавливается существующим rollback, а не новым игровым возвратом валюты.

## 2. Принятый расчёт D

Сохраняются точные определения [раздела2 общей модели](combat-system-proposal.md):

```text
T_E = [0, 8, 18, 32, 46, 60]
T_R = [0, 20, 45, 75, 110, 160, 220, 300, 420, 560]

T[i] ≤ x < T[i+1]: Q_T(x) = i + (x−T[i]) / (T[i+1]−T[i])
x ≥ T[n]:         Q_T(x) = n + (x−T[n]) / (T[n]−T[n−1])

D = floor(10 × (Q_E(E) + Q_R(R)))
M = min(20 + 0.5×D, X) + floor(0.8×D)
```

Каждый полный ранговый интервал даёт10 D; внутри него D тоже повышается.
Это нормированное продвижение, а не конечный индекс названия ранга. После R560
сохраняется последний шаг140; каждые14 R дают ещё1 D без верхнего предела.
Сумма Q точная, floor один. D не выдаётся наградой и не расходуется.

| E / R | D |
|---|---:|
| 0 / 0 | 0 |
| 8 / 0 | 10 |
| 18 / 0 | 20 |
| 32 / 0 | 30 |
| 46 / 0 | 40 |
| 60 / 0 | 50 |
| 60 / 20 | 60 |
| 60 / 560 | 140 |
| 60 / 840 | 160 |
| 63 / 0 | 52 |
| 63 / 560 | 142 |

E развивается до первого полного принятого результата E≥60. Весь crossing gain
сохраняется, затем E закрыт. Например E59+4→63, D52. До законного вознесения R0;
вознесение открывает рост R и ничего повторно не добавляет к D. Возвращение в
Хаос/смертная жизнь сохраняют E/R и не открывают E заново. Пример E80/R27→D77
остаётся верным для законно заданного профиля; новая культивация не обязана
создавать именно такой профиль. Большое уже принятое значение не обрезается.

## 3. Культивация по выбранному объёму

**История до уточнения5.5:** тарифы ниже проектировались для дополнительного
ускорения, поэтому больше не являются текущей рекомендацией для основного пути.
Механика явного выбора объёма и атомарного результата сохраняет смысл, но
новые цены будут определены вместе с естественными наградами и наградами прорыва.

Общая команда вкладывает Перья в **текущий доступный этап**. Нельзя выбирать
закрытое Просветление ради более выгодного обмена. Перед подтверждением игрок
видит количество единиц, итоговый E/R/D, открываемый предел статов и полную цену.
Доля кошелька, обязательный минимум20 и старое4 E/Перо удаляются.

**До завершения Просветления:** +1 E стоит `100 +25×floor(Q_E(E))` Перьев.
Цена берётся из состояния ДО приобретаемой единицы:

| Текущее E | Цена +1 E |
|---|---:|
| 0…7 | 100 |
| 8…17 | 125 |
| 18…31 | 150 |
| 32…45 | 175 |
| 46…59 | 200 |

Полностью купить E0→60 стоит9400 Перьев. Это существенная замена старого
20→80, предложенная сознательно. E7→9 стоит100+125=225. При E59 покупается
ровно последняя единица за200; неподходящая61-я не включается в расчёт и не
оплачивается. Органическая награда, заранее определённая как+4, при E59 остаётся
целой: различие следует из правил источника ДО начисления, не из обрезания D.

**После законного вознесения:** принят независимый путь культивации R за Перья.
В5.4 сохранён прежний кандидат2800+800r за полный интервал Q, частичные объёмы
оплачиваются по разности накопительного ценового индекса. Цена не принята и
больше не рекомендована после уточнения5.5 об основной роли культивации.

**Прежний тариф для сравнения:** +1 R за `140 +10×floor(Q_R(R))` Перьев.
Это НЕ нынешний дешёвый автоплатёж NPC и больше не текущая рекомендация цены.
В первой полосе R0…19 цена140, следующей R20…44 цена150, далее160/170/…;
R420…559 —220, R560…699 —230, R700…839 —240 и так далее без предела индекса.
Используется продолжающийся Q, не ограниченный названием боевой/гражданский ранг.
R0→20 стоит2800, R0→560 —109700 Перьев. Искры этим обменом не расходуются.
Начальные140 выбраны так, чтобы первый интервал R стоил те же2800 за10 D,
что последний интервал E46→60. Вариант50 давал бы скачок выгодности в2.8 раза
при вознесении; он рассмотрен и не выбран. Дальнейшее равновесие со статами,
проектами и искусствами всё ещё требует баланса, это не доказательство темпа.
**Статус цены R:** рекомендации5.4 и более ранние тарифы отозваны по роли5.5; правила проектных
наград и подарка Искр приняты в5.3, но новый тариф ещё не согласован. Текущие проекты дешевле и не требуют подтверждённого
долгого строительства; точный разрыв разобран в5.2. Он не исправляется вслепую
переносом стоимости ограниченной награды на неограниченную культивацию.

Этот новый путь нужен, потому что аудит существующих наград не установил
гарантированного непрерывно доступного роста R. Он не доказывает, что проекты
конечны навсегда: новая настоящая фракция имеет собственные первые награды. R сохраняется:
проект+10 за первый архетип в своей области учёта, discovery+20 по своему receipt.
Повторный вход в Обитель не возрождает уже полученную награду. Постоянный учёт
по фракции/архетипу принят в5.3; культивация от этих первых наград независима.
На стадии E завершено/R ещё закрыто культивация недоступна, плата не взимается.

Пакет сначала целиком моделируется с пересчётом каждой предельной цены и остановкой
перед недоступной единицей; затем подтверждается **одним атомарным результатом**.
Это не серия частичных публикаций. Недостаток средств блокирует предложенный
пакет: интерфейс может отдельно предложить доступный меньший объём с новой ценой.
Изменение профиля/фазы/кошелька между просмотром и принятием требует перерасчёта
и нового подтверждения, а не скрытой замены заказа или списания за недоступный рост.

## 4. Просветление за жизнь: отделить развитие от дохода

**Принято автором после пояснения:** денежная награда и автоматический прирост
Просветления — разные результаты жизни. Например, 300 Перьев не означают ещё
300 Просветления; отдельная награда E зависит от достижений. Перья сохраняются
и могут быть сознательно вложены в дополнительное развитие через культивацию.
Утверждён принцип разделения; прежний пример +2 E и таблица 0/1/2/4 не стали
согласованным численным балансом. Расчёт темпа ниже показал их чрезмерную
медленность; кандидат заменил их на 0/4/10/15. Затем автор принял основной
ориентир 5–6 жизней и поручил уточнить критерии именно этой шкалы. После их
предъявления автор ответил «отлично»: игровые критерии разделов4.1–4.3 приняты.
После пересчёта5.7 автор принял новые суммы0/1/2/3; ниже текущие критерии и
примеры синхронизированы с ними без изменения смысловой оценки достижений.
Это не утверждает автоматически остальные цены, техническую схему и полную реализацию.

При предложенных порогах сохранение `FinalFeathers → E` давало бы огромный
первый crossing gain. Разделение выбрано как способ согласовать масштабы, а не
как единственная математически возможная схема: можно было менять коэффициент
или пороги. При реализации убрать эту связь; замену старой тысячной таблицы E
и синхронизацию потребителей завершить после согласования общего масштаба.
Формулу валютной награды в этом срезе заново не балансируем. Её множитель от
ранга обязан явно ссылаться на согласованный ранг E, а не старый уровень по1000.

Рабочая таблица отдельной **итоговой** награды E за жизнь, пока E открыт:

| E | Основание, подтверждённое принятыми событиями жизни |
|---|---|
| 0 | Нет завершённого содержательного достижения; один факт рождения/смерти не награждается |
| 1 | Подтверждено отдельное содержательное достижение, но нет завершённой значимой жизненной линии |
| 2 | Полноценная содержательная жизнь: завершена значимая линия, преодолён конфликт/испытание с длительными последствиями для героя или окружающих |
| 3 | Исключительное достижение с устойчивыми последствиями масштаба мира или множества душ |

Берётся одна наивысшая подходящая категория, не сумма наград за каждый квест.
GM обосновывает категорию конкретными принятыми событиями; новый текст оценки
сам по себе не создаёт событие. Размер валютной выплаты/число повторённых действий/
одна смерть не доказательство категории. Повторная выдача по той же жизни запрещена.
Это новая калибровка, не обнаруженный код и не доказанное число жизней до вознесения.
Раздел4.1 содержит принятые критерии/пограничные примеры; проверка на игровых
сценариях перед реализацией ещё требуется.
Количество смертей, прожитых лет, уровень или богатство сами по себе не дают2 E;
это ориентир содержательного результата, не автоматическая плата за завершение.
E0 не отменяет нынешнюю гарантию минимум10 Перьев и новой реликвии за завершённую
жизнь (Block31:674–678). Другие явно определённые источники E не ограничиваются
этой таблицей итоговой оценки; общего нового потолка D или количества жизней нет.

Благоволение усиливает допустимую валютную награду на принятые0.5% за единицу,
но прямо не умножает E/R. При закрытом E оценка заранее обещает только остальные
подходящие награды; пропущенного/сгоревшего E в принятом receipt нет. Автоматическая
выдача R за жизнь не вводится: остаются собственные источники R и культивация.
Вложить полученные Перья в R после жизни можно по общим ценам.

### 4.1. Как GM выбирает итоговую награду: принятый игровой регламент

Оценивается конкретная завершённая жизнь на её отдельном Life Evaluation ходе.
Результат — одна наивысшая подтверждённая категория, не сумма за каждый квест.
Не использовать скрытый счётчик добродетели, числа заданий или количества текста.
Значимость и последствия оценивает GM; клиент не может доказать их истинность
одним парсингом свободного текста. Нужны объяснение и проверяемые источники.

**Общее основание результата:** что было поставлено на карту, что сделал/выбрал
герой, какое препятствие преодолел или какое существенное решение принял,
что фактически изменилось. События уже должны принадлежать принятой истории
именно этой жизни. Не достаточно намерения, обещанной награды, одного статуса
«completed», величественного названия или новой фразы в посмертном отчёте.
Квестовый статус — полезный источник, но смысл/масштаб берутся из его событий.
Отдельный art/quest/chain ID не обязателен для свободно возникшей сюжетной линии.

**0 — нет подтверждённого содержательного результата.** Ни одно событие не
соответствует даже отдельному достижению ниже. Например, герой лишь появился
в мире, накопил обычные ресурсы/убийства без сюжетного результата и погиб.
Короткая жизнь или смерть сами по себе не означают0: решительный поступок мог
успеть изменить чью-то судьбу. Напротив, множество часов/уровней сами по себе
не гарантируют1. Неполная/нечитаемая история — причина восстановить контекст,
а не подменить неизвестный результат нулевой наградой.

**1 — отдельное значимое достижение.** Есть конкретная решённая задача или
завершённый этап и наблюдаемый результат для героя/других. Было препятствие,
неочевидное решение, риск или содержательный выбор. Это больше, чем рутинный
повтор ради ресурсов, но полная жизненная линия ниже ещё не подтверждается.
Примеры: освободил пленника, раскрыл личность заговорщика, вывел караван из
опасности, нашёл проверенное средство против болезни, не успев завершить борьбу
с эпидемией. Десять таких отдельных поручений не складываются автоматически в2;
они могут вместе образовать линию только при реальной причинной связи и развязке.

**2 — завершённая значимая жизненная линия.** GM должен подтвердить ВСЕ условия:

1. По событиям видны исходная проблема/стремление героя и значимые для него либо
   других ставки. Это не обязательно главный квест мира или заранее заведённая цепочка.
2. Линия получила развитие через содержательное препятствие/испытание/решение;
   герой сыграл существенную причинную роль, а не только присутствовал при чужом подвиге.
3. Наступила состоявшаяся развязка: центральный вопрос этой линии получил ответ.
   Успех, трагическое поражение, осознанный отказ или иной исход допустимы;
   обрыв попытки со смертью без развязки сам по себе не закрывает линию.
4. Есть подтверждённое итоговое изменение: положение людей, отношения, известная
   правда, судьба сообщества либо воплощённый в поступках выбор самого героя.
   Оно выходит за пределы мгновенной выдачи добычи/опыта. Обещание будущего эффекта
   или декларация «я изменился» без событий не заменяет результат.

Примеры: вернул семью и разрешил породивший разлуку конфликт; нашёл погибшего
близкого, раскрыл правду и завершил линию мести собственным решением; создал
действующее убежище и обеспечил его дальнейшую жизнь; разрешил кризис города;
потерпел поражение в войне, но завершил эвакуацию и создал основу жизни беженцев.
Личная история без спасения города тоже может давать2. Не требуется несколько
отдельных квестов, заданное число ходов или минимальная длительность.

Разница1/2 — между преодолённой отдельной помехой/достигнутым этапом и ответом
на центральный значимый вопрос самостоятельной линии. Глобальная история мира
при этом может продолжаться. GM должен давать обычным жизненным историям
самостоятельные развязки, а не удерживать2 до финала всей мировой кампании.
Если локальная линия действительно соответствует всем четырём условиям, её
малый географический масштаб не основание снизить награду до1.

Если главный замысел не удался, уже завершённая самостоятельная линия всё равно
даёт2. Если замысел оборвался и есть лишь промежуточный результат —1. Гибель
героя может быть осмысленной развязкой, но факт смерти не создаёт её автоматически.
GM не повышает обычное поручение до «смысла всей жизни» задним числом: значимость
должна следовать из целей, конфликтов, решений и последствий, возникших в игре.

**3 — исключительный перелом.** Выполнены условия2, и дополнительно:

1. Результат меняет фундаментальное условие существования мира, судьбу целой
   цивилизации/общности душ или механизм, определявший их существование. Это
   качественно шире личной/обычной локальной линии, а не просто больше побеждённых.
2. Изменение уже состоялось и имеет устойчивое основание: снята действовавшая
   мировая печать, устранён источник катастрофы, принят и начал действовать новый
   порядок, разрушен механизм порабощения душ. Ждать десятилетия не нужно, но
   голое обещание будущего величия не подходит.
3. Существенный вклад героя в этот перелом подтверждён. Совместный подвиг допустим;
   не требуется выполнить всё одному. Имя в списке участников или присутствие
   рядом не заменяет вклад.

Примеры: остановил подтверждённую гибель мира и устранил её источник; освободил
общность душ от действовавшего цикла порабощения; изменил мировой порядок так,
что его новая действующая основа подтверждена событиями. Победить именованного
«бога» или «владыку мира» недостаточно без соответствующего реального результата.
Количество жителей не является фиксированной квотой; масштаб определяется
установленным устройством конкретного мира, не красивым названием поселения.

### 4.2. Обязательные границы оценки и спорные случаи

- **Мораль не является множителем E.** Добрый/злой/нейтральный исход сам по себе
  не меняет категорию. Реформатор, завоеватель и сложный личный герой оцениваются
  по тем же условиям вклада, развязки и последствий. Это не перенос moral/GM
  коэффициента денежной награды. Много жертв само по себе не даёт3, как и много
  добрых мелочей не заменяет завершённую линию. Намеренный вымышленный тиранический
  сюжет не исключается из достижений только потому, что он злой.
- **Неудача не обнуляет прошлое.** Поздняя смерть/поражение не стирают состоявшийся
  результат другой линии. Но если заявленный большой эффект был опровергнут
  ещё до конца той же линии, нельзя ссылаться на него как на продолжающийся.
  Выбирается наивысший реально подтверждённый результат полной истории.
- **Роль героя важнее формы действия.** Переговоры, исследование, создание чего-то,
  забота о семье, организаторская работа и бой равноправны. Не требовать последний
  удар, мирный финал, героическую смерть или литературно красивую рефлексию.
- **Повторы не складываются в награду.** Одна жизнь получает одну категорию.
  Повторить одинаковый тип истории в следующем мире разрешено: новые реальные
  поступки другой жизни оцениваются заново. Старое событие, пересказ или retry
  той же оценки не становятся новым достижением/начислением.
- **Результат по силам мира.** 2 не требует глобального спасения; 3 требует
  исключительного масштаба относительно установленного мира. Высокий уровень,
  сумма Перьев, проценты impact, количество квестов и язык описания не подменяют
  проверку условий. GM не подгоняет категорию под желаемое вознесение на5-й жизни.
- **Отсутствие доказательств и повреждение контекста различаются.** Если контекст
  доступен и показывает только отдельную цель —1, даже при заявлении игрока о3.
  Если нужная часть истории недоступна/противоречива, восстановить или уточнить
  её существующим repair-путём до выдачи; не придумывать факты и не ставить0 за
  техническую потерю. Пустой список формальных квестов не доказывает отсутствие
  свободных значимых действий.

### 4.3. Обоснование для игрока и будущий договор данных

GM сначала сопоставляет условия3, затем2, затем1; иначе0. Для каждого
выбранного основания записывает: линия/цель, исходная ситуация, действие и вклад
героя, развязка, фактическое последствие, ссылки на исходные принятые события.
Отдельно коротко отмечает, какое условие ближайшей большей категории не выполнено.
Это пояснение выбора, не новая шкала с суммой скрытых баллов.

Игроку достаточно понятного текста без внутренних ID, например:

> Просветление: +2. Ты нашёл семью и положил конец конфликту, который её разлучил.
> Эта история завершилась благодаря твоим решениям, а семья смогла начать новую
> жизнь. Это завершённая личная линия; перелома масштаба мира в этой жизни не было.

Во время игры GM может обозначать значимые цели и уже достигнутые результаты,
но не обещает окончательную категорию до завершения событий. Обязательное новое
меню/команда или заранее зарегистрированный квест этим срезом не вводятся.

**Что реально имеется сейчас:** BuildLifeSummary передаёт имя/расу/класс,
локацию, общий счётчик ходов и summary, а не готовый проверенный пакет достижений
(GameEngine.IncarnationAndAfterlife:45–64, TurnLifecycle:2825–2838). Block31:134–154,
603–607 требует GM notableAchievements/impact/обоснование. Quest histories и
stories/*.jsonl могут служить первичными источниками; вновь записанная оценкой
строка completedIncarnations не является независимым доказательством самой себя.

**Что нужно добавить при будущей реализации:** привязанный к завершённой жизни
пакет оснований категории и ссылок на предшествующие источники, проверку принадлежности
этой жизни/принятому состоянию, выдачу E и запись результата в одном authoritative
accepted workflow. Конкретная схема полей ещё проектируется; готового E-receipt
или семантического verifier в нынешнем LifeEvaluationRewardDelta нет.
Клиент проверяет допустимую категорию, идентичность/источники/арифметику/повтор,
а GM аргументирует смысл, завершённость и масштаб. Не выдавать текст GM за
автоматически доказанную runtime истинность, не вводить нового publisher-обхода.

Стабильные данные истории/целей для оценки собрать один раз на её операцию и
переиспользовать через существующий service/repository/cache. Owner — операция
оценки конкретной души/жизни; ключ включает identity, revisions источников и
редакцию правил. При repair/изменении источников инвалидировать зависимые данные.
Не перечитывать всю историю для каждой ступени0/1/2/3. Fresh ownership/phase/
snapshot/publish проверки остаются, кэш не разрешает выдачу повторно.

Результат сохраняется один раз для данной жизни. Retry после принятия возвращает
тот же результат; отклонённая попытка ничего не начисляет. Не дробить2 на
несколько промежуточных наград. При E59 и законной награде2 сохранить E61 целиком,
затем закрыть фазу. При уже закрытом E это «этап завершён», а не оценка жизни0;
не выдавать скрыто R вместо E. Численные/сюжетные основания и фаза — разные вещи.

Критерии приёмки документа: каждая строка пограничной таблицы объяснима правилами;
провал/личная линия/свободные действия не лишены награды автоматически; мораль,
богатство и количество квестов не заменяют основание; missing context отделён
от0; отсутствующие runtime возможности явно названы новыми. При реализации
нужны cheap typed fixtures категорий/источников/дедупликации и GM-примеры, без
рефлексии и генерации полного мира. Сейчас это только проверяемая спецификация.

### 5.1. Исторический расчёт темпа до выбора автонаград

Актуальный пересчёт с растущим Благоволением —5.7. Таблицы ниже сохраняют
прежние10 E, дорогую культивацию и постоянный Favor7 как историю сравнения.

**Автор принял основной ориентир5–6 полноценных содержательных жизней.**
Расчётные варианты:4–5 при приоритетной культивации и достаточном доходе; около3
при серии исключительных богатых жизней с сильным приоритетом развития. Это
балансная цель и примеры, не наблюдаемая статистика. Без культивации шесть наград
по10 E дают60. Принятие ориентира не утверждает все цены и схемы этого приложения.
Слабые/короткие результаты по4 E требуют больше жизней. Низкий доход может
не сократить даже целое число жизней, хотя культивация раньше открывает ранги/D.

Цель позволяет освоить несколько воплощений и пользоваться развитием между ними,
не требуя десятков полноценных прохождений до открытия Обители. В часах это пока
не оценено: правила допускают неизвестную длительность жизни, типичный финальный
уровень/число квестов не установлены. Длинные кампании могут потребовать более
быстрого доступа; целевой диапазон нужно проверить по реальному игровому опыту.

Предыдущие2 E за содержательный результат требовали30 жизней без культивации.
В сценарии B ниже даже направление60% награды в культивацию давало14 жизней.

неизменным требованием и заставлять игрока тратить весь доход на E.

Расчётные профили дохода опираются на формулу Block31, но **не считаются
известными типичными жизнями**. L — финальный уровень, M/S — завершённые
смертные/душевные задания, K — принятый GM-коэффициент:

| Профиль | L / M / S | K | B=(10L+15M+30S)×K до ранга/Favor |
|---|---|---:|---:|
| A, малый доход | 10 / 5 / 1 | 1.0 | 205 |
| B, умеренный доход | 20 / 10 / 2 | 1.3 | 533 |
| C, высокий доход | 30 / 20 / 4 | 1.6 | 1152 |

Во всех строках сравнения ниже результат жизни оценивается в10 E; эта оценка
**не выводится** из L/M/S/денег. Однотипность дохода между жизнями — допущение
модели, а не гарантия мира или следствие покупки статов. Исходные E/кошелёк0,
Благоволение постоянно7, других доходов/источников E нет. Ранговый множитель
дохода1+0.1r использует предложенные пороги E и ранг ДО оценки текущей жизни.
Сначала floor(B×(1+0.1r)), затем согласованный бонус Favor3.5% с переносом
дробного остатка между наградами. Старая дополнительная ретронаграда при новом
ранге не включена: её судьбу/расчёт ещё надо согласовать с новой оценкой.
Это не полная симуляция нынешнего GM и не молчаливое удаление ретронаграды.

Из каждой фактической валютной награды выделяется floor(p×награда) в бюджет
культивации, остаток бюджета переносится. Сначала выдаётся отдельная награда E
за жизнь, затем, если E открыт, покупаются доступные +1 по новой цене текущего
ранга. Иные Перья остаются для остальных вложений. При E≥60 расчёт завершается,
новые единицы не покупаются; весь органический crossing gain сохраняется.

| Профиль, награда10 E за жизнь | Культивация0% | Культивация30% дохода | Культивация60% дохода |
|---|---:|---:|---:|
| A | 6 жизней | 6 | 6 |
| B | 6 | 6 | 5 |
| C | 6 | 5 | 4 |

Детализация B при60%: E после каждого завершённого цикла10+2=12,
12+10+2=24,24+10+3=37,37+10+2=49,49+10+1=60. Награды Перьев
551/607/661/716/772, всего3307; культивация250/300/525/400/200, всего1675.
Остаются1632 Пера для прочих целей; покупок за пределом60 нет. Таким образом
ускорение на одну жизнь не требует фактически потратить весь доход. Но эти
1675 конкурируют, например, с несколькими нынешними самостоятельными обучениями
по500; нельзя считать культивацию бесплатной или предполагать, что искусства
никак не меняют будущие результаты жизни вне модели.

Для C при60%:4 жизни,5483 Пера дохода,3250 на культивацию,2233 для иных целей.
Три жизни получаются в отдельном исключительном примере C с15 E за жизнь и
выделением90% в ранний бюджет: E22→44→60, всего4172 Пера, из них2400 потрачены
на культивацию. Большой бюджет не обязан израсходоваться, если цель уже достигнута.
Проценты — выбранная стратегия примера, не обязательная доля/налог/новый лимит UI.

Нельзя обещать минимум3 или максимум6 жизней. Уже существующая формула допускает
гораздо больший доход: при законной первой награде10 E и возможности потратить
8350 Перьев можно купить оставшееся до60 за одну жизнь. Это допустимое раннее
вознесение без искусственного счётчика. Если оно окажется обычным, исправлять
калибровку доходов/цен, не обрезать заработанные E/D.

Authority не задаёт минимальное число жизней: AfterlifeAscensionAuthority:13–57,
GameEngine.TurnLifecycle:4294–4329, validator LifecycleControlAndStateFiles:6610–6700.
Кроме готовности нужны Хаос, явный выбор Ascension и отдельный от life transition
ход; старые readiness shortcuts по имени/level уже исключены новым кандидатом.
Все числа таблиц означают достижение порога E, а сам переход требует этого шага.
Универсальная обязательная плата за новое обычное воплощение/первое вознесение
в проверенных путях не найдена; optional покупки и pending blockers сохраняются.

Приёмка этого среза — воспроизводимость условных расчётов и ясное различие между
целевым темпом, подтверждёнными правилами и неизвестной реальной статистикой.
До реализации дополнить сценариями смены дохода/других источников, критериями
оценки достижений и решением по ретронаградам. Часы игры и фактический баланс UNRUN.

### 5.2. Историческая численная рекомендация и сравнение вложений

Последний запрос автора — обдумать окончательный старт, цены характеристик,
культивацию и D. **Рекомендация:** сохранить старт5×5+10, стоимость базы5n,
ранговые пределы10…100, точную Q-конверсию D и E-культивацию100+25floor(QE)
как согласуемую численную основу. Новых причин менять коэффициенты mortal,
добавлять потолки или вводить другую валюту не найдено. Это предложение к
утверждению, не объявление всей экономики/боя окончательно сбалансированными.
Здесь сохранены сравнительные расчёты прежней ставки140+10floor(QR); последующее
исследование5.4 рекомендует другую цену, не меняя эти исторические числа.
HP/урон/ОД не конструируются молча в этом срезе.

**Роли вложений различаются.** База усиливает выбранное направление и применимые
собственные эффекты характеристики. D усиливает все применимые проверки через
ту же формулу, открывая дальнейшее развитие. D не повышает сами пять баз и
не увеличивает процент награды Благоволения. Роль Мощи в уроне/Цельности в HP
принята по направлению, но её численная величина ещё не выбрана: нельзя выдать
эти будущие эффекты за уже доказанную окупаемость статов.

#### После первой содержательной жизни: один доступный кошелёк, разные решения

Берём уже рассмотренный условный профиль B:10 E и551 Перо после первой жизни,
стартовые базы7/7/7/7/7. E10 означает D12, C26, B9. Экипировки/эффектов нет.
Порядок баз: Мощь/Чуткость/Воля/Цельность/Благоволение. Сравниваем только M
проверок, не урон, HP, вероятность критов, качество добычи или полный боевой билд.

| Приоритет | Покупки | Потрачено / осталось | E / D | M Чуткости / Воли |
|---|---|---:|---|---|
| Общее развитие | +4 E за500, Чуткость7→8 за40 | 540 /11 | 14 /16 | 20 /19 |
| Специализация | Чуткость7→15 за460, Мощь7→8 и Воля7→8 по40 | 540 /11 | 10 /12 | 24 /17 |
| Смешанный | Чуткость7→10 и Воля7→10 по135, +2 E за250 | 520 /31 | 12 /14 | 21 /21 |

В первом варианте остальные нетронутые базы7 дают M19; во втором Цельность7
даёт M16; в третьем нетронутые базы7 дают M18. Это примеры доступных решений,
не поиск глобального оптимума и не гарантия равной полезности любых билдов.
Благоволение во всех трёх остаётся7 и даёт те же3.5% валютной прибавки:
рост D не превращает его M в дополнительный процент Перьев/Искр.
Можно также сохранить валюту или купить искусство; таблица не заставляет
тратить весь кошелёк только на эти две оси развития.

#### Почему раннее D полезно, а поздняя специализация не теряет смысл

Если X остаётся ниже C в обоих состояниях, +10 D даёт ровно+8 к применимому M.
Цена полного рангового интервала растёт:

| Покупаемый интервал | Цена Перьев | Прирост D / M при X≤C |
|---|---:|---|
| E0→8 | 800 | +10 /+8 |
| E8→18 | 1250 | +10 /+8 |
| E46→60 | 2800 | +10 /+8 |
| R0→20 | 2800 | +10 /+8 |
| R220→300 | 16000 | +10 /+8 |
| R300→420 | 25200 | +10 /+8 |

При E60/R300 D120, C80. Покупка базы70→78 стоит2980 и даёт+8 соответствующему M.
Четыре такие покупки стоят11920; R300→420 стоит25200 и даёт+8 всем применимым M
при той же ненасыщенной границе. Это сравнение формул, не утверждение, что в
реальном бою четырьмя статами проверяют одинаково часто. Общий рост не является
доказанно лучшим вложением на всём пути; разные цены/область применения дают выбор.
При X выше C развитие D может одновременно поднять границу C, меняя сравнение.

#### Сохранённый mortal min: некоторые дорогие пункты пока не улучшают M

| Состояние E60 | D / C | Разрешённая база | Пример покупки | Цена | Немедленное изменение M |
|---|---|---:|---|---:|---:|
| R420 | 130 /85 | 90 | 85→90 | 2200 | 0 |
| R560 | 140 /90 | 100 | 90→100 | 4775 | 0 |

Это следствие исходной формулы, а не новый потолок. Покупку не запрещаем и C
не переписываем. При E60/R840 D160, C100: все100 могут участвовать в проверке.
От R560 до840 культивация по условной ставке стоит65800; отдача от высоких X
открывается постепенно, например при R574 D141 даёт C90.5.

Рекомендация игроку, ориентированному только на M: можно отложить покупку
пунктов выше C — их цена от ожидания не увеличивается. Бонусы/штрафы и будущие
отдельные формулы HP/урона могут давать иные основания для покупки, но они
должны быть определены, а не обещаны как готовое оправдание текущего баланса.
Если понадобится немедленная полезность каждого пункта всех пяти статов,
это требование проверяется при проектировании их прочих ролей.

Preview должен показывать базу до/после, применимый предел вложений, D/C и
фактическое изменение соответствующих вычисленных параметров. Не обещать+1 M
за каждый пункт. Так же +1 E не всегда сразу повышает M: при базе7 и E0…8
добавка B равна0/0/1/2/4/4/5/6/8. E0→1 за100 увеличивает D с0 до1, но M
остаётся7. Накопленный E не пропадает; floor/коэффициенты остаются исходными.
Не показывать ещё не реализованные эффекты HP/урона как рассчитанный результат.

#### Стартовые пункты и стоимость специализации

Бесплатные10 пунктов не равны одинаковому числу Перьев при всех распределениях.
10/10/5/5/5 соответствует400 Перьям покупок от пяти баз5;7/7/7/7/7 —325.
До пяти баз10 затем нужно600 против675 Перьев. Разница75 — однократное
экономическое преимущество концентрации, при реальных слабых других статах.
Это не повторяемый арбитраж: пункты не продаются, создание души не повторяется
в каждой жизни, добровольная перераздача этим срезом не вводится.
Рекомендация — сохранить простую раздачу, не добавляя отдельного денежного
бюджета создания ради выравнивания этих75. Это осознанный компромисс, не
утверждение равной денежной стоимости стартовых вариантов.

#### Почему цену культивации Сияния ещё нельзя объявить окончательной

Проверенный player complete_project — заявка сразу на завершение, затем один
принятый GM-ход с exact quote/receipt. Отдельного обязательного start/progress/N
циклов или долгого строительства в этом контракте нет. При существующей
доступной operational-фракции два разных tier1 архетипа дают20 R базово за
40 Перьев+20 Искр и два принятых завершения; возможны скидки. Культивация того
же R0→20 стоит2800 Перьев и не требует ни фракции, ни Искр. Длительностью
проекта такой разрыв не обосновывать.

Восемь архетипов не гарантируют мгновенную доступность восьми наград: default
Обитель имеет пустой factions[], а subversion требует другую существующую
фракцию. Повтор того же архетипа в той же фракции снова платный и не даёт R;
retire не очищает учёт. Ordinary reentry сохраняет счётчик, actual ascension
сейчас сбрасывает его и выдаёт100 Искр заново. Нельзя переносить этот reset
неизменным в новый постоянный жизненный цикл или приписывать текущему коду
уже реализованный однократный подарок. Новые фракции имеют собственные условия.

Источники: UI ShiningAbode.Gates:11–73,1033–1079; ShiningAbodeState.Gameplay:

**Выявленный здесь вопрос теперь решён игровыми правилами5.3:** постоянные
R-награды архетипов, однократный подарок и сохранение Искр. Обычный переход

сравнить ограниченные награды за Перьев+Искры с неограниченной

вложений при одном кошельке; поздний нулевой прирост M раскрыт; ни D, ни Favor

Игровая эффективность/частота действий, HP/урон/ОД и полный баланс ещё не проверены.

#### Выбор повторяемости

Рассмотрены два варианта: платить R за каждое завершение с тем же архетипом
или сохранить награду за освоение нового для фракции направления, убрав сброс.
Первый превращает повторяемую покупку одинакового проекта в дешёвую культивацию
за две валюты и требует отдельного нового баланса. Автор выбрал второй:

- Один раз за всю историю души для сочетания **фракция + архетип** выдаётся10 R.
  Новая реальная фракция — новая область работы и свой набор первых наград.
- Повтор/перестройка/retire, новый tier, переименование, возвращение из Хаоса,
  новая смертная жизнь и повторный вход не возрождают уже полученные10 R.
  Более сильный проект даёт собственные гражданские эффекты, но не новые R
  только за повышение tier. Награда за каждый tier в этом варианте не вводится.
- Формальная замена ID/разделение/объединение существующей фракции не должны
  обнулять историю: прежние основания сохраняются по реальной преемственности.
  Новый самостоятельный контент отличается фактическим сообществом и результатом;
  один лишь новый GUID не доказывает новизну. Смысл обосновывает GM, клиент
  проверяет identity/историю/допустимость выдачи, а не достоверность прозы.
- Новое native discovery сохраняет20 R один раз на действительно новую
  материализацию. Два найденных seeded проекта не являются проектами, которые
  построил игрок: само обнаружение не выдаёт ещё два project-бонуса. Первая
  собственная подходящая работа во фракции имеет отдельное основание10 R.

Это не общий потолок R: число действительных новых сообществ/достижений не
фиксируется, а культивация не зависит от наличия неосвоенного архетипа.
Существующие цены проектов/discovery и их точные скидки этим срезом не меняются.

#### Принятые источники дальнейшего Сияния

| Источник после первого вознесения | Награда/повторяемость |
|---|---|
| Первый собственный проект данного архетипа во фракции | 10 R по постоянной истории выше |
| Новое native discovery | 20 R по единственному основанию materialization |
| Завершённое значимое духовное задание | 10 R за самостоятельную задачу с существенным вкладом и состоявшимся результатом |
| Крупная духовная сюжетная развязка | 20 R вместо10 за устойчивое последствие для сообщества душ/Обители/иного духовного пространства |
| Культивация | Основной путь по уточнению5.5; купленное количество R за Перья, новый тариф открыт |

Два сюжетных размера приняты как новые правила, не существующие выплаты Soul Quests.
Ценность определяется ставками, вкладом, трудностью и состоявшимся последствием,
не добротой выбора, красотой текста или количеством убитых. Простая доставка,
повтор разговора и обычный бой не дают автоматического R. Они могут иметь
свои денежные/предметные награды. Бой как часть значимой задачи может привести
к её завершению; это одно основание R, а не дополнительный XP за каждого врага.

Награда за один результат не удваивается переупаковкой в quest/achievement:
«построить этот проект» не приносит project10 плюс ещё quest10. Самостоятельная
развязка большой линии с другими действиями/последствиями может иметь собственную
награду; отличие должно быть обосновано, не выведено из разных receipt IDs.
Новое содержательное происшествие допускает новую награду, даже если тип задания
знаком; повтор уже зачтённого эпизода, reload и воспоминание исторической роли — нет.
Нынешняя отложенная выплата Soul Quest при Life Evaluation не применяется второй
раз к уже закрытому новому духовному основанию. Точный договор settlement ещё
предстоит спроектировать через существующий publisher/receipts.

Растущая после вознесения душа может получать R за духовные достижения и в Море
Хаоса; новое пространство не требует нового рангового кошелька. Это принятое
расширение области наград, не факт существующих handlers. За новую смертную
жизнь автоматически R не выдаётся, E не открывается: сохраняются её другие
награды, включая Перья для дальнейшей культивации. Благоволение не умножает R.

#### Искры после вознесения

Приняты **100 Искр однократно при первом законном вознесении**. Это
добавление к уже законно заработанному, не присваивание100/max(balance,100).
Если подарок уже отражён bootstrap-результатом, второе начисление исключено.
Благоволение подарок не увеличивает. Возврат/новая жизнь/повторное прибытие
сохраняют баланс, дробные остатки и историю, без повторного подарка.

Возобновляемые источники: собственные предусмотренные награды конфликтов;
задания/события духовного мира, которым явно назначена выплата Искр; ограниченный
обмен Казны по существующим25:1 и3 за настоящий incarnation cycle. Для нового
задания приняты базовые ориентиры: небольшое поручение2 Искры, значимое5,
крупная развязка10. Это ориентиры новых источников, не автоматическое требование
платить обе валюты/Искры в каждом пространстве. Источник/получатель/обычная сумма
определяются до выплаты; не выводятся из отсутствия денег у игрока. Например,
поручение Обители может дать2 Искры и0 R, значимая линия —5 Искр и10 R.
Существующие редкие сюжетные пакеты, включая Сарефа, имеют собственные суммы;
их запись в rewardBundle сама по себе не доказательство зачисления.

Благоволение применяется к заработанным Искрам по принятому +0,5% за единицу
и точным остаткам, но не к подарку/обмену/переносу собственных средств. Cap кошелька
100 удаляется; квота обмена3 — иной договор и сохраняется. Цикл Казны связан с
канонической новой инкарнацией, не числом входов или новым случайным cycleId.
Возврат в той же инкарнации его не обновляет. Различные источники не должны
становиться отдельными независимыми кошельками или системами начисления.

#### Ограничения экономического вывода и проверки будущей реализации

Стартовый подарок позволяет оплатить несколько проектов/улучшений, затем нужен
заработок. При полном исчерпании8 первых архетипов одной фракции это80 R;
нынешний civic gate native discovery требует R100, а не боевой порог R20.
Поэтому нельзя обещать, что одни эти проекты всегда откроют следующий источник:
нужны достижение/культивация/другая доступная фракция. Default factions пуст;
доступный контент начальной Обители не возникает из таблицы наград автоматически.
Сквозная доступность хотя бы платной культивации без проекта/Sparks должна быть
проверена до реализации, civic gates этим срезом молча не переписываются.

При оценке цены нельзя считать Искры бесконечно покупаемыми по25:1: квота3
не позволяет купить20 за один цикл. Дешёвые проекты расходуют ограниченный
ресурс и открывают собственные эффекты. Культивация — независимый путь за Перья;
её окончательный тариф и темп R всё ещё требуют отдельного решения автора.

Будущая приёмка: первый/повторный подарок с balance0/37/150; проект затем
repeat/retire/tier-change/reentry/новая жизнь/смена ID без нового содержания;
новая настоящая фракция; discovery с seeded projects без лишних наград;
один результат в quest/project и самостоятельная большая развязка; новый
эпизод против replay; отсутствие ретровыплаты уже полученного при Life Evaluation;
обмен3 против4, тот же/новый incarnation cycle; Favor/carry/баланс>100;
reject/repair/reload без двойной выплаты и без расхода без результата.
Стабильные профили и история в одной операции читаются существующим сервисом
кэша с полной identity/revision/инвалидацией. Свежие ownership/фаза/право выдачи
и публикация не заменяются сохранённым результатом. Runtime/баланс UNRUN.

### 5.4. Исторический тариф дополнительной культивации — отозван после5.5

**Автор не принял этот тариф; затем уточнил основную роль культивации в5.5.
Математические примеры сохранены для сравнения, не как действующая рекомендация.**
Не менять принятое D, ширину порогов, награды, цену статов или отсутствие потолка.
Не добавлять ожидание, дневной лимит, обязательную фракцию/Искры для культивации.
Цель — сохранить дорогой независимый путь за Перья, полезный для ускорения и
добора прогресса. Не требуется, чтобы покупка заменила содержательные достижения.

У прежнего тарифа два множителя удорожания: растёт цена каждой единицы R и
число R в интервале, дающем10 D. Поэтому0→20 стоит2800,300→420 —25200,

делает широкое усиление заметно дешевле по сравнению с известным примером
специализации; рекомендуется более осторожный+800r. Это калибровка дизайна,

#### Частичная покупка и округление

Игрок вправе купить любое доступное целое количество R, не обязан оплачивать
целый интервал. Для r текущий интервал начинается в A_r, имеет ширину W_r.
Для r≥9: A_r=560+140(r−9), W_r=140; до этого берутся принятые пороги.
Накопительный ценовой индекс, вычисляемый из текущего R и редакции правил:

```text
C_r = 2800 + 800r
H(R) = 2800r + 400r(r−1) + (R−A_r) × C_r / W_r
T(R) = ceil(H(R))
цена покупки R=a → R=b = T(b) − T(a), b>a
```

H вычисляется точно по формуле и текущему интервалу, без перебора покупаемых
единиц R. Округляется общий индекс, а не каждая заказанная порция.
Поэтому цена a→b→c равна a→c при неизменных правилах и без промежуточных наград.
Примеры:19→21 стоит284,109→111 —268,560→580 —1429. Нет дополнительного кошелька
дробных Перьев/кредита, T не хранит фактически потраченные Перья и не является
долгом. Органические+10/+20 R бесплатны; следующий заказ просто начинается с
нового фактического R. Никакого списания за пропущенную наградой часть индекса нет.
Цены всех единичных повышений положительны; в первых интервалах минимум65,
с r≥9 нижняя целая стоимость растёт вместе с C_r/140. Игровой максимум не вводится.

Цена одной сырой единицы R иногда снижается при расширении интервала, поскольку
для сопоставимого роста D теперь требуется больше R. Цена полного интервала
при этом всегда растёт. Показывать R/D до и после, общий расход и доступный
объём; не обещать фиксированную цену+1 R или немедленный+1 M от любой покупки.
Полный расчёт и свежие phase/wallet/revision проверки выполняются до атомарного
списания/публикации. Между preview и принятием изменился R/кошелёк/редакция —
пересчитать и подтвердить новый quote. Повтор receipt не оплачивает/не выдаёт
рост заново; существующие rollback/ownership сохраняются. Новый respec не вводится.

Условный профиль B из5.1 при E60, множителе1.5 и Благоволении7 даёт826 целых

такой жизни. При выделении половины — около61 и20.3 соответственно. Это

На известном примере E60/R300 покупка базы70→78 стоит2980 за+8 одной применимой

HP/урон/криты пока не рассчитаны. Благоволение по-прежнему зависит от собственного

Кандидат E100+25floor(QE) этим не принимается и не меняется. Его последний
интервал46→60 стоил2800 за10 D; начальный интервал R сохраняет эту цену,
поэтому смена фазы сама по себе не создаёт скачка стоимости сопоставимого роста.
Первые проекты могут оставаться выгоднее: у них иные условия и расход Искр.
Проверка полного игрового темпа остаётся будущей задачей, не разрешённым сейчас
production/600-секундным прогоном. Для этого среза достаточно точной арифметики,
независимого review и предъявления автору текущей рекомендации.

### 5.5. Культивация как основной рост и награды прорыва

**Новое обязательное направление автора:** культивация — основной способ
развития и Просветления, и Сияния. Переход на новый ранг должен давать ощутимое
постоянное усиление в духе культивации из донхуа. После обсуждения автор ответил
«да» на вариант автоматической прибавки ко всем пяти характеристикам при новом
ранге с сохранением ручных вложений для специализации. Затем автор принял
предъявленные +3 E/+5 R и полную награду сверх предела покупки (5.6).

Игровой цикл: получить ресурсы в смертной жизни/духовном мире → осознанно вложить
их в культивацию → достичь нового ранга → получить усиление и новые возможности.
Задания, проекты и открытия сохраняются как дополнительные источники прогресса.
Основная роль — требование к доступности и экономике, а не запрет сыграть иначе:
не вводить обязательный процент покупок, минимальную долю культивации, счётчик
жизней или штраф за развитие через найденные достижения. Нынешние законные
условия первого вознесения сохраняются; обязательные задания на каждый ранг
не добавляются этим срезом.

#### Что требуется пересмотреть

- Прежние цены E100+25floor(QE) и R2800+800r за интервал были подобраны для
  дорогого дополнительного пути. Они отозваны как текущие рекомендации.
- При сохранении10 E за содержательную жизнь и порога60 пять жизней дают50 E
  сами, шесть —60. Более низкая цена одна не сделает культивацию основной при
  том же ориентире5–6 жизней: либо раньше наступит вознесение, либо естественный
  прирост останется главным. Пересмотр завершён принятием0/1/2/3 и цен E5.7;
  ориентир и качественные критерии четырёх категорий сохранены.
- Для R награды10/20 тоже нужно сопоставить с ролью:20 R равны целому первому
  интервалу. Но discovery сейчас требует civic R100, поэтому этот пример не
  доказывает реально доступный прыжок сR0 через discovery. Учитывать actual gate,
  частоту/доступность задач и новые награды рангов; не снижать выплаты молча.
- Прежнее абсолютное правило «характеристики растут только от прямой покупки,
  ранг сам ничего не добавляет» пересматривается. Сознательное вложение остаётся
  в выборе культивации/специализации; произвольный обычный ход не даёт автостаты.

#### Принятая основа прорыва — автостаты всем пяти и ручная специализация

Рассмотрены два варианта: общий автоматический прирост характеристик
при новом ранге либо набор очков, который игрок распределяет сам. Первый
лучше передаёт общее преображение души, второй сильнее подчёркивает выбор билда.
Автор выбрал общий автоматический прирост Мощи, Чуткости, Воли, Цельности и
Благоволения при каждом новом ранге Просветления или Сияния; отдельные покупки
за Перья сохраняются для специализации. Обязательная двойная система
«всем автостаты плюс ещё распределяемые очки» сейчас не вводится.

Включение Благоволения и размеры +3 E/+5 R приняты в5.6. Дополнительные пассивы/новые способности
на каждом ранге тоже не объявляются выбранными без конкретного содержания.

Усиление должно быть видимо: переход показывает ранг, базовые характеристики
до/после и рассчитанное изменение параметров. Рост D/статов должен отражаться
в будущих формулах здоровья, силы воздействий и проверок по их собственным
контрактам; HP/урон/ОД ещё не определены и не выдаются за готовый эффект.
Доступ к более высоким уровням искусств может быть частью ранговой системы,
но открытый доступ не означает бесплатного изучения/повышения самого искусства.

Награда относится к достигнутому рангу: законный дополнительный прогресс от
задания не лишает её и не требует заново оплатить этот прогресс культивацией.
Прорыв и его награда должны иметь единственный результат для души/достигнутого
ранга: повтор принятия, вход в Обитель, новая жизнь или rollback/repair не
создают вторую раздачу. Подтверждённые награды сохраняются вместе с развитием.
При пересечении нескольких рангов одним законным результатом нужна явная
обработка всех положенных рубежей, а не потеря промежуточных бонусов. Точные
границы выдачи и реализация входят в будущий план, а не обходят existing publisher.

Ручные5n и старт сохраняются. Автор принял полную автонаграду сверх предела

#### Экономика и порядок дальнейшего обсуждения

Состав, размеры основной награды и роль ручных покупок выбраны; теперь сравнить
естественные награды/цены культивации с доходами, сохраняя ориентир5–6 жизней
до первого вознесения. Это не повод снова ставить цены до определения отдачи.
Автоматический рост Благоволения меняет валютные награды и скорость
следующих покупок: нельзя использовать модель постоянного Благоволения7 как
доказательство баланса такой новой схемы.

Узкая предварительная консультация показала, что при неизменном Благоволении7
и условном профилеB сочетание естественных0/1/2/3 E с ценой20+5floor(QE)
может дать5–6 жизней при вложении40–50% дохода. Это иллюстрация осуществимости
пересмотра, не текущая рекомендованная таблица или принятое изменение0/4/10/15.
После введения автонаград расчёт надо повторить с фактическим профилем; доля
вложения не становится обязательной игровой квотой.

Дешёвый кандидат R800+200r тоже нельзя объявить решением только по доходу:
при R300 полный интервал стоит2200 за широкие+8 M, тогда как база70→78 стоит
2980 за одну проверку. Это риск вытеснения специализации; автостаты прорыва
усилят его. Такая цена не выбрана. При основной культивации равная ценовая
эффективность двух путей не обязательна, но смысл ручных вложений должен быть
объяснён их реальными эффектами, не ещё не рассчитанными обещаниями.

Критерии будущего согласованного решения: доступный основной рост за часть
дохода с местом для искусств/реликвий; ощутимое подтверждаемое усиление каждого
заданного прорыва; дополнительные достижения без обязательной цепочки задач;
чёткое разделение D/автонаграды/покупки и отсутствие двойного учёта; сохранение
награды при возвратах и точная обработка нескольких рубежей; учёт Favor и
пределов; реальные причины специализироваться. Численные ранговые бонусы
уже приняты в5.6, E-экономика —5.7; R-цена и реализация требуют согласования.

#### Частичная покупка без переплаты за дробление

Пусть A_r — начало текущего интервала, W_r — его ширина из принятой таблицы
T_R. При r≥9: A_r=560+140(r−9), W_r=140. Тогда:

```text
C_r = 800 + 300r
H(R) = 800r + 150r(r−1) + (R−A_r) × C_r / W_r
T(R) = ceil(H(R))
цена a→b = T(b)−T(a), b>a
```

H рассчитывается точно; округляется единый индекс, не каждая порция отдельно.
Индекс не хранит фактические расходы и не является долгом души. Бесплатные
R просто меняют исходную точку следующей покупки: после награды0→10 покупка
10→20 стоит400, а не800; награда не оплачивается задним числом. При отсутствии
внешних наград/изменения правил a→b→c стоит столько же, сколько a→c.
Примеры:19→21 стоит84;109→111 —88;559→561 —47;560→580 —500.

Цена единицы R не обязана монотонно расти: ширина рангов меняется, а один
сырой R даёт разную долю Q/D. Например первые полосы стоят40 и44 за R,
а в420→560 средняя цена3200/140. Полный ранг всегда дороже предыдущего.
Все единичные цены положительны: для первых девяти полос минимум22, далее
при ширине140 и растущем C цена растёт. Это не скрытая скидка от дробления.
Показывать цену заказа, R/D до/после и конкретные пересечённые ранги, а не
обещать фиксированную цену любого +1 R или мгновенный +1 M.

Пакет рассчитывается целиком и публикуется одним результатом существующего
accepted workflow. Все пересечённые награды +5 выдаются ровно один раз;
повтор/reentry не повторяет ни платёж, ни награду. При изменении профиля/фазы/
кошелька/редакции между preview и принятием нужен новый quote, не скрытая замена.
Формула D и единственное итоговое floor суммы Q_E+Q_R не меняются.

Рассмотрены800+100r,800+200r и800+300r. Все сохраняют первый шаг800.

поэтому их продажа не считается обязательной частью бюджета.

#### Точный частичный платёж

Для R пусть a_r — нижний порог интервала, w_r — его ширина. Определить
`T(R) = 100r + 25r(r−1)/2 + ceil((R−a_r)(100+25r)/w_r)`.
Стоимость a→b равна `T(b)−T(a)`, вычисляется целочисленно/рационально.
Для E аналогично prefix сумм единичных тарифов. Проверенные R-примеры:
19→21=10;109→111=9;559→561=5;560→580=47;0→80=400;80→100=100.
Естественный R меняет начало следующего расчёта, долга за бесплатные единицы нет.
Все пересечённые ранги дают +5 однократно, не только последний. При изменении
R/E/wallet/revision новая котировка; cached DATA не разрешает списание без fresh checks.
Не добавлять постоянный кэш для дешёвой арифметики. При большой операции один
раз получить стабильные определения/профиль через существующий operation service.

## 6. Контракты реализации и приёмка после согласования

Один профиль владеет базами/E/R/фазой. Его создание, покупка и награда проходят
существующие authoritative accepted-turn/receipt пути; UI/GM/normalizer не могут
независимо начислять один результат повторно. Отказ проверяется до списания;
ошибка публикации не оставляет расход без роста. Новый цикл не сбрасывает базы,
E/R и бесплатное создание не повторяется. Не требуется поддерживать старые saves.
Гражданские пороги R0/100/220/380/580 и NPC profile tiers имеют иное назначение:
не подменять ими Q_R или право игрока на покупку. Автопрогрессия NPC не начисляет
`player_soul`; её полный баланс и рост характеристик NPC остаются отдельной работой.

При будущей реализации стабильный профиль/правила одной операции разрешения
переиспользуются через существующий Service–Repository cache: ключ включает
душу, revision профиля, редакцию правил и применимые источники; lifetime одной
операции, после мутации инвалидирование. Для дешёвой арифметики отдельный кэш не
нужен. Свежие ownership/balance/phase/publish проверки кэшем не заменяются.

Критерии проверки с дешёвыми типизированными фикстурами после утверждения:

1. Однократный старт5×5+10, все распределения в пределах10; новая жизнь не даёт
   новых бесплатных пунктов; роль воспоминания не пишет в настоящий профиль.
2. Предельные цены и суммы из таблиц; снятие реликвии не меняет цену базы;
   превышение рангового предела/нехватка средств не списывают валюту.
3. Проверить принятую автором цену5.7: E7→9=45,
   E0→60=1880 (прежние225/9400 отозваны); покупка сверх60 не оплачивается;
   органическое59+2=61 сохраняется целиком. D до/после вознесения одинаков,
   E не открывается вновь. Принятые числа не заменяют согласования технической реализации.
4. Точная Q-сумма: E80/R27 даёт77, а не76; каждый порог непрерывен до floor;
   R560/700/840 продолжают развитие/цены без clamp индекса или D.
5. Награда жизни не равна FinalFeathers; категории требуют evidence; Favor
   усиливает валюту, не XP; duplicate receipt, retries и reject не дублируют рост.
6. Пакетный quote равен сумме последовательно рассчитанных цен, но публикация
   одна; изменённая фаза/revision требует нового quote. Новая цена не применяется
   задним числом к уже принятому receipt, overflow не теряется.
7. Console/browser/GM показывают одинаковые стоимость, результат и причины
   недоступности. Изменённые источники/нормализация/шаблоны/примеры синхронизированы.

Сейчас проверены только арифметика примеров и связность документов. Runtime,
игровой баланс, миграция активных templates и перечисленные production-контракты
не реализованы и не проверены. До исполнения нужны рассмотрение точной spec,
пересборка [plan](plan.md)/[tasks](tasks.md) и consistency. T001 остаётся закрытым gate.
