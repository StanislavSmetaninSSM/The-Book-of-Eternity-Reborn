## Skill and Guideline Set

- `book-eternity-dark-fantasy-ui`: project-specific dark-fantasy Browser Client rules, C# authority boundary, plain-CSS design-system constraints.
- `frontend-design`: distinctive game-client visual direction rather than generic SaaS/web shell styling.
- `web-design-guidelines`: accessibility, focus, responsive layout, motion, image, touch, and dark-mode checks.
- `vercel-react-best-practices`: simple derived UI state, no always-loaded debug UI, typed DTO boundaries.
- `browser` / `browser-act`: preferred live/browser verification surfaces when feasible.
- Superpowers: Spec Kit bridge, TDD/source-guard first, systematic debugging for the tab-count smoke failure, verification-before-completion.

## Baseline Findings

- The focused .NET browser/local-web baseline failed in `LocalWebUiBuiltFrontendSmokeTests.BuiltFrontendSmoke_LaunchesHostWithViteDistAndCapturesDiagnostics`: `ExtractPlayerTabs` expected 4 tabs but current `tabBarConfig.ts` has 5 tabs after the QTE practice route.
- `command-ui.css` is imported last and currently overrides `.browser-shell` with a flex shell and generic blue-gray fallback colors, weakening the earlier dark-fantasy design-system modules.
- `tabBarConfig.ts` stores emoji strings for player navigation icons; #930 touches navigation, so the route should move to styled local glyphs rather than emoji markers or an external icon package.
- Several legacy CSS aliases (`--surface-raised`, `--color-accent`, `--color-success`, `--color-warning`, `--color-error`, `--text-secondary`, `--space-xs`, `--space-sm`, `--space-md`) still rely on fallback colors in command UI selectors.
- Existing source guards already keep many technical details behind advanced mode, but #930 needs focused coverage for changed navigation/CSS/default artifact surfaces.
