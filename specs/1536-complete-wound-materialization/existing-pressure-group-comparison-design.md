## 2. Supported set, and what remains closed

Proposed comparison scope is deliberately finite:

- Chaos Sea, positive signed turn, exact player soul `player_soul:player_soul`;
  continuing original-prefix owner, its next unstaged ordinal and the last complete
  original direct-root standard `pressure/setback` exchange against standard
  incoming `pressure`. Keep signed dice, complete ordinary snapshots, final root
  echo, exact pointer/inventory and normal chronology/rules/resource validation.
- Exactly **one or two distinct existing active signed rank-III player wounds**.
  Each has exactly one available, graph-valid root/component for
  `spiritual_strain_burden/pressure`, magnitude1, current/max stacks1 under the
  existing valid parent graph contract. No caller-supplied parent list or count.
- `0 <= beforeRank < ordinaryRank < 4`, so ordinary rankI, II or III is supported
  for comparison. This explicitly admits ordinaryIII DATA without requiring a
  hypothetical ordinary+1 to be below `broken`. It does not qualify cap arithmetic.
  The ordinary source must be a genuine increasing, non-guaranteed standard player
  pressure source, with no special art, explicit re-trauma or preexisting strain
  preimage. Its normal calculated maximum is retained, including a legitimate
  ordinary maximum0; comparison DATA is not zero-source admission. The singleton
  actual adapter retains its existing positive hypothetical-actual ceiling gate.
- All other available contributions stay installed and pass their existing
  consumers, including applicable non-strain pressure burdens on a selected wound
  or another wound, costs, rolls, position/tempo/restrictions and the other side.
  Their presence is not permission to bypass an unresolved consumer.

Collect **every matching strain row before rank/count filtering**. Validate its
source/root/component and parent joins; then require the whole set to fit the
above contour. A third strain parent, IV parent, same-turn/mixed parent, unsupported
matching descendant/graph, unavailable/mismatched required root, foreign/missing/
stale parent or invalid duplicate refuses the group. Never take the first two,
drop an unsupported row, retry as singleton, or repair invalid DATA by `Distinct`.
There is no full FR-025, arbitrary-N, multi-actor, ambiguous failure, no-effect,
same-turn, special-art, terminal/replacement, mixed-healing or actual-zero extension.
Current effect-carrier collision restrictions stay closed for actual projection.

Completeness is relative to authenticated current/signed input and its complete
accepted mechanics projection, not a fixture's external list of expected wounds.
A legitimately authored and signed singleton is valid. Removing/changing the
second parent after its signed/captured frontier is an integrity/freshness failure;
the implementation cannot infer an erased historical wound from untrusted metadata.
An independently valid other-participant wound is not a missing player parent:
do not count it, and keep its applicable consumers installed. A foreign-parent
negative must target a claimed matching player's source or an already captured
member, not assert that every different valid signed world should contain two.

## 4. Alternatives and recommendation

1. **Separate group-query lane, duplicate evaluator.** Easiest to keep actual
   untouched, but duplicates source/resource/probe validation, dependency identity
   and lifetime rules. It risks inconsistent ordinary meanings and repeated work.
2. **Reusable group comparison core plus a named private singleton actual adapter
   (recommended).** Preserve the existing query API as the group comparison lane;
   share only authenticated group capture, ordinary evaluation and immutable DATA.
   Require a separate private singleton basis before the actual caller may read/
   reuse that DATA for projection. No caller-selectable skip/count/permission flag.
3. Widen the shared isolation directly and rely on the v3 constructor to fail:
   reject. This is an incomplete transition, may evaluate/allocate too far, and
   does not preserve legacy other-wound and hypothetical+1 eligibility fences.

Keep `SpiritualOriginalTurnCapture.ReadExistingPressureOrdinaryComparisonAsync(lease)`
and its existing detached return type. No new public API is needed to turn the
accepted pair RED GREEN. Proposed private implementation names below specify
responsibility, not permission to implement before approval:

- `ExistingPressureComparisonGroup`, nested in the owned mechanics context, has a
  private constructor and immutable ordered `Members`; each member retains full
  current/signed canonical parent DATA, source-group key/fingerprint and its exact
  strain-row references. It has **no** `FirstParent`, singular parent accessor,
  persisted permission or public list/count constructor.
- `CaptureExistingPressureComparisonGroup` derives and validates the full set from
  that context. `Isolates(context,row,conflict,exchange)` requires the exact same
  current context, exact conflict and complete frozen ordinary exchange, and
  reference membership in the selected strain rows. Matching effectId, woundId,
  profile or source alone never isolates siblings. It is used only inside the
  discarded ordinary prospective evaluation.
- A named `ReadOwnedSingletonPressureOrdinaryForProjectionUnderGateAsync` adapter
  first captures that complete group, then privately mints
  `ExistingPressureSingletonActualBasis` **before ordinary cache lookup/evaluation,
  actual projection construction or allocation**. It requires one member/one exact
  row and every old actual restriction, including the old other-wound pressure
  exclusion, rankIII, stacks/magnitude, realm/actor, shape, before<ordinary,
  ordinary+1<4, no special/target/same-turn, existing healing/prior-mapping exclusions.
  After the core ordinary result it independently requires the unchanged +1
  hypothetical actual positive-ceiling test and existing carrier-collision check.
  Only this private basis can supply singular parent/effect/component DATA to the
  existing v3 `PressureProjectionData` constructor. A pair query success cannot
  construct it or be passed back by a caller as proof.
- Both named lanes call the same private ordinary core with an owner-issued group
  and exact frozen input. Query returns detached ordinary DATA only. The adapter
  rechecks live eligibility even on a core DATA hit. Do not implement the distinction
  as a public Boolean or infer it from which fields a returned DTO happens to have.

The core removes hypothetical actual +1/<broken/positive-ceiling checks from its
ordinary-only predicate. The adapter preserves them for actual, with no change in
accepted v3 shape/bytes/meaning. This move and the explicit actual guard must land
atomically, never as separate production stages. Leave `MatchesActualSource`,
live/pre-stage guards, raw/C2 successor checks, completion/cold rederivation,
receipt/History readers and all wire version dispatch unchanged.

## 5. Full-set validation, ordering and computation

Under the existing capture gate, then source continuation gate and existing resource
access discipline:

1. Retain all existing real lease/capture/source/resource/effect/current-prefix,
   unresolved-wait, input/request, origin, original inventory and direct-root checks.
   Use current signed participant ownership, not a supplied actor or parent list.
2. Enumerate the complete available player pressure-strain projection without
   prefiltering rank/count. Partition by exact `(realm,kind,woundId)` only after
   duplicate/identity validity checks. Enumerate every actual matching source/root,
   validate full group definitions, all declared roots and lineage, exact target,
   source links, availability/generation and fingerprint recomputation. Preserve
   existing complete graph validation, including invalid unselected graph content.
3. Resolve all selected active parents in one validated current view and one
   separately authenticated signed view. Require complete carrier/identity/History
   agreement, exact owner/realm/path, full canonical signed/current equality and
   current source-group match for **each** member. Signed creation/receipt and
   historical checks remain in their existing owners; no resealed DATA creates
   historical C2/C4 authority. Reject same-turn or incomplete signed-existing joins.
4. Require the proposed complete supported set. Duplicate profile/operation within
   a wound is already invalid through `WoundMaterializationContract` and
   `WoundConsequenceEnvelopeCatalog`'s shared coordinate set. Duplicate rows/root
   identities are invalid, not count-one success. Multiple legitimate non-strain
   components on one shared root are siblings, neither extra wounds nor isolated
   strain. A valid but unsupported repeated/descendant strain contour must refuse,
   not be deduplicated into the supported one-row-per-parent shape.
5. Canonicalize private member DATA by exact ordinal wound/source key, then exact
   root/effect/component key. Contribution traversal retains the existing projector
   order; identity is insensitive to harmless parent-carrier/definition property
   enumeration permutations after their validators accept them. Preserve semantically
   ordered History, exchange inventory, receipt prefixes, definitions/lineage where
   their contracts require order. Never sort away invalid duplicates. No new parent
   array is serialized, so there is no v4 array-order acceptance rule in this block.
   Equivalent parent/effect DATA reordered before independent signing may yield the
   same ordinary result/canonical member DATA. Reordering after signing or capture
   still violates exact bytes/freshness. Equivalent DATA across captures never
   means a cross-owner cache hit or transferable authority.
6. Begin the existing discarded conflict-validation probe once. Call the shared
   `EvaluateProspectiveCoreAsync` once with group isolation. It must independently
   produce exactly one added checked exchange and player harmful ordinary source,
   unchanged accepted prefix/pending inventory and exact full frozen ordinary root.
   Keep full shape/dice/rules/source calculation and genuine resource batch building,
   with one complete batch/no pending sides and exact source/conflict/exchange/ordinal.
   Return one detached ordinary calculation and expected two-side transitions.
7. Dispose the probe before returning. Repeat opening/closing raw-input, signed
   origin, current-owner/context and complete dependency checks. Ordinary evaluation
   never commits a resource batch, claims dice, advances ordinal or exposes a ticket.

Grouping, isolation and eventual counting are different: the group proves the whole
set; isolation suppresses **all and only** its strain rows in one common ordinary
evaluation; future aggregation counts each valid wound once. This block performs
neither one evaluation per parent nor actual-minus-N reconstruction nor actual sum.

## 6. Reuse, fresh checks and invalidation

Use the existing source-owned `ValidationOperation` and operation service, not a
dictionary/static cache or another framework. Its reusable value is immutable
ordinary comparison DATA. A hit does not return an owner or actual capability.

- Owner/lifetime: exact source and capture's usable unstaged mechanics window,
  canonical lease, continuation revision/ordinal, resource owner/routing epoch,
  wound draft/read and dependency-cut version. Dispose with comparison invalidation,
  successful actual staging/ordinal advance, failure, cancellation, owner revocation,
  retry, route/draft replacement or capture disposal. New attempts get new owners.
- Identity: bump the computation revision and use explicit semantic lane
  `comparison_data/group_v1`, complete frozen raw/input inventory and witnesses,
  original snapshot/session/request/token/turn/realm, full exchange/pointer/prefix,
  complete canonical member set and graph/component/availability DATA, exact owner/
  lease references, source/resource baseline/continuation and all versions above.
  Keep all other contributions and their availability/group facts in dependencies,
  not only selected parents. A changed second parent invalidates the whole group.
  A changed structural snapshot invalidates retained group, parsed views, input and
  identity slots, not merely the computed result. Revalidate the full group from
  the still-current owned basis or refuse; `GetOrCompute` cannot repair a stale
  `_ordinaryGroup ??=` selection on a cache miss. The context currently filters
  unavailable rows. Prove that making one available changes its existing epoch/
  wound/cut version, or retain the complete accepted projection plus availability
  in the dependency inventory; an invisible newly available row must not be missed.
- The named actual adapter has a distinct private `singleton_actual_v3` authority
  role and fresh eligibility proof; it is never stored in or recovered from the
  comparison cache. Its unchanged singleton core DATA may reuse the query's core
  computation **only when the full core identity/dependencies match**. Keying by
  public entrypoint would duplicate the same ordinary probe unnecessarily; keying
  permission as ordinary DATA would be unsafe. Neither a cache hit nor detached
  query DTO can satisfy the actual adapter's private basis requirement. There is
  no mode-dependent validation in this homogeneous core and therefore no query/
  actual mode cache key. If implementation retains such a difference, it must key
  that mode and invalidate all retained `??=` group/input/identity slots, or stop
  for design revision; two different computations may not share this cache entry.
- Full current/signed catalog, identity and History validation is repeated today
  by `SpiritualWoundCurrentData.ReadActive` for every parent. Extract a typed
  validated-view/batch path in that existing service, with the existing singular
  reader delegating to the same checks. Build each authenticated current/signed
  view once per stable window, then resolve all parents from it. Reuse already
  parsed catalog/identity/History when its existing owner can supply them without
  changing lifetime; otherwise one new batch validation per view is justified.
  Do not loop four complete parses or repeatedly clone `WoundOperationBeforeData`
  properties; take each detached snapshot once. No view issues live permission.
  In the existing cheap DATA cases, compare both batch results with singular
  `ReadActive` on the same inputs and require both paths to refuse malformed views.
  This is shared-reader parity, not an extra native matrix or new case count.
- Fresh before every lookup and after computation/return: canonical lease/current
  capture/source/prefix/resource ownership; exact physical ordinary conflict and
  request plus all other retained witnesses; signed origin; context/ordinal/epoch/
  draft/dependency cut; complete rows/availability and recomputed graph fingerprints.
  Existing `CheckRetainedInputs` conflict exceptions do not replace the explicit raw
  fence. Physical edits fail even when the cached context object is unchanged.
  Expected signed/current member snapshots are DATA, not permission to reuse them
  after any writer or version boundary. Exceptions/partial/cancelled results are
  never cached as success. Overlap stays serialized by the current gates.

Prove one ordinary evaluator/probe and one resource batch computation on cold pair,
zero on a valid warm repeat, with fresh checks on both. Count actual current/signed
catalog/identity/History builds and parent resolutions separately at source entries.
Keep existing query/evaluator/signed-parent counters' meanings; do not relabel
resolutions as physical reads or infer saved IO from a hit. Two parents still
require two exact resolutions and more graph checks than one. Costs of identity,
fingerprint recomputation, copying and allocation are unknown; no speedup is claimed.
