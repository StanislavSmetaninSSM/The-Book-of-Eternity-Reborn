## 2. Proposed grant, and why it is a real decision

**Proposed grant G-C:** allow the existing main lifecycle subsystem, through an explicitly registered recovery owner, to reconcile one original run's recorded operations after transport/client/coordinator failure, retire their actual exhausted authority, and issue a durable `RetiredAfterReconciliation` receipt under the unchanged physical G. It may re-enter only the original owners' already-authorized finite debt settlement, then issue same-G quiescent admission for the exact handoff. It cannot recreate the lost operation, supply gameplay outcomes, create G, rebind old G, or mint target authority from M.

This adds a recoverable issuer where today only a live coordinator/original terminal can issue retirement. It changes durable lifecycle admission and cold recovery authority, including the existing main-metadata schema/namespace contract. Therefore **G-C is UNACCEPTED and must be discussed as a concrete principled grant**, not silently classified as routine D11 extraction. The canonical design's “no new journal” rule is not interpreted as permission to add an operation ledger: the bounded extension below must be expressly accepted as lifecycle-owner metadata. It is not a new gameplay journal.

Minimal proposed API/authority assumptions (all UNACCEPTED, names illustrative):

1. **A1 `RegisterOriginalOperationLifetime`**: before activation, the actual main owner durably registers an exact operation and the participant holds an OS-backed per-operation lifetime guard until all its local/borrowed work, finalizers and owner cleanup have settled. Every operation-derived asynchronous/native writer must retain that lifetime or its own registered native owner. The bridge captures real endpoint/process-instance identity using a platform-owned observation, never request PID. This adds actual in-flight-work ownership missing from the current handshake.
2. **A2 `PublishOriginalOperationDisposition`**: a strict bounded extension of existing main-owner persistence stores Prepared/Active/Revoked/terminal facts, exact terminal frames where observed, exact owner obligations and retained handoff references. Publish-before-activate and durable terminal readback precede release. No active/debt row is evicted. The current 32-active limit remains; HC/H3/HQ referenced terminal records remain pinned until their actual consumer releases them. A full retained set refuses new admission rather than dropping evidence. Unknown is never terminal.
3. **A3 `ReconcileRevokedOriginalRun`**: a recovery-only lane closes admission, obtains actual participant exhaustion and native/managed retirement proofs, reconciles known debt through its original owners, and terminalizes each exact operation. It does not set `_pins=0` or clear a catch-all uncertainty flag. Uncertainty becomes owner-identified obligations, each requiring its own disposition; unexplained uncertainty blocks the lane. Existing live handles expire only upon verified terminalization of their own row.
4. **A4 `OriginalNativeScopeRecoveryCustody`**: original native scope identity and stop observation must survive loss of the managed bridge. A platform-owned custody mechanism registered before terminal release must retain the original handles/scope and persist stop proof, or support exact same-scope recovery with equivalent proof. Linux supervisor/cgroup and Windows Job/ConPTY need separately specified adapters. A replacement connection may consult the custodian; it cannot become a replacement live pin. No arbitrary PID termination, PID absence, newly opened unrelated Job, or name-only systemd lookup suffices.
5. **A5 `AdmitHandoffAfterOriginalRetirement`**: a private adapter validates durable lifecycle proof, current physical G, exact source/target originals and H2, then issues the named HC/target-bound recovery capability under the actual quiescent guard. For Lost it consumes `RetiredAfterReconciliation`, never manufactures `ClosedObserved`. HC/H3/HQ use the same genuine debt/retirement contract.

A1–A3 are necessary even if the original coordinator survives. A4 is the irreducible extra issue for full coordinator-crash recovery: the inspected code has no demonstrated issuer for it. This report specifies A4's acceptance contract, **not a working backend implementation or a completed platform design**. If A4 cannot be provided within accepted lifecycle scope, the concrete user decision is whether to authorize such recoverable original-scope custody. Without that grant and actual platform design, full DEP-C cannot be declared solved. A reboot-only escape, requiring that the original bridge never crash, or retaining an unexplained permanent block is not qualification of the required same-root restart route.

## 3. Identity, receipts and no-work proof

The owner binds every row to `I = {normalizedRoot, exactPhysicalG, runId, epoch, backend, hostInstanceId, bootId, pinId, closeId, operationId, participantInstance, lifetimeGuardIdentity}`. The first seven run fields retain their original meaning; G is exact existing storage identity, not freshly generated. Handoff correlation additionally binds source action, P/C original tuples, source n/k, exact H2 cohort receipt, target request/original tuple and phase HC/H3/HQ. Hashes protect exact bytes but confer no issuer authority.

Three distinct proof components are mandatory:

* **Participant exhaustion P:** owner has revoked admission for I and exclusively acquired the registered operation lifetime guard, or retains an equivalent actual original process-exit observation plus accounted descendant owners. Live clients release only after their registered tasks and borrowed scopes settle. OS release on process death proves that lifetime ended only under the A1 all-work coverage invariant; it does not settle durable writes. Retain the exclusive guard until I is durably terminal, so a late client cannot reactivate it. Work that outlives its process must have its own registered native owner; an unregistered escape invalidates qualification.
* **Native/managed exhaustion N:** exact original native scope stopped/empty; original terminal I/O and registered bridge input/pump/status work settled; actual worker-owner conjunction and handle disposal established. External participant P is separate. While the bridge lives, use actual bound tasks and original stop evidence. After its proven death, managed work in that process is gone, but custodian proof is still required for native descendants and publication debt. Proven host reboot can establish old-boot process extinction only through a trusted platform adapter; it does not replace debt reconciliation or same-boot qualification.
* **Debt resolution D:** complete finite registration of canonical publication, original/finalization, native transaction, specialized claim and main-metadata debt; each owner returns exact committed/rolled-back/readback-settled disposition. Discovering a missing obligation or undecodable native journal refuses, never produces an empty set. H2 committed/rollback classification comes from the actual cohort owner and exact bytes, not inferred from process death or `Outcome=Completed`.

Durable terminal receipt: `{I, retirementKind, revocationRef, participantProofRef, nativeScopeProofRef, managedSettlementRef, operationDebtReceipts, exactPublishedPhaseRefs, currentGReadback, retainedConsumerRefs}`. `retirementKind=RetiredAfterReconciliation` means authority exhausted and debt resolved; it does not imply the original business operation completed. ClosedObserved remains a separate exact terminal-frame fact, including Outcome/ClosingFailed. A failed close may exhaust the pin but still cannot issue HC until D resolves. Cold receipt parsing alone grants nothing: the recovery owner must acquire the real guard, validate original custody/provenance, exact namespace/phase membership and current G, then issue a narrowly scoped capability.

| Active / exact normal close | Freeze new borrowing; retain actual terminal frame after finalization. Persist exact owner-observed disposition before pin release. Close reply loss remains queryable from retained owner evidence. No reconnect/replay of the original close command. |

| Revoked / participant still live | Cancellation may request unwind; await actual P. If the client is hung, remain held. Cancellation request, elapsed deadline and pipe shutdown do not establish P. Do not kill an external browser/client process as a shortcut. |
| Revoked / P and scoped stop available | Obtain N through the actual retained native owner/custodian; join original bridge work. Waits and IPC occur outside canonical/lifecycle leases. Unaffected local pins must really drain; other remote pins each need their own P/D, not blanket forgiveness. |
| P+N established / reconciliation | Acquire the lifecycle exclusion under the new recovery-only lane; revalidate I/G and admission seal. Reconcile native and canonical debt in established lock order through the existing owners' finite plans. This access is restricted to recorded recovery, not ordinary operations or target dispatch. | P+N+D / terminal publication | Durably publish the per-operation retirement dispositions and corresponding stopped-run proof, with exact readback. | Bridge/coordinator crashes before terminal persistence | A4 custodian retains/reconciles original native scope. | Crash during any metadata/native write | Freeze exact prior plan and uncertainty; actual owner resolves known before/after/uncertain. Unknown extra stage, changed metadata, failed flush/readback or unavailable custody retains debt. Never relabel uncertain bytes as committed. |

| Timeout / cancellation / authority loss | Record the unresolved component and retain originals/owner evidence. Retry only original bounded reconciliation; a timeout is not a receipt, and unrelated uncertainty is never cleared. |

Native stop may be initiated without waiting for the unresolved pipe counter, but only after admission is closed and through its genuine original owner. It must not race unaccounted active canonical publication. The design orders participant exhaustion before the final recovery lease and debt reconciliation; platform stop can run concurrently only when the owner contract proves that its remaining process writers cannot invalidate those proofs. No filesystem lock is held across process/task waits. The exact lock graph and registration coverage require source review before this design is implementation-ready.

## 5. H2 / HC / H3 / HQ and player behavior

H2 still requires a fully qualified continuation, including DEP-C/I/L and all lawful target rows, before activation. The new contract is not permission to ship H2 while recovery is incomplete. For a future committed H2 whose close is lost, retain H2 and both original inventories. After real retirement, HC binds the exact owner receipt to H2 under same-G quiescent admission; no resurrection of the source active scope. H3 gets a fresh target-bound scope using that genuine admission, deletes only source K artifacts atomically with sourceReleased/sourceTransferred, and preserves current target headers/originals/provenance. H3's own failed close remains debt and blocks HQ. HQ removes only the matching browser slot with its acknowledgment; its own debt blocks dispatch. There is no infinite close-ack journal: durable semantic phase plus actual owner fence and retained disposition govern the next admission. Owner evidence needed by cold HC/H3/HQ cannot be evicted or deleted merely because M contains a phase flag; release occurs only after the genuine consumer proves it no longer needs that evidence.

Console and browser share the classifier and dispatch predicate. While held, display a Russian player-facing transition/recovery state (for example, “Переход после завершения жизни ещё не закончен. Продолжение временно недоступно.”), retain accepted text, block composer/new action and duplicate evaluation, and expose recovery retry only when it invokes the genuine owner. Reload/new client PID inspects owner state; it does not reconnect as the lost operation. Technical pin/run/debt details belong only in diagnostics. No “successful completion” is shown from request presence or M alone.

Source remains turn n/incarnation k with one exact death marker at Turn=-1, `[DEATH]`/`[VOLUNTARY_END]`, and H1 preserving k; retirement causes no Mortal tick, reroll, source reward, realm reversal or second life-end command. Automatic LifeEvaluation remains the genuine n+1 target with its own existing dice/gacha/progression/rewards. Physical G is unchanged throughout this same-root route.
