## 4. Chosen owner/API design (proposed, not implemented)

Use no new QTE runtime field and no separate history file. Extend the existing proposed preparation-only request control variant with one closed step kind `qte_pending_reminder_v1`. Production source eligibility remains actual ordinary GameEngine console/browser; LivePreparation/helper acceptance is not upgraded to ACTIVE.

Concrete separation:

1. In GameEngine retain the actual under-construction request/default observations and the already completed ordered reminder parts **before** invoking consume. A private `OwnedTurnPreparation` holds the actual engine/FS/root/main operation, G, source label, existing player intent/turn/browser binding, ordinal, and original backup owner. No public constructor, imported path dictionary, bool “accepted,” fake response, caller-generated G, or replay of Stage.
2. Share the existing typed load parser as a pure `ParseRuntimeForReminder(string? actualDecodedText)` and a private projection that captures the exact string and clears the typed field. The ordinary public method continues the same callbacks/write/error ordering. The source-aware adapter is a separate private entry on the **same QteSceneService**: proposed `ConsumePendingReminderForPreparationAsync(OwnedQteReminderStep step)`. It verifies service/FS identity and can be invoked only by that live preparation owner. This is not a publicly importable read delegate or a result DTO that grants admission.
3. Add a fixed-purpose internal FS entry, proposed `CaptureQteReminderRuntimeAsync(OwnedQteReminderStep step)`, which validates the live step's actual owner/FS binding and derives QteRuntimePath internally. It reuses a factored private public-read core returning the **final selected CanonicalFileReadSnapshot** plus decoded text; `ReadFileAsync` still returns only its text and preserves its current recovery, hook and conditional reread order. This is data transport to the private step, not a public snapshot-import issuer. Do not capture the first snapshot if the actual missing/pending branch selected a second read. The step captures fixed-path presence + exact bytes through the actual FS/read owner, including any real read/recovery/callback task debt; records the final actual decoding source. Do not replace the public read chain by an unreviewed scalar read. For the chosen bounded current-local contour, acquisition/recovery must already have a genuine owned disposition; inability to obtain that disposition is OPEN, not evidence-free retry.
4. Run BeforeRuntimeWrite only for nonempty result, in its existing pre-serialization position and **outside a newly held long canonical lease**. Do not move an arbitrary callback under a lease and create nested-write deadlock. Freeze actual serializer output after that callback. The live step is enrolled before its first read/callback/acquisition; completed task/result and outstanding native/release work are retained separately.
5. Acquire the actual publication lease through the same owner. Require same FS/root/G, live main/browser binding, exact current prior control, and exact captured runtime bytes/presence. Read generation through the existing owner; require preexisting G, never manufacture one to make this step usable. Do not reread/reparse to replace a drifted baseline.
6. Persist a **prepared** record containing all inputs/result/after-image, before runtime mutation. For nonempty consume, publish precisely two changes in one native member set: runtime captured-before → frozen-after; preparation control prepared → completed-with-next-cursor. For no-reminder, publish only the control transition and preserve the runtime file byte-for-byte; validate its source under the same lease immediately before publication. A runtime guard is not a redundant rewrite. Never append a receipt after Save returns.
7. Capture actual native Committed/RolledBack/Uncertain before facade/release. The native transaction GUID need not be embedded in the control (that would require a new preallocated native API); atomic co-publication of exact images is the relation. The stored control is a client-owned protocol record, not a claim that a self-hash proves origin.
8. Only after publication completion run the ordinary post-write callback, if present, then return the retained result. Mark publication, callback and task-return dispositions separately in the hot frame. Production null-hook case has no callback side-effect ambiguity. A crash after a nonnull effectful callback but before its acknowledgement is **not** solved by a serialized “callbackCompleted” bool: require that callback's real recovery owner, or leave that injected contour unqualified. No automatic callback replay and no disabling hooks to pass tests.

Proposed closed per-step data (all fields version-checked; fixed roles, not caller-selected paths):

Optional observed mtime/read metadata belongs the read observation; it neither grants freshness nor samples a new validation/action time. No step timestamp/GUID is needed. The outer preparation codec supplies its existing binding/version/purpose.

Its exact string can be stored in the completed control as redundant checked data or reconstructed from those slots. Persisting only the QTE string cannot recover lost earlier fragment results or the unassigned request draft. This is the precise remaining parent-input prerequisite.

## 5. Cold disposition and abort: what can and cannot be established

Cold parsing selects schema only; no preparation record can issue PendingTurnSnapshotReadAuthority/full admission/CommonAuthority. Authenticated original, when present, determines protocol obligations first (PH-D01); an incompatible preparation record is a conflict, never a downgrade. Missing original + genuine preparation kind permits only its specific preparation recovery protocol, not a successful original/admission.

After genuine storage admission/recovery under the correct G/owner:

- **Before prepared publication:** no QTE mutation has been armed by this protocol. Lost request/default/prefix observations are not recoverable from qte_runtime. R01P03 remains open; do not recreate them or call Stage again.
- **Prepared control committed, runtime publication not begun / rolled back:** runtime must match recorded before-image, control must match prepared image. Recompute only the pure parser/serializer/string relation to verify the stored result; it executes no source callbacks, clock, IDs or mechanics. A genuine continuation owner may publish the retained already prepared pair. No second consume call. Whether a new cold browser owner may continue remains R03 OPEN.
- **Native pending decision:** original native owner restores the complete pair to before-images. Its uncertainty is not classified as “unissued, safe to retry” until actual recovery completes.
- **Native committed decision or cleaned completed control:** independently check fixed recipe, same G/source/parent ordinal, exact raw input→typed result→serialized after-image relation, prefix composition and actual current after-image. If a later owned step legitimately changed runtime, require that exact later transition chain; arbitrary current difference is not accepted. Empty current reminder alone proves nothing about whether this action consumed it.
- **Committed pair, return lost:** resume from retained exact result/cursor. Do not reread pending reminder as a replacement result. Native cleanup/release debt remains separately owned and must settle before retirement/seal.
- **Malformed/foreign/missing/mixed control:** preserve conflict/evidence. An old unversioned runtime without a reminder cannot be upgraded into a completed new step.

Current caller failures matter: **TL1668–1737** lets SessionReplaced and publication uncertainty escape. Ordinary browser staging failure retains original evidence and exits in-game mode; it does not prove rollback. Console ordinary failure attempts request deletion, RestorePreTurnBackup, Explorer restoration, backup cleanup and pending-snapshot cleanup; some nonuncertainty cleanup errors are logged and the original failure is rethrown. These attempts are not a single atomic abort certificate.

**SS1900–1944,2366–2410** include qte_runtime in rollback-tracked game_state but exclude validation_repair_request. Therefore a console restore can put the summary back while a proposed completed preparation control remains. A later generic success/stale cleanup can instead delete the proposed control while leaving consumed runtime. Both are real split-state hazards.

A lawful **unissued abort** for this step must be derived from the *actual* parent rollback owner: restore the QTE original pre-turn baseline image (not automatically the step's later before-image), and atomically advance/retire the matching preparation step under exact source guards in the relevant parent restore plan. Preserve player intent and the parent's other committed/retained-owner consequences. Requeueing the summary is rollback of message consumption, not rerunning the prior QTE scene/rewards. If parent rollback policy cannot supply that exact disposition, this step does not invent one. After original issue, no preparation-only abort is allowed. Whole abort R01P01–03/R03 remains OPEN; permanent HOLD is not declared lawful full recovery.
