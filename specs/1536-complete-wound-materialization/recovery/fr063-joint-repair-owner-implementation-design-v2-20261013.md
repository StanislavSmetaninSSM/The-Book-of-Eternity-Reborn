## 2. Closed first contour and admission

The first supported contour is exactly one already-issued, fully confirmed guaranteed request for an existing current-player physical wound; one real QTE physical occurrence from source turn N, offered by the official original N+1; and one real severity correction packet. The complete scene already belongs to the sealed treatment command. The first fixture/example uses an initial `materialize` draft at severity III against the real maximum II and corrects its packet-authorized severity to II. Production accepts any severity that the real adapter validates within the actual sealed packet/opportunity range (I or II in this fixture); II is not a production-only admission value. Retain decision kind, opportunity, woundRef, all unaffected proposal fields and the entire scene. The new wound and treated wound must be distinct. The current genuine pending component supplies a faithful source/held-request construction, including a real quantity-2 energy claim; that fixture quantity is not a new product rule.

Exclude multiple requests/opportunities/packets, narration correction, `none` substitution, treatment of the newly acquired wound, item mutations, courses, procedures, diagnosis, raw resource/effect commands, new skill/party/owner commands, and unrelated repair waves. Existing canonical periodic effects still run through the single effect schedule; they cannot be silently skipped. Acquisition-owned wound effects and treatment-owned rematerialization remain supported within that schedule. A candidate outside this closed contour must retain its current refusal, not receive a general mixed-family fallback.

Normal entrance is a new typed callback immediately before the current homogeneous-treatment branch at `ResourceMaterialization.cs:503`, after the existing ordinary upstream, official original and resource continuity checks. It uses that actual participating write lease and validated original context. Keep the old callback/signature available unchanged for every old caller; add the joint callback as an explicit optional/default-null integration parameter, not an ambient flag. The actual GameEngine caller supplies it; external/unaware callers retain their current behavior. Before the joint callback can return a plan, run the current treatment branch's effect continuity, skill/source-owner validation and unrelated registered-outcome exclusions as shared pure checks. Its ordinary mechanical-envelope counterpart permits only the separately proved acquisition draft and exact owned private wave; all remaining `TreatmentOrdinaryGuardPaths` comparisons stay strict. An admitted plan must pass a dedicated retained-joint-plan check and short-circuit the generic wound/effect path once, just as the old treatment branch does; it must not be passed through the old singleton retained-treatment validator or reduced again below `stageMortalQteDecision`.

Admission has three closed outcomes: `NotApplicable` (continue unchanged old branches), `Rejected` (return real issues; never fall through), and `Owned` (a private phase-specific result). Simultaneous treatment/decision presence only identifies a candidate requiring inspection; it does not authorize ownership. A candidate with a malformed joint checkpoint, changed source or incomplete request is `Rejected`, not `NotApplicable`. A valid acquisition without an admitted prior severity-repair checkpoint is outside this first extension and remains refused.

For initial capture and every correction, prove all of the following under the current lease:

1. Read the actual official original N+1 and current physical G; require Mortal/player, exact session/request/snapshot/turn, unchanged signed before-images and current root admission. The accepted-event vectors for the QTE source and the treatment binding are separately validated against their owners. They need not be equal and must not be concatenated or re-signed into a fabricated common event set.
2. Strictly parse and recompose the physical homogeneous treatment command; require one treatment, no opportunity/accepted-transition commands, unchanged final scene. Parse command/pending/history through `MortalWoundTreatmentPersistedRequestCatalog`; exact duplicate copies coalesce, conflicting graphs refuse. Fresh `ExportCurrent`/`RestorePersistedTreatmentRequests` re-establishes the same request/agreement from existing durable authority on lease/process turnover. No `PrepareGuaranteedRequest`, reserve, new attempt, or replacement request is called by repair.
3. Re-run `CreateGuaranteedAttempt` from that exact request, real accepted wound/history and fresh accepted state, then `MortalWoundTreatmentResourceComposer.Finalize`; validate the actual ConfirmedHeld agreement and exact operation/attempt/request/resource/finalization identities. Diagnostic `InspectConfirmed…` may witness this state but is never the authorizing input. Existing private reservation/continuation checks remain the authorizing owner.
4. The genuine QTE adapter reads the current public draft and scene against the actual original occurrence partition. Initial capture requires the real actionable `wound_severity_above_opportunity` issue and one matching `WoundRepairPacketBuilder.Build` packet. A private/client-root error, malformed occurrence, wrong source, invalid treatment or mere manufactured packet cannot be delegated to GM repair.

## 4. Durable repair checkpoint, restore and correction

Extend the existing private pending root with one optional closed property, `jointRepairCheckpoint`. Existing `repairPackets`, `repairReceipts` and `submittedTreatmentRequests` remain as emitted by `ComposePendingRoot`. The latter is the complete request graph, not a fingerprint-only substitute. Current portable format 4 is local lifecycle integrity, not protection against a same-user owner rewriting data (`PendingTurnSnapshotAuthority.cs:967–987`). No stronger security claim or new key is needed. A new-root admission rejection is a real unqualified dependency; never repair it by editing root/source seals or manufacturing a new turn/request. Same-root child and new-root child are distinct evidence responsibilities.

At each child boundary record actual PID/root/G, original quartet and authority hashes, complete request and reservation IDs, pending/checkpoint packet identity, registry reconstruction outcome, resource finalization and claim state. Fresh process must reconstruct the real source-bound obligation before any corrected contribution is accepted. Exact-copy coalescing and changed-copy rejection remain mandatory. Full FR063 stays open until these owner-level cold and failure responsibilities are actually evidenced.
