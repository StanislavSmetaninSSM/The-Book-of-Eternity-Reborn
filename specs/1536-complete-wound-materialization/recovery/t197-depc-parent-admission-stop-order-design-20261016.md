## Two barriers prevent a nested-task deadlock

The first barrier is **StorageQuiescent**, not ParentCompleted. A nested child's Task may be legitimately waiting for stopping metadata before its read-only finalization; requiring that Task to complete before metadata would recreate a cycle even after O/I accounting is corrected.

Proposed registered invocation states: Running; BodyExitedAwaitingJoin; ParkedOnOriginalChild; StorageQuiescentAwaitingMetadata; Finalizing; CompletedObserved; HeldUnresolved. ParkedOnOriginalChild is issued by an explicit `AwaitOriginalChildAsync(childSlot)` at the actual nested await, with exact parent/child references and a promise that no local semantic continuation executes before the typed child result is processed. It is not inferred from Task.Status or a stack snapshot. A synchronous prefix still running or an uninterruptible input read does not qualify. Returned held values propagate before any next semantic action, prompt or cleanup.

First barrier for the sealed run wave W:

* Every admitted producer and pending factory/acquisition is registered; no new semantic or publication arm is allowed. Pending starts resolve as never-entered or actual joined/parked invocations with all prefix effects inventoried.
* Every invocation is BodyExitedAwaitingJoin or demonstrably ParkedOnOriginalChild / StorageQuiescentAwaitingMetadata. Each owns **zero active or pending storage/lifecycle/native-publication locks**, after actual debt settlement and actual lease disposal. Its O/I owning frames and P remain alive.
* All already-armed attempts are terminal with exact cleanup outcomes; no unresolved/committed-cleanup debt is hidden by facade return. All direct storage-producing callbacks are joined or are parked without a storage lock and with no permission for new effects. Original native writers required for these debts are stopped by genuine original proof; auxiliary status/prompt writers are included as separate producer slots.
* Exact observed MainAccess membership contains only registered live owning frames; every non-owning borrow is disposed. The wave has no unowned physical lease/acquisition. A caller-owned lease is a real storage blocker, even if its admission is an ancestor of the proposed local sibling.

Then the metadata publisher may acquire the canonical lock, publish/ACK Stopping and release its own M lease. Only afterward does the wave signal `StoppingAcknowledged` to original invocations. Child invocations finalize bottom-up and their actual Tasks complete; parents join those actual Tasks, then finalize their own binding if they own it. The final barrier is **InvocationAndBindingCompleted**: all actual children/callbacks/read operations observed, finalization successful, all invocation O/I released, original wrapper returns and P finally disposes. No first-barrier receipt certifies this second barrier or retires main.

For nested same-G binding, existing RunBoundBody:205–223 inherits B rather than creating/closing one. Its new local held route must not call ordinary VerifyCurrentSessionOperationAsync after seal (current RunWithinBinding:385–388 can do so). It preserves the actual typed held decision and delegates the mandatory final generation check to B's original closing owner. This is a private original-bound protocol change, not use of a raw blocked-readmission flag to omit verification. If the nested child needs a standalone closing check, perform its original read-only finalization only after ACK under the existing binding, then return. The root must not claim settlement until B's final check succeeds.

Caller-owned write-lease branch (:250–254) requires explicit integration in its real enclosing owner: settle its exact attempt while that lease is live, perform any required same-lease G verification, dispose the lease and observe the disposal, publish StorageQuiescent, await ACK, then perform the mandatory read-only current-G closing check before B closes. Calling the current caller-owned branch unchanged would close B early or wait for metadata while still holding its lease. No lease is transferred after disposal or recreated from metadata. An existing outer MainMenu/Explorer operation not using this owner protocol remains unqualified; ProcessPlayerTurn cannot retrofit it after effects.

**Exact inherited-lease nested cut:** a child using its original ancestor's caller-owned canonical lease cannot wait for metadata while that ancestor awaits the child. Use a separate private result `HeldUnwoundToOwningBinding(actualBindingOwner, actualChildSlot)`, not `SealedSettled`. After native-only stop and settlement of all of that child's own armed attempts/callbacks/borrows, the new local nested route performs any required same-lease G check through its original read-only debt verification, excludes ordinary post-operation reacquisition, releases only its own O2/I2, and returns this typed control result **before metadata**. The child's real Task is now observed completed, but its inherited B, ancestor lease, O/I and original P remain with the real owner. The owner receives that result before any semantic continuation, settles its remaining exact attempt, disposes its own lease, then reaches StorageQuiescent. It alone awaits metadata and performs the mandatory read-only binding finalization/current-G check. This is control unwind, not a child receipt certifying B/parent/HC completion or a release of borrowed ancestor resources.

This early-unwind variant is permitted only for an actual inherited same-G B and its registered owner, never a separately owned binding, unknown outer wrapper, or arbitrary copied lease. Every level in a nested chain must propagate the control result until that actual owner is reached. If a child owns an independent finalization obligation, it must first become storage-quiescent and await ACK through the ordinary two-barrier variant; an ancestor cannot retain storage while waiting for that child. Such a call graph requires restructuring at the real original owner before admission and remains a blocker until specified. The read-only finalization requirement is deferred to the actual owning B, not waived. Existing `RunWithinBindingAsync` cannot be used unchanged for this typed early unwind because its ordinary post-operation verification may reacquire storage at:388.

## Private settlement before stopping ACK: exact authority and prohibitions

The corrected ordering requires a deliberately new **private original-debt interface valid before stopping metadata ACK**. This is not supplied by today's ordinary leases and is not accepted implementation authority merely because it is named here.

Proposed `OriginalStopWave` captures the actual original coordinator/terminal/root identity, current acknowledged run/G/fence, registered invocation/frame set and already-armed attempts. It is issued only by that live owner for an acknowledged active run with no pre-existing unresolved authority/metadata condition. If another stop wave already exists, reuse that original object; unexpected state or existing uncertainty is not normalized to Running. It is not created by a source action tuple, caller DTO or deserialization. No worker or external native writer can be attached retrospectively on a path/PID guess.

`SettleOriginalArmedAttemptAsync(wave, originalAttempt, originalLease)` is called by the original trusted-local publisher's retained continuation, before its owned lease disposes. It validates: actual object lineage and registered slot; actual still-active canonical lease/physical authority; exact original current G; exact acknowledged metadata bytes unchanged or an explicitly retained original metadata decision (not assumed ACK); original keeper/main guard alive; native stop receipt from this original terminal plus any separately required original writer receipts; no AuthorityLost or independent uncertainty; exact transaction ID, prepared member before/after images, scratch paths, namespace effects and already-entered phase. The wave's own planned admission seal is not uncertainty and does not itself grant anything. An unexpected metadata/G/namespace change fails closed.

The native method validates this private capability directly for **only its recorded attempt's remaining commit/rollback/cleanup steps**. It must not call the ordinary public source facade, new TryCommitWithOwnedLeaseAsync, generalized recovery, a recomputation/normalizer, or BeginStop/metadata as a prerequisite. In particular CoordinatedStateWriteHelper:73–99 may already hold CommitGate plus canonical lease; reentering its owned-lease helper to settle would self-deadlock. Continue the original publisher/attempt in its original owning context; no second canonical or CommitGate acquisition. PendingLocalDecision, worker root pins, namespace preparation and recovery ownership must remain associated with their actual originals, not cleared by a generic finally or capability boolean.

If an attempt did not retain its actual lease/owner, this report does not authorize manufacturing them. A separate exact reacquisition adapter would need its own issuer/debt/lock proof and is OPEN; the bounded schedule here uses retained original ownership. Facade success-with-cleanup-debt must be intercepted before its lease release, rather than learned later from a journal hash. Unknown pre-existing recovery cannot be laundered into this invocation.

Ordinary admission remains unchanged. `ValidateAccessAcquisition`:137 rejects `_closed` for ordinary acquisition. **Existing already-held lease validation does not simply reject `_closed`: coordinator ValidateAccess:151–157 also depends on metadata, uncertainty, workers and root exit.** Therefore the source's semantic effect/arm gate remains essential from the first seal; setting `_closed` alone does not freeze all current writers. After intentional native exit the ordinary guard refuses that root; the private debt path is a narrow separate authority, never a global relaxation of that guard. It cannot issue new after-images, a new transaction/retry, G/M/target writes, rewards, dice, source replay, lifecycle cleanup or a story/HC/parent semantic receipt. Current SessionFinalization remains read-only and MainMetadata remains metadata-only.

Native committed data remains committed. Uncommitted rollback is the original transaction's before-image settlement, distinct from RestorePreTurnBackup. Committed cleanup failures, disposal failures, partial native termination or mutation collisions retain debt and prevent the first barrier. `CanonicalWriteLease.DisposeAsync`:330–367 nulls fields before asynchronous resource disposal and marks main unresolved on failure. **IsActive=false is not successful release.** Store and await the actual DisposeAsync outcome; require successful release of its stream, directory authority, external context, main admission, worker pin and ambient registration. `ReleaseOwnedLeaseAsync`:103–121 can attach/suppress secondary failures; the custody adapter must retain their actual outcome independently, not infer zero debt from its caller's return. Do not clear a resulting NotifyUncertain.

## Pending acquisitions and auxiliary producers are first-class obligations

No empty currently-held-lease list proves quiescence. `AcquireCanonicalWriteLeaseWithAmbientAsync`:3764–3771 creates a MainAdmission and ambient registration before the awaited physical acquisition. :3782–3795 can be pending or fail after retaining main access. Every such invocation is pre-registered as `AcquisitionPromised → Invoking → Acquired(lease)` or `FailedAndDisposed(actual failure)`. Its native open, retry-delay/hook work, activated ambient registration and final cleanup are part of that same slot. Seal cancels only an existing explicitly cancelable operation; until the actual call exits and cleanup is observed it remains pending. A noncancelable old call must genuinely return; a timeout isn't release. No late acquire may start recovery or return an ordinary mutating lease after seal: its new original-owned wrapper checks the same seal before activation/recovery and releases the exact resources. This is an OPEN integration seam in FileSystemManager:3782–3903, not behavior current code already guarantees.

The run wave inventories **every owned async producer**, not only children of ProcessPlayerTurn. Actual BridgeHost.StatusPublication:66–71 creates its own RunOperation pin and writes `game_state/control/gm_bridge_status.json`. Queued status not invoked is discarded by the existing seal prefix; in-flight status has a real pin/body/lease/native debt. Register that auxiliary producer before RunOperation's prefix, keep its actual original owner, and include its storage acquisition/attempt/disposal in StorageQuiescent. It is not a member of the selected parent O/I exemption set and it cannot be assumed finished because `_statusSealed` is true. Existing root-exit/admission-refusal catch:79–84 is not a positive cleanup receipt if a newly introduced retained attempt exists. Its actual attempt adapter must settle first. Global `_pins` sees both operations until both genuinely release.

Input cancellation: RevokeInputLifetime:783–792 itself only changes in-memory state and starts CancelAsync, with no canonical/lifecycle request in that method. Cancellation callbacks are separate invoked work, may run later, and are **not transitively proved storage-free** by that fact. The same applies to prompt-task completion: Program:795–806 calls WriteStatusFile; new status queuing after seal is rejected, an earlier admitted status attempt still settles under its own owner.

Native stop's examined direct control/Job paths have no game canonical/lifecycle acquisition, but native output processing is not automatically independent of presentation: current PumpOutputAsync:1145–1146 awaits consoleWriter.Write/Flush before continuing read. The Client-host proposal must retain a genuinely independent original native drain and isolate detachable viewer backpressure; otherwise Windows close/output EOF or Linux output settlement may remain blocked. This remains an exact hosting/I/O dependency, not solved by changing the stop call order. Keep native EOF/close, input writes, resize, prompt, status and authority/root-observer Tasks in their actual original inventories. Only the native process-scope stop receipt is the early gate; full I/O settlement and disposal are still required before main retirement.

No nested child is allowed to await stopping metadata, parent completion, or any storage-dependent stop wrapper **while holding or waiting for storage**. Such a child must first finish its acquisition/attempt and release storage, or remain visibly unqualified. It may await only the original native-only stop signal or its own bounded native attempt I/O while holding its original lease, provided that dependency has no reverse edge to canonical/lifecycle/CommitGate/metadata. A callback whose dependency graph is unknown blocks release; no Task.Status/empty list/boolean proves otherwise.
