## Linearization, effect registration and closed in-memory state

Proposed original objects: `OriginalParentInvocation` → private `InvocationSlot[]` / `BorrowSlot[]` / `NativeArmSlot[]` / `PublicationDebt[]` / `IoSlot[]`. Each slot is bound by reference to its creating owner, root identity, run and existing G; IDs only describe those objects. State mutations occur under one short owner gate. No serializer/factory can issue them from JSON, a hash, process ID, action tuple or current/new G.

Closed parent states: `Reserved → Invoking → Active → Sealing → Joining → Settled → BindingClosed → PinReleased`. `InvocationFault` is an observed result within the invoking/active chain, not a shortcut around joins. Any unresolved task/native/publication/authority condition enters retained `HeldUnresolved` from Sealing/Joining; it cannot advance on time, EOF or a later process. Normal active completion uses the same join barrier and pin release. Root-lane ownership persists until final source release; the run-level admission seal remains closed afterward until a separately authorized continuation.

Slot states: `Promised → Invoking → Bound(Task) → Observed`; seal-before-invoke permits `Promised → NeverInvoked` only with an atomic proof that the factory has not entered. A synchronous throw records `ObservedFault` only after the prefix has returned and its armed child/debt slots are retained. `NeverInvoked` is not a universal no-change witness. Borrow states are `Registered → RetainedActualAccess → Released`, with retain failure recorded and balanced once. A delayed callback first validates its slot; a late callback cannot create fresh work after seal.

An effect has two distinct steps: enrollment before invocation, then **arm its exact attempt before effects**. Under the short gate, `ArmExactEffect` validates open semantic admission and an immutable already-calculated plan, installs the attempt and marks it armed. Seal and arm share this gate. No filesystem/native/user callback is run under that gate. If arm wins, only that exact bounded attempt can finish/settle after seal; the registration is not a license for future semantic computation, retry, successor transaction or additional paths. If seal wins, no effect starts. An already-entered pure synchronous calculation may finish into retained local data but may not generate a new effect after seal; no replay/redraw is performed. In-memory semantic mutations (turn increment, response/notifications, consuming explorer snapshot) require their own pre-effect gate and retained once-result. Effects completed before seal stay completed; source arrest does not undo them.

A bounded attempt may have multiple syscall steps after arm; these are continuation of its declared attempt, not newly authorized gameplay. For publication, post-seal continuation follows the native owner's exact committed/rollback rules below. For native launch, arm includes original scope/identity and held release state before process effects; release itself races seal under the gate. If seal wins before release, stop/join the held child using the original owner without releasing it. If release wins, retain all started work and stop/join its actual scope. A queued factory cannot be treated as safely unstarted once its prefix has entered. `exec_pending`, original process creation, thread and callback execution count until actual observation, not until the caller drops its reference.

Diagnostic closed metadata proposal (B03 codec/CAS is still OPEN): version; original run/operation IDs; exact existing G/root descriptor; parent/child relationship; registration sequence; seal sequence/reason enum; invocation state; per-slot kind/state; exact already-armed plan member names/byte digests and original transaction ID; actual dispositions; receipt references/digests; unresolved reasons. Forbidden: arbitrary callback/type names, authority booleans, serialized Access/lease/Task/native handles, PID-as-proof, caller-supplied target paths, a replayable action factory. This metadata is inventory/recovery diagnosis only. Fresh deserialization has no capability and cannot issue settlement or same-G retirement.
