# T197 Stage pending-fate original frame — application design

Frozen source `ec50e4cd6c6e17ab651711eaf0c9cbc957dd8842`; comparison `f3bef7097660b12317842903f0849af43b29c06c`. Configured Astra/High; backend telemetry UNKNOWN.

**Proposed conditional hot-only contract. Not independently accepted; no engineering/activation/F2 release.**

## Ruling and chosen boundary

The application contract can be specified now as a **conditional hot-retention subcontract**. It closes the intended behavior of the D01–D04 adapter at explicit RNG, clock, file-publication and original-parent interfaces. It does not prove those interfaces implemented/qualified, does not close H-B02, and does not authorize engineering release. This is a new proposal for independent review; acceptance of the prior PARTIAL inventory is not acceptance of this adapter.

Choose a live, single-consumer PendingFateOriginalFrame inside the original surviving Client custodian, born before Attach invokes any service code. No new journal/schema/service is added for entropy. Preserve successful original draws and exact object/bytes in memory; first potential persisted representation remains the existing publication journal/member. Before that representation, custodian death loses unpersisted entropy: this adapter has NO recovery claim. It cannot infer a value from RNG state, a hash, an empty file, a timeout, another host or a new process. Cold/full keeper-loss protocol remains a blocker for full G-C/T197; this finite hot prerequisite need not pretend to solve it.

The same presentation-loss event remains the goal. Qualified original Client/custodian survival is mandatory. Stopping the native GM scope must not terminate the custody thread executing RNG or the original FS graph. A design with permanent held state would not satisfy the ordinary outcome; source continuation is a separately identified owner contract below, not assumed from retained data.

## Alternatives and recommendation

A. Recommended: per-slot hot frame, no new persistent format. The chosen contract preserves original entropy and makes seal races finite, with an explicit cold limit. B. Treat GenerateSecureRandomDice(20+4) as one armed black-box call: rejected for this slice because a seal after its first Fill would still initiate later unarmed draws; one composite enrollment is insufficient. C. Persist every returned slot before the next: not chosen. It adds a domain-sensitive new durable owner/schema, write/cold-recovery and secret-value handling contracts, still cannot reconstruct entropy from a Fill that never returned, and would broaden this task. It is an alternative for future full-cold requirements, not an implicitly accepted grant.

## Live authority and construction

The new frame is internal with a private constructor. Only a new PendingTurnStateService.BeginOriginalStageFate(StagePreparationFrame parent, TurnRequest originalRequest) factory, invoked by AttachPendingDiceAndGachaAsync at4534 BEFORE the old GetOrCreate call, may create it. It receives references from the proposed born-owner host: the original GameEngine/PendingTurnStateService/FS graph, exact CanonicalRootAuthorityIdentity object, original coordinator Access with nonmetadata actual OperationPin, the actual outer+inner admission frame identities, original bound SessionOperationContext/G, parent source-gate/epoch, and the same existing request/action/session/turn identity. Factory comparison is object identity and genuine owner validation, not string equality. A new private frame ordinal is bookkeeping, not a domain action/request ID or new root pin. No metadata deserializer, browser DTO, pending JSON or generation string calls this factory.

Factory requires a registered parent Stage task, a single outstanding fate-attach invocation for that request, the ordinary trusted-local source family, current G and same physical root authority. It borrows the retained parent and never reacquires an exclusive main lane or creates a root coordinator. Current source exposes no complete gate/frame-issuance API: this is prerequisite PF-P01, not a claim that reading AsyncLocal supplies custody. If an invocation is browser/recorder/legacy recovery rather than this ordinary family, this adapter refuses before RNG and leaves that existing owner on its separately designed path; it must not silently divert the requested user outcome to another mode.

## Frame fields and closed diagnostic shape

Private live fields: OriginalParent and Stage references; original FS/service/request references; actual coordinator Access/pin and admission handles; currentG binding; root identity; parent epoch; phase; nextVisible in0..20 and nextHidden in0..4; visible[20], hidden[4], twenty-four nonreusable slot records; one read-result record with Exists/ExactBytes/DecodedText/selected parsed object; original freshness decision; exact fresh creation clock and write clock; computed gacha; actual PendingTurnState object; retained serialized desired bytes; native operation/attempt handle; original TrustedLocalPublicationOutcome; actual canonical acquisition task/lease/release task; callback and cleanup/debt handles; attached flag; held/fault details. Arrays/buffers are exclusively frame-owned until attachment. No public mutator/serialization authority and no concurrent Advance.

Slot state is Unissued→Armed→ReturnedRetained OR Faulted; Armed never jumps to Unissued. ReturnedRetained stores the decoded value and actual raw buffer under the frame lock before source registration completes. On Fill failure, record Faulted and the actual exception; partially changed scratch is NOT a valid draw. There is no retry of that RNG slot under this contract, even if a provider may have consumed entropy before throwing.

Optional diagnostic metadata has a CLOSED versioned shape: {kind:"pending_fate_original_hot_v1", rootOperationId, childOrdinal, generation, sourcePath:"game_state/control/pending_dice_state.json", phase, visibleReturned:0..20, hiddenReturned:0..4, readDisposition:Absent|Present|ReadFailed, desiredDigest:null|sha256, publicationDisposition:NotStarted|InFlight|Committed|RolledBack|Uncertain, held:boolean, faultCode:null|closedCode}. It contains no hidden draws, untrusted callbacks or importable handles, and grants no authority. Unknown fields/version/enum fail diagnostic decoding, not gameplay recovery. No diagnostic file write is authorized by this design; host metadata format/persistence is PF-P01/PF-P06.

## Per-effect enrollment and lock order

Use the original parent source mutex as the single linearization gate; frame state is guarded in the fixed order parent-gate→frame-state. No I/O, callback, RNG Fill, clock provider, logger, storage lock acquisition or await executes under either mutex. TryArm checks original parent epoch/Open, actual frame ownership and expected phase, then installs a finite registration before returning. Seal takes the same parent gate and sets Sealed; it neither cancels an armed Fill nor grants another slot. Completion may acquire the two mutexes to store the original result even after seal, then release the registration exactly once.

Each Fill is separately enrolled. The current entire loop is NOT one permitted composite. If seal wins before slot arm, no call occurs; if arm wins, exactly that Fill may return and its arithmetic/retention complete. Next slot's TryArm must fail. A thread still inside Fill remains counted until real return/failure; timeout/cancellation/absence of output proves no return. No Task.Run fire-and-forget, thread abort, async-void callback or continuation detached from original parent.

Clock reads that create stored CreatedAtUtc/LastUpdatedUtc each have one retained slot; no second clock read while resuming the same prepared phase. Private constructor clocks discarded by later assignment and storage transaction GUIDs are technical allocations, separately accounted by their enclosing original task/attempt. They are not a grant to create domain entropy, another TurnRequest/session/action ID or another pool. The adapter calls no Guid.NewGuid for gameplay and never constructs a replacement GameLoop/TurnRequest.

Storage acquisition is registered before its await. A seal while waiting prevents new write initiation; an actually acquired lease is released under the original release owner and recorded only after release completes. Merely completing a Task or an empty held-lease collection is insufficient. After native write arm, retain C through the original single-attempt decision/cleanup settlement as defined by PF-P03, then release all storage before main-stop metadata takes C. No child waits for parent/metadata while owning or waiting for storage. Native-only stop never requests canonical/lifecycle admission. O/I admission frames remain live owners during before-close joins, excluded only by exact frame identity from child counts. Final read-only disposal may not reopen reads, recovery or storage.

## Fresh result and valid reuse rules

Existing valid state: select exact final read bytes, parse once using existing SharedJsonOptions and exact IsValid predicate; retain that very returned PendingTurnState object and its visible/Gacha references. Keep lock fields/timestamps unchanged, including values established by earlier Reveal/Rewrite. No application write, no RNG and no rotation. Exact bytes remain an input witness; do not reserialize to replace them. Constructor defaults executed by normal deserialization can read technical clocks; existing supplied JSON fields still win. Preserve existing permissive validity and null-array exception behavior here: schema tightening is a different change.

Fresh state: an absent/invalid-data branch is selected once from that original read. Run the creation clock slot, visible slots0..19, hidden0..3, then the existing pure gacha calculation; construct exactly one state with IsFateLocked=false, original creation time, no FateLockedAtUtc; later capture one write clock and serialize once with existing options/UTF8-preamble encoding. Each phase can hold its already-derived objects without starting any later phase after seal. The only materialized member is pending_dice_state.json. Hidden[4] stays private; existing payload publishes BaseScore/BaseRarity/Formula with DiceUsed empty, not hidden rolls. No current-turn increment, reward, fee, domain ID, Rewrite or Reveal action is implied.

If another owner changes the input between read and native write, the exact-before guard must reject without overwriting, redrawing or adopting the new file as the original decision. Reuse also needs the parent same-action/path exclusion to avoid aliasing a concurrently mutable state. All legitimate pending-file writers and raw replacement/load paths must participate in that exclusion or be rejected by existing current-G/root/lease checks. This is PF-P04, not a claim that PendingTurnStateService currently has such a lock. Holding a new canonical lease across all24 Fill calls is not chosen: it would change the current read/draw/write lock behavior and worsen stop coupling.

## Publication, debts and successful local outcome

Retained exact desired bytes are data until a real live source write permit is issued. Source admission is not native admission: registering an acquisition, opening a lease or reaching a callback before the native effect does not authorize starting publication after seal. Split the original wrapper at explicit boundaries so directory preparation, before/after-mutation callbacks, native attempt and release each have genuine registrations. If seal occurs before the native attempt, do not enter PublishWithOutcome; settle only already-started preparation/I/O and release. A whole-wrapper registration is not a grant to issue later writes.

If native publication is already armed, the original publisher/lease/attempt performs only the bounded decision/cleanup for that exact change. Committed→retain actual result, then track journal/scratch/namespace cleanup and lease release separately. Committed+Failure is not wholly settled. RolledBack→retain that native decision and its original failure; any cleanup remains tracked; never re-run CreateFreshState. Uncertain→retain all evidence and block this local success. Do not start another native retry after seal. If normal open-source retry is required by existing transient policy, it must acquire a fresh native-attempt registration while reusing the same prepared bytes/baseline and recorded earlier attempt; no additional RNG/clock. At seal, retry timer joins/cancels as an owned timer without a new attempt. Exactly-once settlement applies to each actual native attempt, not a path-counter approximation.

After Committed plus complete local storage/release join and while source still Open, AttachOriginalFateOnce assigns the original visible/Gacha references to the SAME request. It checks request identity/reference and frame not already attached; it does not invoke GetOrCreate. If seal wins just before attachment, assignment is deferred with the retained values; this is not permission to run preview/snapshot or later Stage. A successful local outcome is Ready(state, originalRead, originalPublication-or-Reuse, localJoinEvidence), not a main-stop/HC receipt. Attached once has no dice write and cannot retire the parent.

## Held/fault propagation and continuation

AdvanceOriginalStageFateAsync returns the private discriminated outcome Ready / HeldAtCut / Faulted. Held contains a reference to the original live frame, cut and actual debt state; it is not null and is not an Exception. Stage must branch immediately at1596 and leave through the separately proposed typed parent-held route BEFORE entering ordinary error cleanup or any next helper. Existing Stage1672 broad catch must never see a manufactured held exception; if an actual ordinary fault occurs, preserve it as Faulted and follow the existing real error policy only when it remains authorized by the parent. A simultaneous seal may retain that actual fault for later owner disposition, but cannot relabel it cancellation or success. Deserializer's broad catch remains a malformed-input policy; gate/control operations execute outside it and an actual read failure does not become missing input.

A Held frame has two independent facts: application progress saved and owned running work/debt joined or not. It may be retained with no unfinished borrows; it cannot complete remaining slots merely to empty a task count. Original supervisor EOF latches uncertainty. Main exit still requires stopping + actual native empty + !exec_pending and the complete original-operation/debt conjunction; this slice supplies none of the missing whole-parent receipt.

Continuation is NOT automatic unsealing. A proposed ResumeOriginalStageFate(frame, OriginalStageContinuationPermit) may advance ONLY the same retained object at its next unissued phase, original sameG/root/request/action/turn and remaining draw budget. The permit must be issued by the lawful existing source-continuation owner after the original stop/storage/metadata handoff, mutually exclusively with prior executor, using the live retained parent reference and validated exact baseline. It cannot be created from the diagnostic record or fresh coordinator, and cannot be exercised on the sealed old admission. PF-P05 must specify that issuer and actual new/retained admission lifetime within the parent protocol. This report defines the consumer refusal/remaining-budget contract, not an accepted issuer. Until PF-P05 is closed there is no demonstrated successful same-situation resumption; a forever-held frame is a blocker, not an acceptable gameplay resolution.

## Recoverability limit and durability cuts

Before the first successful Fill: hot frame can preserve the selected read/branch; a cold process still cannot prove the original operation and outstanding read/recovery stopped. After any successful Fill but before persisted after-image evidence: only live frame memory preserves that value. Keeper death destroys the value for this contract; never regenerate and call it the original draw. Fill fault has no valid returned value even if scratch changed; the finite failure result cannot resume by trying that slot again.

After original journal intent staging, complete desired bytes may exist in the trusted local journal; they contain visible20 and derived gacha, not hidden raw4. Their existence is not a committed decision, power-loss durability qualification, source continuation permit or proof remote work stopped. After native Committed, existing pending file can be data for an ordinarily admitted future read, but that does not retroactively restore this lost original parent. Custodian surviving with retained native owner can use only its actual settlement interface; keeper loss/cold restart/reboot/container-host migration/distinct-root restore need their original lifecycle/lineage issuer, still OPEN. No backup-format or archive grant follows.

The conditional hot-only application safety proof is sound independently of solving cold entropy recovery: its precondition explicitly requires the original process, frames and native/IO owners to survive. Engineering and user-visible successful bridge-loss recovery remain blocked until those preconditions and continuation are actually qualified. This is an engineering dependency boundary, not a permanent refusal or a narrowed substitute for the requested eventual outcome.
