## 2. Proposed bounded intake and actual takeover

Proposed private `IncarnationSuccessorOwner.AcceptEvaluationAsync` consumes a live, owner-issued `AcceptedEvaluationContinuation` after E4C, together with the actual parsed accepted trigger and exact original/current eligibility inputs. It may issue `IncarnationSuccessorAccepted` only if the compiled finite owner catalog below is complete and qualified, including choices, bootstrap acceptance, cleanup and cold recovery. `SupportsAll=true`, a list of future TODOs or a serialized receipt cannot satisfy it. Before that qualification, globally refuse H2 activation; do not strand an already shipped lawful trigger at E4I.

Concrete proposed storage placement: specialize the existing `game_state/control/incarnation_trigger.json` path into a strict client-owned successor envelope **only after** the accepted raw trigger is consumed by the real issuer. Keep the exact accepted raw payload and evaluation identity/proof as immutable envelope members. Fixed discriminator `kind=accepted_evaluation_incarnation`, version and fixed phase fields route to a dedicated reader before every legacy raw-trigger validator/normalizer/cleanup/handler. Raw GM envelopes with this discriminator must never issue capabilities. This is a proposed D11 owner-specific schema specialization, not an accepted parser change or general journal.

The envelope binds `{successorId, existingPhysicalG, sessionId, sourceEvaluation:{requestId,snapshotToken,turn:n+1,incarnation:k,sourceLabel}, acceptedTriggerBytes, sourceReceiptRefs, returnGuardBytesOrAbsence, eligibilityReadCatalog, retainedArtifactCatalog, ownerCatalogVersion, fixedPhaseReceipts}`. `successorId` is a frozen owner-issued operation coordinate, **not a TurnRequest ID or a fabricated original**. It owns no arbitrary paths, writes or source eligibility. M.E4I stores only its matching reference and exact cohort acknowledgment.

Before acceptance, the real snapshot/provenance owner copies every transitive original/accepted/claim/story/eligibility proof needed after evaluation release into an explicitly catalogued successor-owned role subtree in the existing snapshot/rollback artifact namespaces. A new private intake-role API must distinguish these retained evidence artifacts from a valid pending-turn original: no dummy TurnRequest, no fabricated source label, no changing current header to an imaginary n+2 request. Exact role-path mapping and missing/absence inventories are mandatory and remain an unresolved implementation specification. Portable hashes remain trusted-local integrity evidence, not signatures granting independent capability.

**IA cohort:** exact trigger raw→accepted envelope, complete successor-owned evidence membership/readback and M.E4I acknowledgment are one owner publication with complete G/read guards. Source evaluation artifacts remain until IA's native/main/claim debt is settled. At IA there is no realm change, k increment, stat choice, dice roll or Mortal request. The real successor has accepted *all remaining work*, not a convenient subset.

**Evaluation release:** E4R/E4K then delete only evaluation-owned originals/headers/ready/repair artifacts, preserve the successor envelope and its exact retained role inventory, and finish evaluation release before successor preparation/UI starts. A separate private `SuccessorSourceReleased` admission validates actual E4K/native/main outcome and exact preserved successor state; M's released tombstone is inert. If this cannot be reconstructed after fresh PID without deleted provenance, IA cannot qualify. It is legal to retain copied proof longer; it is not legal to recreate source evaluation authority or re-execute rewards.

This selection avoids keeping the source's live scope through UI. It does not evade D4: the old joint/evaluation obligation must actually be released before allocation, and the destination must obtain its own reviewed initialization/choice authority. Generic retained-tail guards remain in force. If an initial-allocation adapter requires a blanket bypass or an ordinary browser `/distribute` call under mismatched originals, the design is blocked.
