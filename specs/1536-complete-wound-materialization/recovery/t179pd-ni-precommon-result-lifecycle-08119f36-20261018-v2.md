## Why current owners cannot recover the missing history

Current I reads freshness/current text, projects once (including its one actual UTC fallback), calls the ordinary public single-file writer when Changed, then performs the remaining I validation and returns diagnostics. The public writer owns its own lease/release. Its trusted-local journal contains the one declared I member; after commit and cleanup neither that journal nor the file contains the later validator result or actual public return observation. The common marker does not exist yet. Equal current bytes cannot distinguish no invocation, a committed write followed by a lost return, or a normalization followed by an error. No cold reader may infer those histories from I's current image.

An I+receipt batch alone is insufficient for the stronger no-reprojection-after-restart requirement: an uncommitted batch can have published I before crashing, and existing recovery restores its before-images and cleans its prepared result. The solution must retain the computed result before any I side effect can happen. This is a lifecycle requirement, not an absent-observer or Windows blocker.
