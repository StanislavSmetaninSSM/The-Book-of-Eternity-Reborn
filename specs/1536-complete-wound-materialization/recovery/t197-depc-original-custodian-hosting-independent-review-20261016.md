## Source assessment

1. **Original graph ownership is correctly a proposed construction change.** Current Client `Program.cs:122–157,236–355` builds the console service graph, runs the actual `GameEngine` at 334–335, then disposes UI/API resources in `finally`; web startup selects another graph. `GameEngine.cs:107–161,187–242` retains the actual services and performs bootstrap, health/menu work, error logging and audio cleanup. Current GMBridge `Program.cs:474–543` separately starts the native main, constructs its own filesystem manager and binds retirement after starting pumps. The proposal's existing-assembly `--custodian` mode is technically grounded by the Client project reference and `InternalsVisibleTo`, but neither assembly visibility nor relocating registrations creates authority. Its required one original graph, HostBirth promise before constructor effects, retained menu/turn state, and separate presentation endpoint are correctly presented as changes that do not exist today. Keeping an authoritative legacy external Client would leave the original-hosting problem open. Proposal lines 5–9,19–54,60–68,173–183 are appropriately conditional.

2. **Parent enrollment is not confused with the story child's success.** `GameEngine.TurnLifecycle.cs:1484–1504` has an actual participating ordinary stage/wait/finalize operation; the late path and story child have additional outer continuation and cleanup. The proposal selects the parent invocation before its synchronous prefix, an installed promise before delegate invocation, actual task retention, original local coordinator access, and nested borrowing. This fits `FileSystemManager.MainRunFence.cs:18–110` and `GmSessionRunCoordinator.cs:126–158`. Crucial implementation boundary: `RunOperationAsync` creates its pin and disposes that pin and access scope when its awaited delegate returns (126–130). Saving an Access object or Task reference in a registry does not extend this lifetime. A future exact contract must keep the actual body/closing path alive until required joins and disposition, and must preserve the actual SessionOperation/lease owners. Proposal lines 72–93 and H-B02/H-B03 leave that contract open rather than asserting current coverage. One story leaf cannot retire the parent pin, advance turn, discharge all cleanup or authorize HC.

3. **Frontend loss is accurately separated from gameplay cancellation and original-authority loss.** Existing turn cancellation can delete a request and restore state (`GameEngine.TurnLifecycle.cs:89–110,293–325`); wait/input tasks and `finally` joins are real (`474–505,545–567,598–622`); generic error handling can publish `error_log` (`4386–4410`; `GameEngine.cs:228–234`). The existing `IConsoleInputSource.cs:1–32` synchronous interface has no custodian-seal result. The proposed nonsemantic held outcome, owned input unblock, prohibition on synthesizing Escape/null/default/timeout failure, and interception before generic catches are therefore necessary new seams, not claimed existing behavior. The proposal expressly does not use frontend detach as `NotifyUncertain` while the original owners remain valid, and does not clear true uncertainty. UI return and `Program` disposal cannot be used as proof of task or native exhaustion. Reattachment is presentation-only and cannot reopen a sealed operation. These requirements are consistent at proposal lines 122–157 and H07/H14/H17.

4. **Native birth, publication permission and stop ordering remain honestly incomplete.** Current coordinator launch assigns the prepared original terminal before releasing it (`GmSessionRunCoordinator.cs:209–268`), while BridgeHost starts/binds its readers later. Registering startup/partial-owner/pump promises before effects and binding the actual retained owner before one release is the right dependency; the Win startup observation also precedes main guard acquisition (`BridgeHost.WindowsLaunch.cs:10–59`; `WindowsStartupObservationProbe.cs:60–105,149–155`). There is no claim that new status metadata supplies those live references. Existing access validators still reject closed admission, uncertainty, debt, wrong main state or lost/root-exited authority. `BeginStopAsync:292–313` waits for pins and turns timeout into uncertainty; `ConfirmSettledStopAsync:341–354` rejects unresolved uncertainty or active pins. `PipePins.cs:44–50` leaves a lost remote pin counted. The proposal explicitly rejects these as an existing successful reconciliation path and requires an exact private, original-attempt debt-bound permission, distinct from new ordinary publication. Native stop needed to unblock an already-owned waiter must be orchestrated without holding locks required by its join or cleanup. H-B03/H04/H11/H12 remain required; no timeout, pin decrement, replacement G or fake ClosedObserved is licensed.

5. **The surrounding-writer inventory is useful and expressly partial.** W01–W16 identify startup/health, outer turn, status/error/debug publication, prompt/draft work, helpers/daemon, direct CLI, workers, web refresh/load/media and endpoint/audio tasks. Actual status publication is queued and later executed under `RunOperationAsync`, with its own seal/join behavior (`BridgeHost.StatusPublication.cs:23–114`). `StateManager.cs:33–74,130–152` bootstrap and refresh can mutate; BrowserGameScreenService and ExplorerWebCommandService refresh paths are not made read-only by their UI shape. `LocalWebUiHost.cs:28–132` bootstraps its separate 30-registration graph; `BrowserRequestAdmission.cs:1–25` serializes an HTTP request, not an original source lifetime. The proposal retains browser staging/idle/expected-G finalization and the retained-load complete/cancel exception. It explicitly requires extraction/inventory instead of treating cohosting, process containment, a DI count, the prior story guard map, or a source catalog as a write grant. Full media/UI parity is not silently disabled to claim qualification. H-B01/H-B02 and full target remain open.

6. **Lifecycle and security claims stay within their stated limits.** The candidate selects no service, endpoint listener, OS policy change, credential, key or permission expansion; B03 codec/acknowledgement and B04 caller rights remain unaccepted.
