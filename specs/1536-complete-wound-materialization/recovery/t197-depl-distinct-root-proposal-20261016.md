## 2. Exact ordinary archive boundary

`SaveLoadService.cs:69–100,210–288,549–594,1039–1180,1548–1553` defines the boundary:

* Included trees: game_state, lore, mods, world_profiles, stories, selected entity image subdirectories (not scenes), output; optional config; save_metadata; schema-1 SHA-256 save_manifest. The resource authority file is emitted from its actual validated owner image rather than copied blindly.
* Excluded controls include pending_turn_snapshot.json, validation repair request/ready/task, terminal_protocol_failure_request, life_transitions, incarnation_trigger, ascension, progression report, GM window/status, local UI lock, resource command, Mortal wound opportunity decision, ink-feather result and explorer/console rollback roots. Excluded prefixes include pending_turn_snapshot/, local UI locks, explorer/console rollback, QTE normalizer backups, worker_tasks/ and worker_proposals/.
* Input and ready trees are not included. The actual root `.boe_runtime` is outside game_session and is not exported: no physical current-G authority, runtime locks, native journals, pipe objects, process handles or main pins migrate.
* `pending_turn_snapshot.authority.json` is a sibling, **not** the explicitly excluded manifest or directory. Likewise ordinary `.rollback.*` sibling files can survive inside included trees. M at `game_state/wounds/mortal_qte_decision_publication.json` can survive. Thus the defect is incomplete/orphaned provenance, not a claim that every proof byte is filtered.
* Schema-1 manifest validates exact non-ephemeral membership/hashes and rejects listed ephemeral members. The ordinary reader also accepts archives without a manifest; that behavior is not sufficient T197 proof and no legacy fallback is proposed for this family. Existing archive budgets are 8,192 entries, 2 MiB entry-name bytes, 4 MiB manifest, 8 MiB soul, 64 MiB per entry, 512 MiB total, with existing compression-ratio checks.
* Load skips ephemeral entries again (`Loading.cs:337`), canonicalizes fixed paths (`:423–476`) and may project the detached player-soul profile (`:478+`) before importing. A T197 adapter must account for actual transformed bytes. It must not rewrite historical originals or weaken old receipts to make them match. Require exact no-op for a bound profile/path or an already-owned, explicitly catalogued transformation and separate import mapping. Cross-platform case/path collisions remain refusal conditions.

Current save/load integrity therefore cannot establish target originals, request, source/target copy roles, pending/repair obligations or exact phase by itself. There is no currently supported source-backed **T197 in-flight** route demonstrated here. Ordinary save/load support is not withdrawn; the family specialization is a required unresolved part of its qualification.

## 3. Conditional bounded family contract

The names in this section are proposed private issuer APIs, not existing APIs or accepted grants. They reuse the actual save/load/native owners; no parallel journal, wildcard writer, copied capability or general old-G rebind is proposed.

### A. Export at a semantic in-flight, storage-settled cut

`T197ArchiveOwner.TryPrepareContinuationExport(heldLease, actualFamilyAdmission, actualDebtReceipts)` should return a private `PreparedT197ContinuationExport` only from actual owner-validated originals and phase readback. Capture current physical G_A without minting it, actual source root correlation, source Mortal tuple n/action/k_death, target evaluation n+1 and current fixed phase. Freeze a precise immutable descriptor plus role inventory; checksums validate bytes after issuance and never replace the issuer.

“Quiescent” has two separate meanings: the lease freezes storage writers, while actual native/claim/main owners resolve their own operation debts. A lease alone cannot certify a stopped process. At export, all already-published semantic effects remain accepted; only their remaining work transfers. No uncertain publication, open claim or unresolved pin can be represented as portable success. DEP-C's lost-pin hole remains blocking where applicable. A source that needs a genuine stop uses its actual source lifecycle owner; **B's later stop cannot certify A's main or browser debt**. The current save helper has no such source-cut issuer. An interactive save can wait for its actual owner to reach the cut and then retry preparation, without advancing an extra Mortal turn or rerunning an accepted phase.

Proposed archive-only names are a strict family envelope `continuations/t197/descriptor.json` and numbered payload entries `continuations/t197/objects/<ordinal>.bin`, all covered by the existing outer integrity manifest and budget. Numbers map one-to-one to declared typed roles; no arbitrary destination path is executable. This is a **proposed new narrow archive-family contract, NOT an accepted format change**. It avoids removing the general ephemeral filter. Strict reader consumes this envelope rather than importing it as arbitrary live namespace data. Export must either include the full required catalog or refuse creation of a *resumable* T197 snapshot with a concrete missing-proof reason; that refusal does not satisfy the required restore qualification.

Descriptor fields: family/schema; actual owner-issued checkpoint kind; immutable source root/G and source/target tuple; phase; exact predecessor receipts; exported source-M image; original manifest/authority/validation-copy and rollback-copy identities; accepted story/history/progression prefixes; guarded canonical images; source closure evidence; finite obligations and consumed/remaining work. Every inventory member declares role, logical path, kind (file/directory/absence), byte length/hash/encoder and predecessor role. Exact bytes-or-absence remain available in payload where subsequent validation or undo requires them. Name/hash-only catalogs cannot reconstruct missing originals.

Portable phase rows are finite, but their exact full per-leaf inventories remain an open design prerequisite:

| Source cut | Required evidence and permitted remaining work |
|---|---|
| H0 | Frozen n/action/k, lawful death/voluntary original, reserved values/dice, source accepted prefix; continue H1 only. |
| H1 / HP | Exact accepted realm/history/death/reset cohort; HP schedule/control frozen UTC when accepted; continue the next missing phase without another realm/history/time effect. |
| H2 / HC / H3 / HQ | Both source and successor role catalogs, actual target acceptance and source closure/release/dequeue receipts as present; copied browser binding classified by its real phase. Request presence is not dispatch. Any A pin debt must be resolved before portable issuance. Resume only remaining destination-local cleanup/dispatch after owned admission. |
| Private repair/pending / EP | Actual specialized owner checkpoint, candidate, original and bounded pending obligations; no fake plan from raw repair DTO. Unresolved native/claim decisions must first settle at A. |
| E1 / E2P / E2S / E3 | Exact accepted canonical/progression/story/presentation receipts and baseline overlays; never rerun reward, dice, evaluation normalization, history or n+1 tick already accepted. |
| E4C / E4I / E4R | Exact pending-owner cleanup; absent successor or genuine DEP-I incarnation intake/bootstrap lineage; original-release inventory and remaining cleanup. An incarnation offer is insufficient. |
| E4K | Released tombstone is diagnostic; no target writer reissued from deleted proofs. Ordinary loaded state can proceed only through its existing lawful new action admission. |

For each row, closure of the current transport/native operation must not be confused with semantic completion. A lower-cut archive cannot assert later receipts merely because a newer A later reaches them. Unknown/mixed phases fail closed with all evidence retained.

### B. Real load installs the admission proof with G′

Propose `SaveLoadService.PrepareT197Import(candidate)` and `T197LoadOwner.BindImportToReplacement(...)`. They run within the existing prepared-archive source custody, exact namespace staging and real load admission. First verify complete outer manifest, strict family schema, all payload bytes/absences/roles, immutable source originals and exact phase graph. Reject extra/unowned duplicate roles, foreign tuples, deleted mandatory provenance, accidental ephemeral fragments, raw old capabilities and unknown transformations. Revalidate source bytes before the actual transaction just as current load does.

The existing load owner alone chooses destination G_B′. It adds a fixed `loadAdmission` record to the existing R2 M family envelope, with the pre-import M bytes preserved in an exact **named** role under the existing original artifact namespace. This location/schema and immutable predecessor mapping are a proposal requiring explicit design review; no additional journal or free-standing control-root permission is assumed. Source G and every historical source/target receipt remain immutable. New current-G fields live only in the load-owner record. An archive's copied previous loadAdmission is historical evidence, never current authority.

Proposed bounded receipt:

```
T197LoadAdmissionV1 {
  actualLoadOperationId, actualNativeTransactionId,
  archiveImageIdentity(length,sha256), familySchema, exportDescriptorIdentity,
  immutableSource(rootCorrelation,G_A,n,action,k_death,targetTuple,phase),
  predecessorReceiptRefs, completeImportedRoleCatalog,
  destination(rootAuthority,beforeG,newPhysicalG),
  destinationStopReceipt, sourceDebtResolutionRefs,
  exactOwnedTransformations, remainingPhase, dispatchEligibility
}
```

A bounded import keeps the immediate predecessor receipt and the immutable origin basis required by the next reader, not an unbounded chain of M snapshots. Repeated A→B→C import must explicitly prove how this finite representation preserves every required predecessor; simply truncating a chain is not allowed. This is an unresolved schema proof, listed below.

The receipt must enter the **same real namespace+G′ cohort**, with complete guards and known native outcome. `LoadReplacementResult` currently drops the underlying publication receipt. A routine typed extension can retain the genuine `TrustedLocalPublicationResult` for live readback, but persisting its TransactionId after commit in a second unrelated write creates a crash gap. Proposal: the actual native namespace owner privately prepares one publication identity, invokes a strictly typed load-family receipt builder, freezes the final receipt/member plan, then uses that exact prepared transaction once. No caller-selected transaction IDs, observer-side mutation, validation-only ID or manually duplicated native journal is permissible. This requires a small explicit owner API change; missing it is not automatically a new principled grant. Receipt body catalogs the payload members without recursively hashing itself; the actual native result/catalog includes the receipt's real after-image hash.

### C. Cold re-admission and destination-local execution

`T197LoadOwner.TryReadCommittedImport(currentLease, actualRoot, existingG)` must first let the existing native owner resolve its real debt, then require a present actual current G, exact committed admission/namespace match, the source proof roles and the phase-specific live canonical overlays. It does not bootstrap G from M. When receipts are present but native/claim debt remains uncertain, hold. When load rolled back, no new family capability exists. A third physical G or another root rejects this record unless another actual load operation issues its own complete admission.

Private `ImportedT197RemainingPhase` represents the relationship **historical proof at G_A → narrowly admitted remaining phase at G_B′**. It is not an ordinary old SessionOperationContext rebound to G′. Each actual family owner needs an explicit imported-origin reader preserving historical validation and using current G only for new admitted publications. No source Mortal action replay; no target result reacceptance; no new dice/reward; no synthetic target request from an M tuple. If a genuinely unaccepted installed target request is the remaining obligation, its immutable original bytes and owner-gated dispatch survive; accepted target phases resume after acceptance. Incarnation uses the separate genuine DEP-I owner/initialization contract when applicable.

Cold receipt readback is not proof that the old live `GmLoadSessionOperation` finished or a GM restarted. Separate current local main admission must establish current root/G quiescence; any retained main uncertainty stays with its real owner. The T197 reader can reconstruct semantic remaining-phase authority only after this actual guard and all source provenance validations. It cannot turn serialized NoActiveSession/Stopped into a fresh process receipt. Current main startup/recovery integration for this branch is missing. If no existing owner can resolve lost live load/main custody after a crash, that requires the bounded lifecycle authority decision in DEP-C, not routine D11 or a DTO workaround.

## 4. Client, dispatch and cleanup obligations

Console and browser retain their current original stop→actual load→refresh→finish sequence. Put the new family classifier/admission **before** generic loaded-state normalization, ordinary pending recovery, response building that assumes normal ownership, and daemon request scanning. A typed imported family remains blocked pending exact readback; request/ready file presence cannot unlock scanning. Generic current-G original validators must not silently accept old-G artifacts. The family adapter owns this exceptional typed path; unrelated gameplay keeps its normal admission.

Browser displays the actual imported remaining state and waits for genuine bundle Applied before its existing finish route. Its old player-action source binding is history/remaining cleanup according to H2/HC/H3/HQ; it is never recycled as the evaluation or incarnation player request. Console only shows the existing legal target/presentation/input state. UI delay, reload, cancel, timeout and disconnected browser retain the committed load and a blocked continuation where required; they do not undo accepted history or fabricate acceptance.

Native runtime scratch stays in each real root and is cleaned solely by its native owner. Source A originals/cleanup stay governed by A's source owner: exporting a copy does not delete or discharge them. B cleans only exact imported names admitted by its role inventory, with its new-G authority and phase receipt; it does not run broad snapshot/rollback glob cleanup. Source validation/rollback images can differ and require separate roles. Current/retained successor roles cannot be removed by predecessor cleanup. Preserve complete pending controls, repair/private-owner obligations and main closure debt until their actual owner acknowledges them. Terminal tombstone deletion/release remains inert; missing provenance cannot be recreated from hashes.

## 6. Authority classification and remaining decisions

Routine already-owned specialization, conditional on complete reviewed T197 design: pure role-catalog/phase extraction; exact archive integrity preparation; strict family serialization/parsing; existing save/native publication reuse; typed load result retention; exact actual-transaction preparation; remaining-phase readers under actual current-G admission; UI classification/dispatch gating; finite owned cleanup. These are candidates for D11 because the current save/load owner already reads archives, replaces its namespace and establishes G′. Their implementation is **not authorized by this report** while T197 DESIGN remains incomplete.

Concrete proposed contracts needing review, not implicitly accepted grants: (L1) archive-family schema/paths/inclusion contract above; (L2) bounded same-cohort M import receipt and actual native transaction identity API; (L3) source stable-cut/debt receipt issuer and complete phase/leaf catalogs; (L4) current-G imported-origin family capability readers preserving original G and repeat-load history. No broad archive format migration, backward-compatibility guarantee, global gameplay permission or generic cross-generation authority follows from them.

The genuinely new principled issue, if required, is **durable lifecycle proof for process/pin/load custody that existing live owners cannot issue after loss/crash**. That is the separately unaccepted DEP-C/G-C discussion, not a new helper called D11. Granting it would need actual lifetime/operation/source-debt custody and exact retirement proof; this proposal grants none. No new distributed A→B ownership/revocation authority is requested or assumed.

Remaining questions, each blocking a claim DEP-L complete:

1. **Q-L1:** Accept a precise family archive envelope and M loadAdmission schema/locations, with strict limits and no unowned data extraction; finalize exact leaf inventory for all phase rows, including source/target validation versus rollback images and eligible incarnation.
2. **Q-L2:** Name the actual source stable-cut issuer and closure receipts for every required semantic phase. How can every legal H/E/repair/incarnation state reach an exportable storage-settled cut without forbidden replay or abandoning unresolved work? DEP-C remains mandatory for Lost.

4. **Q-L4:** Finish the exact historical-original/current-G reader contracts and bounded repeated-load predecessor proof. M's immutable source data must survive while the added receipt changes its outer bytes; existing whole-image predecessor seals cannot be weakened.
5. **Q-L5:** Prove cold startup's genuine current main admission/stop-custody resolution and all console/browser/daemon entry gates. Existing GmLoadSessionOperation is live-only; its persisted lookalike cannot solve this.
6. **Q-L6:** Catalog fixed-path and detached-profile transformations versus bound originals on actual Windows/Linux namespaces; qualify genuine no-op or named existing owner transformation. Reject unknown overlays before import.
7. **Q-L7:** Finish DEP-I/full-target obligations and exact imported pending/native/claim/main cleanup ownership, then qualify the supported full route. A finite phase list is not an executable complete member catalog.
