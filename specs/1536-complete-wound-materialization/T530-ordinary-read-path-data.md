# r69 — Результат кэширования каталогов в подготовке чтения

Issue [#1536](https://github.com/StanislavSmetaninSSM/The-Book-of-Eternity-Reborn/issues/1536),
spec PATH1..7, tasks T526..530. Изменение работает в основном коде. Выигрыш
**небольшой: первое восстановление быстрее на3,63с, весь тест на6,37с** в одной
последовательной off/on-паре. Цель дополнительной экономии100с не достигнута.

## Что изменено

ReadPathObservationPhase хранит только положительные наблюдения обычных каталогов
через существующие ValidationOperation/ServiceCacheStorage. TrustedScope EntryKind
и Windows directory metadata используют разные ключи; Windows root/segment роли
также разделены. Не сохраняются файлы, отсутствие, ошибки, результаты Validate или
право на запись. Сервис очищается при закрытии короткой фазы.

Ordinary sync/async readers явно передают фазу только в подготовку и начальный
допуск. Перед open/read, callback, await и retry она закрыта. Внутренний root version,
worker/callback/suppression eligibility перепроверяется при использовании. Native/
main/generation, открытие файла, leaf/post-read и source/exit fences сохраняют свой
свежий маршрут. Внешние одновременные правки открытого сохранения остаются
неподдержанными по конституции; новый механизм защиты ОС не вводился.

Нет ambient cache routing, нового глобального словаря или кэша результата допуска.
Новый internal доступ к SuppressValidationReuse нужен для прямой проверки текущего
production-контракта; рефлексия не использовалась. GM-схемы, правила, интерфейсы и
формат состояния не меняются, поэтому GM-промпты/примеры обновления не требуют.

сосредоточиться на них ради100с не оправдано. Узкая фаза сохранила свежие границы,
но оставляет почти все повторные полные проходы между запросами.

По новой просьбе владельца после завершения этого блока следующим исследованием
станут крупные проверки **перед уже имеющимся DATA cache hit** и возможность
более широкого стабильного read window через тот же сервис. Это пока гипотеза:
нужно проверить точные callers, ключ/owner/lifetime, source/authority fences и
стоимость по текущим таймерам; новое кэширование verdict/lease не разрешено этим
результатом. Новые микрооптимизации или дополнительные прогоны этой пары не нужны.
