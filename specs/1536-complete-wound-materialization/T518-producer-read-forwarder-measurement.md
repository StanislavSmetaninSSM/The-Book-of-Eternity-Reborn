# T518 — Пустые обработчики чтения производителя

Задача: [#1536](https://github.com/StanislavSmetaninSSM/The-Book-of-Eternity-Reborn/issues/1536).
Канонический контракт: spec.md FWD1..7, plan.md r67, tasks.md T514..518.

Полный исходный Windows cut0 прошёл в обоих режимах. На одной паре одинаковых
сборок и входных данных время теста уменьшилось **283,9837495 → 264,5061081 с**:
**−19,4776414 с (6,86%)**. Выигрыш находится в производителе до аварийного среза.
Первое восстановление осталось практически прежним: около 163,3 с.
Это результат одной последовательной пары, а не статистическая оценка.

## Изменение и сохранённые контракты

Два постоянно установленных обработчика реальной lifecycle-фикстуры пересылали
вызовы отсутствующим наблюдателям. Производственный код обоснованно считает
произвольные read hooks способными изменить данные и отключает повторное
использование источников и наблюдений каталогов. Проверка допуска не изменена.

В TestSupport добавлен типизированный владелец наблюдателей. Только обычный
extended seeded Windows cut0 producer по умолчанию получает действительно
отсутствующие read hooks. Попытка поздно подключить ненулевой обработчик в этом
режиме явно отклоняется до изменения состояния. Прочие конструкторы, срезы,
платформы, диагностические сценарии, проверки гонок и ошибок сохраняют обработчики.
Исходные callback order, await и исключения сохранены. Resumer не меняет hooks.

Закрытый переключатель BOE_TEST_JOINT_PRODUCER_READ_FORWARDERS принимает on/off;
родитель передаёт Boolean ProducerReadForwarders, оба дочерних входа проверяют его
до доступа к фикстуре. Пропущенные старые тестовые метаданные сохраняют forwarding.
Добавлены пассивные полные счётчики canonical source events по исходному пути.
Они не являются переписью всех системных вызовов, GetAttributes или дисковых чтений.

Производственные кэш-сервисы, свежие проверки источников и поколения, допуска,
native handle identity, journal/pending/QTE/gameplay assertions и native owner
не изменены. GM-документы и примеры не требуют изменений: контракт игры прежний.

## Дешёвое доказательство перед полным запуском

Новый отдельный класс использует настоящий конструктор GameEngineTurnLifecycleTests
с маленьким nonce-owned adopted root, настоящим менеджером, поколением и сессией.
Создание игрового мира и reflection отсутствуют; очистка проверяет nonce и корень.

Сначала извлечение прежних безусловных hooks воспроизвело 5 содержательных отказов
из 10 случаев: 8 вместо 2 чтений, 16 вместо 4 для двух операций и отсутствие
нового финального source fence на старом fallback. Callback order, задержка и
оба исходных исключения уже проходили. Ошибки компиляции не считались RED.

После исправления все 10 случаев прошли. Для sync и async вариантов:

| Наблюдение | Старые пустые hooks | Hooks отсутствуют |
|---|---:|---:|
| Запросы present.txt в одной фазе | 8 | 8 |
| Реальные события источника present.txt | 8 | 2 |
| Возвращённые fast DATA hits | 0 | 7 |
| Контексты проверки каталогов | 0 | 57 |
| Directory DATA hits | 0 | 456 |

Два чтения — начальное и свежее контрольное при завершении. Подмена байтов той же
длины с восстановленным timestamp отклоняется. Следующая операция видит новые
данные после успеха и ошибки; позднее подключение observer отклоняется, а обычный
режим сохраняет порядок, ожидание и primary exception. Время маленькой фазы само
по себе выросло из-за дополнительного входа и свежей проверки; ускорение по этим
миллисекундам не заявлялось.

Семь выбранных категорий: core-producer-read-forwarders,
core-admission-directory-observations, core-control-game-state-data,
core-game-state-data-reuse, fr063-joint-interface-probe-budget-contracts,
fr063-joint-interface-seed-contracts, fr063-joint-five-fixture-package-contracts.
**234 различных случая PASS**, очистка owned/runtime PASS. Catalog discovery PASS,
0 выполненных тестов и 0 duplicate IDs; полный набор тестов не запускался.

GREEN проверен на b99919301. Далее изменены только XML-комментарии и документация;
финальная XML-enabled сборка 7272b0e293d5d8a360f8ce5cb1bd1b4eff631c5e согласует
все восемь DLL. Неизменённые 234 поведения повторно не запускались. Две небольшие
XML-правки после предварительной квалификации потребовали лишней сборки — это
затраты рабочего процесса, не время игры. Независимое ревью кода принято.

## Целостность, хранение и вывод

В каждом оригинале producer exit73/resumer exit0, native birth/handle identity,
EOF/join, gameplay/recovery/idempotence/mechanical/pending/journal assertions,
registry settlement и owned/runtime cleanup прошли. Анализ обработал все 142
native JSON записи и 2 текстовые строки каждого запуска. Оба полных архива по
33 члена проверены CRC и SHA256 каждого члена, без выборки и усечения.

В Git сохраняются код и этот человеческий отчёт, без логов/TRX/analysis dumps/архивов.
Независимое ревью приняло результаты, расчёты, все 131 члены трёх архивов и точный
план хранения без нерешённых замечаний (SHA256 ревью
19EE2DFB37C4B8F55E004C3AAA0DF1D3A17BF7656D894B156AC2F68B558BBD2F).
После принятия удалены ровно 109 файлов/326921503 байта: прежние два полных
архива r65 и проверенные дубликаты. Все 485 защищённых файлов, новые архивы,
старые и новые CPU/GC/INPUT, instrumentation и binary backups проверены до/после
и сохранены неизменными; рекурсивного удаления не было. Квоты сбора не вводились.

Изменение оправдано: обычная фикстура больше не отключает существующие кэши
пустыми hooks, при сохранении явного observed-режима и проверок целостности.
Получен выигрыш около 19,5 с, а не 100 с. Главный оставшийся большой интервал —
первое восстановление около 163,3 с — этим изменением не ускорен. Результат не
даёт основания кэшировать целиком допуск или пропускать свежие проверки источников.
