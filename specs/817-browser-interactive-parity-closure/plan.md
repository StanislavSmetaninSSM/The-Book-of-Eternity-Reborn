# Implementation Plan: Browser Interactive Parity Epic Closure (#817)

**Source issue:** https://github.com/StanislavSmetaninSSM/The-Book-of-Eternity-Reborn/issues/817

## Architecture

The Browser Client command-coverage audit is generated by `BookOfEternityClient/WebUi/BrowserCommandCoverageService.cs` from shared C# command metadata. The parent epic can close only after this generated audit no longer exposes #817 as a pending follow-up and after the child parity tests remain green.

## Files and Responsibilities

- `BookOfEternityClient/WebUi/BrowserCommandCoverageService.cs`: remove stale #817 audit overrides and let covered commands report the default `covered` audit state when their command descriptors already have read-only or mutating browser parity.
- `BookOfEternityClient.Tests/BrowserApiContractTests.cs`: add the parent-closure regression guard that fails while any coverage row or subcommand still references #817 or remaining umbrella work.
- `BookOfEternityClient.Tests/WebUi/*ParityTests.cs`: update child-slice assertions that previously kept #817 open as a parent umbrella to assert the specific child issue is closed and no stale parent follow-up remains.
- `BookOfEternityClient.WebFrontend/src/api/contract-fixtures/command-coverage.json`: regenerate/update if the C# coverage fixture changes and tracked generated fixtures are part of the repository.
- `specs/817-browser-interactive-parity-closure/`: record the parent closure requirements, plan, and task/evidence log.

## Method

- Use strict TDD for the coverage cleanup: add the parent-closure guard first and verify it fails against the current stale #817 metadata.
- Implement the smallest service/test/fixture changes needed to remove stale #817 follow-up metadata.
- Do not change runtime write contracts, game-state validation, afterlife pending/control files, or player command behavior.
- Preserve existing child Spec Kit artifacts; this feature is a closure/evidence layer over already merged child implementations.
