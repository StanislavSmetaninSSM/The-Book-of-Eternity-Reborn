Составь план на исправление найденных проблем.

Требования к плану:
- план должен продолжать hardening-консолидацию, а не локально латать симптомы;
- предпочитай migration на shared gateway/kernel layers;
- если несколько finding’ов имеют один root cause, план должен закрывать root cause;
- обязательно укажи, какие regressions и source/architecture guards нужны для предотвращения возврата seam’а;
- не раздувай план unrelated refactors;
- не меняй публичные JSON shapes без реальной необходимости;
- если нужен новый helper/gateway, он должен становиться source of truth, а не ещё одной parallel веткой.

В плане обязательно должны быть:
1. краткое summary;
2. ключевые implementation changes;
3. test plan;
4. assumptions/defaults.
