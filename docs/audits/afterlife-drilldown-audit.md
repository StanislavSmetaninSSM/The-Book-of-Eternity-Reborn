# Afterlife Drill-Down Audit

Source issue: #949 - https://github.com/StanislavSmetaninSSM/The-Book-of-Eternity-Reborn/issues/949

Scope: audit afterlife screens for missing detail drill-down flows after the mortal read-only audit (#948) and reference-detail work (#1054-#1057). This artifact is intentionally a triage and guardrail record. It does not implement broad afterlife drill-down behavior.

## Classification Vocabulary

- `adequate`: current console/browser output already gives a player-facing overview or guided action flow that is not raw-only and does not need a #949 follow-up.
- `fixed in #949`: a small read-only, overview-preserving fix landed in this audit PR. Current result: no rows use this classification because every confirmed behavior gap is broader than the bounded #949 slice.
- `follow-up required`: a confirmed gap is too broad for #949 and has a linked GitHub follow-up issue.
- `not applicable`: the command or surface is help-only, action-only, or otherwise not a list/detail drill-down candidate.

## Audit Basis

- Console ExplorerMode afterlife handlers expose rich selectors and detail panels for many Guardian, archive, relic, Shining, inbox, and combat surfaces.
- Browser command-result services already preserve overview output for the migrated afterlife commands.
- The largest gaps are browser-visible selected-detail actions for read-only or support rows. Implementing them together would span several builders and user workflows, so #949 records them and links follow-ups.
- Existing overview output must be preserved in every follow-up.
- Default player-facing output must avoid raw-only/generic-completion paths and avoid API/DTO/debug/local-path copy outside established advanced/debug diagnostics.
- Docs/contract impact for this audit: audit and source-guard only. No runtime afterlife contracts, pending/control files, validation rules, normalizer behavior, GM prompts, examples, or manifests changed.

## #949 Implementation Decision

No small behavior fix was implemented in #949. The confirmed gaps are larger than a safe read-only patch because they span multiple command-result builders, detail routing, browser action semantics, and parity tests. This PR therefore adds the audit artifact, follow-up issues, and source guard only.

No afterlife runtime contracts, pending/control files, validation rules, normalizer side effects, GM prompts, examples, manifests, or GM-facing afterlife contract docs were changed.
