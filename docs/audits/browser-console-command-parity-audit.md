# Browser vs Console Command Output Parity Audit

Source issue: #1119 - https://github.com/StanislavSmetaninSSM/The-Book-of-Eternity-Reborn/issues/1119

Parent epic: #1118 - https://github.com/StanislavSmetaninSSM/The-Book-of-Eternity-Reborn/issues/1118

Audit date: 2026-06-21

## Scope

This audit covers every command and subcommand emitted by `BrowserCommandCoverageService` / `/api/explorer/command-coverage` at schema version 2. It compares the browser command-result surface against console semantic parity: the browser may use browser-native layout, but it must not lose player-facing data, force raw JSON as the only explanation, or expose API/DTO/debug terminology in default player mode.

Pixel-perfect console rendering is intentionally out of scope. The standard is semantic parity: same player-visible meaning, same ability to inspect important entities, same blocked/advanced-only decision where relevant.

## Classification Vocabulary

- `covered`: current browser command output is considered semantically adequate for the audited scope.
- `advanced-only`: intentionally hidden from the default player UI and available only through explicit diagnostics or expert entry.
- `blocked`: intentionally unavailable in browser player flow until a separate contract/UX decision changes it.
- `tracked-follow-up`: a confirmed non-adequate gap has an owning GitHub issue.
- `P0`: blocker or dangerously misleading output.
- `P1`: major player-facing information loss.
- `P2`: notable player-facing quality, drill-down, or navigation gap.
- `P3`: adequate, intentionally advanced-only/blocked, or low-risk polish.

Current coverage metadata reports no open `tracked-follow-up` command or subcommand. Rows therefore mostly classify as `P3 adequate/no open gap`; historical fixes and owning closed issues are still linked so future agents know which work made the row adequate.

## Raw JSON And Advanced Diagnostics Policy

Raw payloads may remain available only as an explicit advanced/debug diagnostic surface. Rows marked `advanced-only` are not player-default parity gaps because the command itself is intentionally diagnostic.
