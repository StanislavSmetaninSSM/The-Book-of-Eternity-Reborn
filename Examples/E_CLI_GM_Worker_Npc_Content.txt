# Example: GM worker npc-content

This example shows a proposal-only NPC content worker. The worker prepares an
NPC dossier for the main GM. It does not write canonical `game_session` files
and it does not decide that the NPC already exists in the scene.

Worker profile:

```json
{
  "workerId": "npc_content_codex",
  "displayName": "Codex NPC content author",
  "launchCommand": "powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File \"BookOfEternityClient/Launcher/gm_worker_cli_runner.ps1\" -AgentCommand \"codex exec -m gpt-5.6-terra -c model_reasoning_effort=high --dangerously-bypass-approvals-and-sandbox --skip-git-repo-check -\" -TimeoutSeconds 120",
  "role": "npc-content",
  "enabled": true,
  "launchVisibility": "hidden",
  "timeoutSeconds": 150,
  "maxConcurrentTasks": 1,
  "permissions": {
    "taskTypes": ["npc-content"],
    "readPaths": [
      "game_state/core/**",
      "game_state/npcs/**",
      "game_state/factions/**",
      "game_state/quests/**",
      "game_state/world/**",
      "lore/**",
      "Rules/**",
      "TaskGuides/**"
    ],
    "proposalWritePaths": [],
    "proposalOnly": true,
    "requiresValidation": false
  }
}
```

The worker process receives `BOE_WORKER_TASK_PATH`,
`BOE_WORKER_PROPOSAL_PATH`, and `BOE_WORKER_SESSION_PATH`. It reads the task
packet and writes exactly one proposal JSON to `BOE_WORKER_PROPOSAL_PATH`.
For npc-content tasks it must keep `changedFiles` empty and return
`authoringProposal`.

GM bridge dispatch request:

```json
{
  "command": "dispatchworkertask",
  "workerTaskType": "npc-content",
  "authoringDomain": "npc",
  "authoringGoal": "Prepare an NPC dossier for the manor investigation scene.",
  "entityHints": ["senior steward", "witness", "merchant guild contact"],
  "requiredLinks": ["current location", "faction reputation", "personal quest"],
  "outputNotes": ["Return separate thoughts, quests, relationship hooks, and dialogue seeds."],
  "contextPaths": ["game_state/npcs/npc_core.json", "game_state/world/current_location.json"]
}
```

The inbox entry is diagnostic/read-only. If the main GM likes the proposal, the
main GM rewrites it into normal NPC, faction, quest, and dialogue state updates
and validation remains authoritative.
