GM worker Soul content example.

This example is a worker-proposal-v1 contract example for a hidden/background
proposal-only afterlife worker. The main GM remains responsible for the player
turn, final narration, validation, and canonical state writes.

Runtime entrypoint:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File "BookOfEternityClient/Launcher/gm_worker_cli_runner.ps1" -AgentCommand "codex exec -m gpt-5.6-terra -c model_reasoning_effort=high --dangerously-bypass-approvals-and-sandbox --skip-git-repo-check -" -TimeoutSeconds 120
```

The worker receives:

- `BOE_WORKER_TASK_PATH`
- `BOE_WORKER_PROPOSAL_PATH`
- `BOE_WORKER_SESSION_PATH`

Rejected patterns:

- a `soul-content` task without `afterlifeContract`;
- a `soul-content` task without `soulContentRequest`;
- a proposal that assigns `soulName`, `soulFormDescription`, `newSoulName`,
  `newSoulFormDescription`, `identityChange`, or `identityOverride`;
- a proposal that models the player soul as `character`, `player-character`,
  `mortal-character`, `inventory`, `item`, or generic `state`;
- a proposal that uses `UpdateCharacter`, Mortal inventory, `worldStateFlags`,
  `game_state/player`, `game_state/inventory`, or other Mortal World
  substitutes for soul progression/rewards.
