# NPC Local Trade Examples

## Canon

- Local NPC trade is client-side only.
- It does NOT create `turn_request.json`.
- It does NOT use `ink_feather_action_result.json`.
- It uses mortal-world currency from `game_state/core/player_status.json.money`.
- Soul Relics are NEVER part of NPC local trade.
- Canonical local NPC merchant profiles are:
  - `GeneralGoods`
  - `Equipment`
  - `CraftingSupplies`
  - `Consumables`
  - `KnowledgeAndMedia`
  - `LuxuryAndDecor`
  - `ArtifactsAndCurios`
  - `TechnicalGoods`
  - `IllicitGoods`
- Every generated local NPC trade item belongs to one of three classes:
  - `Functional`
  - `Material`
  - `FlavorOrUtility`
- Ordinary local goods may have no `bonuses`, `effects`, `passiveEffects`, or `structuredBonuses`. This is normal.
- A merchant NPC knows the local goods from their own stock and should not be surprised if the player asks about an item bought from that stock.

## Blocked trade

```json
{
  "tradeState": {
    "canTrade": false,
    "tradeBlockedReason": "Лавка разграблена бандитами и временно закрыта.",
    "merchantProfile": "GeneralGoods"
  }
}
```

If `canTrade = false`, the client blocks the local trade panel and shows `tradeBlockedReason`.

## Player money

```json
{
  "healthPercentage": "100%",
  "energyPercentage": "100%",
  "poisePercentage": "100%",
  "currentCondition": "Здоров",
  "money": 500
}
```

NPC trade MUST use `game_state/core/player_status.json.money`, not Ink Feathers.

## Important operational note for GM

- The stock in local NPC trade is canonical for that merchant in the current world-time window.
- When `/торговля_нпс` / `/npc_trade` creates or finds a pending inventory
  request because the current stock is missing or stale, the console and browser
  clients send `[NPC_TRADE_REQUEST]` to the GM immediately. Resolve that request
  in the current GM turn; the player should not need to type another ordinary
  action just to make the shop appear.
- If the player later asks this merchant about an item bought from that local stock, the merchant knows the item and may explain its practical use, origin, or reputation.
- Special off-menu goods may still exist through roleplay. Those are separate from the local panel.
- Mundane local goods without bonus arrays are valid and expected. Do not assume every local stock item is a build-oriented reward item.

## Closing a pending NPC trade inventory request with the GM helper

When `game_state/control/pending_npc_trade_inventory_requests.json` exists, use the session-local GM helper instead of manually searching and wiring receipts.
This is especially important for same-turn NPCs: the merchant can be present in `npc_core.json` only through `initialId`, before the canonical id is promoted.

```powershell
. "$GameSessionPath\gm_turn_helper.bootstrap.ps1"
Initialize-BoeGmTurnHelper -GameSessionPath $GameSessionPath

$items = @(
  [ordered]@{
    itemId = "npc_item_egor_bread"
    price = 12
    itemData = [ordered]@{
      itemId = "npc_item_egor_bread"
      name = "Дорожный хлеб"
      description = "Плотная буханка для дороги."
      type = "Food"
      tradeItemClass = "Functional"
      quality = "Common"
      price = 10
      baseSellPrice = 4
      weight = "0.2"
      group = "Еда"
    }
  }
)

Complete-BoeNpcTradeInventoryRequest -RequestId "npc_trade_req_egor_001" -Items $items -GenerationTradeTier "Good" -PricingTradeTier "Neutral"
Complete-BoeTurn -FilesModified @("game_state/npcs/npc_core.json")
```

`Complete-BoeNpcTradeInventoryRequest` reads the pending request, finds the NPC by `NPCId`, `npcId`, `id`, or `initialId`, validates required `itemData` fields including `tradeItemClass`, recalculates each slot `price` from `itemData.price`, NPC trade, player trade, and `pricingTradeTier`, writes `npc.tradeInventory`, and appends the matching `UpdateNpcTradeInventoryReceipts` entry with `requestId`, `npcId`, `tradeCycleId`, `merchantProfile`, `itemCount`, `resolvedAtTurn`, and `resolvedAtUtc`.
