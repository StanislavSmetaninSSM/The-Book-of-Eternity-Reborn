# E_CLI_Afterlife_Lifecycle.txt

Read when: Resolved ordinary afterlife realm; no handoff. Follow only the current dispatch/contract; Missing/null/empty realm remains unresolved fault; no ordinary topics does not independently activate this topic.
Prerequisites: Current request, authoritative realm and exact active pending/issued packet; [applicable common-core paragraphs](OtherGuides/GM_Common_Core.md).
Author here: only existing contract-authorized outputs; this reading guide grants no additional authority.
Never author: do not invent client-owned identities, seals or unissued receipts, or mutate pending/canonical state outside the current contract. Legitimate GM-authored receipts and pending closures remain permitted only through their existing explicitly authorized owner/response surface.
Worked examples: [E_CLI_Afterlife_Lifecycle.txt](Examples/E_CLI_Afterlife_Lifecycle.txt); paired rules: [Afterlife_Lifecycle.md](OtherGuides/Afterlife_Lifecycle.md). Whole original examples/negative labels remain below.

3. VALID — SHINING ABODE PENDING-BOOTSTRAP HANDOFF
==================================================

Scenario:
- `currentRealm = "Shining Abode"`.
- `shining_abode_state.json.preparedIncarnationPackage` is not null.
- The player has already chosen a prepared next-life package.
- No unresolved afterlife pending/control contracts remain; Guardian, resident, archive, offering, Source of Light (`pending_source_of_light_capstone.json`), active spiritual conflict (`game_state/meta/afterlife_spiritual_conflict_state.json.activeConflict`), Shining core/trade/politics, malformed wrong-realm NPC, and legacy `pendingNativeFactionDiscovery` blockers must be resolved or repaired before this handoff, not in the same response.

6. VALID — ORDINARY CHAOS SEA TRIGGERINCARNATION
==================================================

Scenario:
- Realm is ordinary `Chaos Sea`.
- No Shining `preparedIncarnationPackage` is present.
- The player explicitly chooses the next mortal life.
- This is not Life Evaluation and not Shining pending-bootstrap handoff.
- This response is part of the accepted turn that owns the matching validated `game_state/control/pending_turn_snapshot`; a later manual `incarnation_trigger.json` repair without that authority is invalid.

Correct response/control fragment:

```json
{
  "response": "Море Хаоса раскрывает новую смертную нить. Хранители не спорят с выбором души: впереди мир заснеженных перевалов, караванных обетов и древних горных архивов.",
  "TriggerIncarnation": {
    "worldDescription": "Горный мир позднего средневековья, где караванные города держатся на клятвах, архивных печатях и договорах с духами перевалов.",
    "characterDescription": "Ребёнок хранителя перевального архива, родившийся в семье, которая помнит долги караванов.",
    "circumstances": "Первая зима жизни начинается во время спора между городскими старейшинами и духом закрытого перевала."
  }
}
```

Do not write in ordinary Chaos Sea `TriggerIncarnation`:
- `TriggerLifeEnd`.
- Life Evaluation rewards.
- `preparedIncarnationPackage` mutations.
- Shining faction/radiance/trade progression.
- Mortal World `currentLocationData`, `worldEventsLog`, `UpdateNPCs`, `UpdateQuests`, or weather/time outputs.
- Out-of-band `incarnation_trigger.json` after the turn has ended or after snapshot/terminal authority is gone.

Guardian-forced incarnation is a different flow. It is legal only on an ordinary player-driven Chaos Sea turn with either legacy explicit provocation against the current active Guardian or current-turn resolved afterlife spiritual conflict proof. Guardian identity, current Abode, reputation threshold, and severity are evaluated from the validated pre-turn `game_state/meta/guardians.json` snapshot; same-turn Guardian edits cannot make the force legal. It must include the extra guardian-forced fields described in `TaskGuides/CLI_Step_Main.txt`.

6A. VALID — LEGACY GUARDIAN PROVOCATION TAG EVIDENCE
---------------------------------------------

The runtime accepts exact `playerAction` tags as deterministic evidence for Guardian-forced incarnation. This is the input context, not a GM response surface:

Additional pre-state requirement:
- The provoking Guardian must be the current active Guardian.
- Pre-turn `game_state/meta/guardians.json` for that Guardian must have `relationshipData.currentReputation` / `CurrentReputation <= -21`.
- Severity mapping is mechanical: `-21..-50 => "harsh"`, `-51..-100 => "severe"`. A reputation of `-20` or better must not force incarnation even with a provocation tag.

```text
input/turn_request.json:
playerAction = "[GUARDIAN_PROVOCATION: guardian_azalia] Игрок deliberately insults Азалия and demands punishment."
turnNumber = 77

pre-turn activeGuardian.guardianId = "guardian_azalia"
pre-turn guardian_azalia.relationshipData.currentReputation = -34
```

Correct GM response:

```json
{
  "TriggerIncarnation": {
    "source": "guardian_forced",
    "guardianId": "guardian_azalia",
    "severityBand": "harsh",
    "reason": "The player explicitly provoked the current Guardian.",
    "provocationSummary": "The player used the GUARDIAN_PROVOCATION tag and insulted Azalia directly.",
    "worldDescription": "A cold frontier world where oaths have immediate metaphysical weight.",
    "characterDescription": "A child born under a debt-mark, watched by oath-keepers.",
    "circumstances": "The first winter begins with a public obligation that cannot be ignored."
  }
}
```

Why this is valid:
- `[GUARDIAN_PROVOCATION]` without an id is accepted as explicit provocation evidence.
- `[GUARDIAN_PROVOCATION: guardianId]` is accepted only when the id exactly matches `TriggerIncarnation.guardianId`.
- `severityBand = "harsh"` matches pre-turn reputation `-34` in the `-21..-50` band. If the same Guardian had `currentReputation = -62`, the correct `severityBand` would be `"severe"`.
- This tag is evidence, not a pending file. It does not authorize Shining handoff, protected post-life turns, or forcing one Guardian's punishment through another Guardian's id.
- The trigger is still valid only inside the current accepted turn with matching validated `game_state/control/pending_turn_snapshot` authority; otherwise validation reports `incarnation_trigger_invalid_validated_snapshot_context`.

6B. VALID — ASCENSION HANDOFF IS CLIENT-EXECUTED
------------------------------------------------

Ascension is a Chaos Sea lifecycle trigger. The GM confirms the explicit choice and writes the trigger only; the client performs the later realm handoff after validation. Do not manually switch `soul_state.currentRealm` to `Shining Abode` in the same response.

Input prerequisites:
- `soul_state.currentRealm = "Chaos Sea"`.
- Enlightenment is ascension-ready: `enlightenment.experience >= 60` or `soulProgression.totalExperience >= 60`; legacy max/Transcendence markers (`progressPercent=100`, high tier, `Transcendence`) remain valid.
- `playerAction` explicitly chooses Ascension.
- No `TriggerLifeEnd`, no Shining pending-bootstrap package handoff, no Mortal World state mutation.

Correct accepted response:

```json
{
  "AscensionTrigger": true,
  "playerChoice": "Ascension",
  "response": "Море Хаоса раскрывается сияющим разломом. Душа делает выбор вознестись; дальнейший переход в Сияющую Обитель выполнит клиент после принятия этого хода."
}
```

Correct `game_state/control/ascension.json` after distribution:

```json
{
  "AscensionTrigger": true,
  "playerChoice": "Ascension"
}
```

Forbidden in the same accepted response:
- `TriggerLifeEnd`.
- `game_state/control/life_transitions.json`.
- `TriggerIncarnation`.
- Manual `soul_state.currentRealm = "Shining Abode"`.
- Shining faction/radiance/trade state mutations.
- `progressionProcessingReport` unless the same request's `progressionControl` explicitly requires scheduler debt.
- Mortal World `currentLocationData`, `UpdateNPCs`, `worldEventsLog`, or faction state.
- Mortal bootstrap files or current-world lore. The client performs the Shining Abode handoff after accepting `ascension.json`.

Correct reasoning:

```markdown
## Охват NPC-анализа
- Режим: Guardian-centric
- Afterlife subtype: Ordinary Chaos Sea living-world turn without pending files.
- Релевантные акторы: Азалия, Лиора
- Почему они релевантны: Азалия has a due Guardian project cycle; Лиора has a due resident agency cycle.

## Actor Brain 2.0
### Азалия
- Текущая локация: Край Обители Шёлковой Памяти; остаётся рядом с текущим проектом.
```
