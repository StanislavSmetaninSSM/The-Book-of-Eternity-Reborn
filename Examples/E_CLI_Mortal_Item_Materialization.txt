# Mortal Item Materialization v1 — исполняемые примеры

Эти примеры относятся только к смертным мирам. Новый долговечный предмет ГМ
передаёт полным объектом с `existedId: null`, уникальным в пределах хода
`creationRef` и полным `materialization`. ГМ не создаёт `itemId`,
`materializationReceipt`, `item_identity_index.json`, seal, transition или
lineage: эти поверхности создаёт и изменяет только клиент после успешной
проверки. Игра ещё не вышла, поэтому receipt-less canonical предметы не
повышаются и не мигрируют во время игры — они отклоняются.

### mortal_item_existing_transfer_v1

Это иллюстрация результата клиента, а не JSON, который должен писать ГМ.
Перенос связывается по exact `itemId`; envelope и receipt остаются побитово
равными, меняется только carrier и добавляется клиентский transition.
`isCarried`, `currentLocationId` и `currentLocationName` are not placement authority
предмета и не должны добавляться ГМ: размещение задают exact route
destination, carrier и `contentsPath`; при входе в `player_inventory` клиент
удаляет устаревшие placement hints.

### mortal_item_split_merge_lineage_v1

Split и merge выполняет клиент через coordinated writer. ГМ не назначает
дочерний ID, receipt, родителей, retired-state или survivor history.

```json
{
  "split": {
    "sourceItemId": "itm_iron_nails_stack",
    "quantityBefore": 10,
    "sourceQuantityAfter": 7,
    "childItemId": "itm_iron_nails_split_child",
    "childQuantityAfter": 3,
    "childReceipt": {
      "instanceKind": "split_derived",
      "parentItemIds": ["itm_iron_nails_stack"]
    },
    "transition": { "kind": "split", "sourceItemIds": ["itm_iron_nails_stack"], "quantityBefore": 10, "quantityAfter": 10 }
  },
  "merge": {
    "survivorItemId": "itm_iron_nails_stack",
    "contributorItemId": "itm_iron_nails_split_child",
    "survivorReceiptPreserved": true,
    "survivorQuantityAfter": 10,
    "contributorState": "merged",
    "mergedIntoItemId": "itm_iron_nails_stack",
    "transition": { "kind": "merge", "sourceItemIds": ["itm_iron_nails_stack", "itm_iron_nails_split_child"], "quantityBefore": 10, "quantityAfter": 10 }
  }
}
```

### mortal_item_receiptless_rejection_v1

ОЖИДАЕМО НЕВЕРНЫЙ canonical input. Он не получает runtime promotion даже если
раньше использовался в тестовой фикстуре.

```json
    {

      "name": "Предмет без квитанции",
      "materialization": {
        "schemaVersion": 1,
        "materializationId": "mat_receiptless_example",
        "realm": "Mortal",
        "route": "player_acquisition",
        "sourceTurn": 7,
        "sourceAuthority": { "kind": "turn_outcome", "authorityId": "turn_7" },
        "creationRef": "new_receiptless_example",
        "state": "complete",
        "sections": {
          "presentation": { "state": "populated", "reason": null },
          "physical": { "state": "populated", "reason": null },
          "mechanics": { "state": "empty_by_design", "reason": "Нет механик." },
          "equipment": { "state": "empty_by_design", "reason": "Не экипируется." },
          "container": { "state": "empty_by_design", "reason": "Не контейнер." },
          "consumption": { "state": "empty_by_design", "reason": "Не расходуется." },
          "readableOrSentient": { "state": "empty_by_design", "reason": "Не читается и не говорит." },
          "craftingAndDisassembly": { "state": "empty_by_design", "reason": "Нет рецепта или разборки." },

          "questRole": { "state": "empty_by_design", "reason": "Не предмет задания." },

```

Диагностический код выше точный. Правильное исправление — откатить
непринятый результат или заново сформировать полный raw creation package с
новым turn-unique `creationRef`; нельзя дописывать поддельную квитанцию.
