==================================================
INK FEATHER ACTIONS — STRUCTURED RECEIPT EXAMPLES
==================================================

For every GM-side `[INK_FEATHER_ACTION: TAG]`, the GM MUST write:
- normal state changes
- `output/ink_feather_action_result.json`

Minimal required receipt shape:

```json
{
  "sessionId": "game-session-123",
  "requestId": "req-42",
  "turnNumber": 42,
  "actionTag": "ABSORB_FEATHERS",
  "resolved": true,
  "costInFeathers": 20,
  "resolutionType": "experience",
  "summary": "The Soul absorbs crystallized memory and gains a surge of experience.",
  "stateEvidence": {
    "affectedFiles": [
      "game_state/player/experience.json"
    ],
    "experienceGained": 120
  }
}
```

Rules:
- `actionTag` MUST match the tag in `turn_request.playerAction`
- `sessionId`, `requestId`, `turnNumber` MUST match current `turn_request.json`
- `resolved` MUST be `true`
- `stateEvidence.affectedFiles` MUST list the files that really changed
- `ABSORB_FEATHERS` is valid only if `experienceGained` is positive and an authoritative XP counter really increases
- `LEARN_SKILL` is valid only if the named skill is NEW for this turn
- `FATE_SHIELD` is valid only if `Щит Судьбы` is newly added this turn

8. VALID — GUARDIAN_FAVOR
==================================================

The player may ask for something specific or may simply offer the feathers as a gift.
The only guaranteed mechanical minimum is a reputation increase for the current Guardian.

Valid minimal receipt:

```json

  "actionTag": "GUARDIAN_FAVOR",
  "resolved": true,
  "costInFeathers": 25,

    "affectedFiles": [

    ],

  }

```

Additional quest / buff / hint / service outcomes are allowed, but they are NOT required for validation.
Pure narrative favor without a real reputation increase is INVALID.

11. VALID — ABODE_OFFERING
==================================================

`ABODE_OFFERING` is an afterlife-only feather offering to a specific Guardian's Abode.
The client writes `game_state/control/pending_abode_offering.json`; GM must read it as input only and must not edit it.
The power increase must be materialized through `guardianPowerEvents` with `reasonType = offering`.

Valid minimal receipt:

```json
{
  "sessionId": "game-session-123",
  "requestId": "req-111",
  "turnNumber": 111,
  "actionTag": "ABODE_OFFERING",
  "resolved": true,
  "costInFeathers": 100,
  "resolutionType": "abodeOffering",
  "summary": "The Abode absorbs the ink and grows denser with accumulated power.",
  "stateEvidence": {
    "affectedFiles": [
      "game_state/meta/guardians.json",
      "game_state/meta/abode_power_journal.json"
    ],
    "guardianId": "guardian_azalia",
    "powerGain": 2,
    "returnCycleId": "return_3",
    "powerEventId": "abode_offering_guardian_azalia_return_3"
  }
}
```

Matching power event:

```json
{
  "guardianPowerEvents": [
    {
      "eventId": "abode_offering_guardian_azalia_return_3",
      "guardianId": "guardian_azalia",
      "delta": 2,
      "reasonType": "offering",
      "sourceSurface": "INK_FEATHER_ACTION.ABODE_OFFERING",
      "sourceId": "return_3",
      "title": "Подношение усилило Обитель",
      "summary": "The Soul offered 100 Ink Feathers to the Abode.",
      "audit": {
        "offeringType": "ink_feathers",
        "inkFeathersOffered": 100,
        "returnCycleId": "return_3",
        "capRemainingBefore": 100,
        "baseDelta": 2,
        "finalDelta": 2
      }
    }
  ]
}
```

Validation notes:
- only `50`, `100`, or `150` feathers are valid in v1
- power gain must be `+1`, `+2`, or `+3` respectively
- total feather offerings to the same Guardian in one `returnCycleId` must not exceed `150`

==================================================
12. INVALID CASES
==================================================

Invalid:
- feathers were spent but there is no `output/ink_feather_action_result.json`
- receipt exists but `actionTag` does not match the current `[INK_FEATHER_ACTION: TAG]`
- receipt exists but listed `affectedFiles` did not really change
- `LEARN_SKILL` points to a skill that already existed before the turn
- `FATE_SHIELD` points to an already existing `Щит Судьбы`
- `ABSORB_FEATHERS` changes `experience.json`, but no authoritative XP counter actually grows
- `DONATE_TO_GUARDIAN` uses a `reputationChange` value that does not match `min(25, max(15, costInFeathers / 3))`
- `GUARDIAN_FAVOR` returns only lore or advice without a real reputation increase
- `CULTIVATE_ENLIGHTENMENT` uses `experienceGain` that is not equal to `costInFeathers * 2`
- `ABODE_OFFERING` changes guardian power without `guardianPowerEvents.reasonType = offering`
- `ABODE_OFFERING` ignores `pending_abode_offering.json` or uses another `guardianId` / `returnCycleId`
- `SOUL_IMPRINT` creates an imprint without summary/description or without preserved core traits / personality traits
- `SEAL_IN_INK` does not create `game_state/control/pending_ink_actions.json`
- `MEMORY_GATES` writes a receipt but does not create a valid `pendingMemoryLegacy`
