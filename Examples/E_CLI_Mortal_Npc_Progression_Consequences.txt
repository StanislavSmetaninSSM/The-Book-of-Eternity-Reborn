# Mortal NPC progression: governed consequences, two independent alternatives

This is a bounded existing-NPC command/composition example, not a creation payload
or a claim that all #1538 combat, trade, journal, item and location dependencies are
implemented. The actor shown is the relevant projection of an already validated
original. Preserve the complete actor in real state; do not replace it with this
projection. The original skill sidecar is absent with authenticated absence or has
only empty consumed-command arrays. Do not replay commands retained from old turns.

The two alternatives below each start from the SAME original, not from each other's
result. Do not send both. Source correlation assumes session_npc_example /
request_npc_example / turn 42; copy the actual current turn request in real use.
No snapshot tokens, hashes or client-owned publication evidence belong in commands.
The world policies below are pre-existing setting authority, not policy changes to
submit alongside XP. Missing world file/subtree means no characteristic growth;
malformed present npcProgression blocks progression instead of becoming absence.

## Alternative A: fixed increments plus one new skill

Existing lore/current_world/world_setting.json policy:

```json
{
  "npcProgression": {
    "schemaVersion": 1,
    "characteristics": {
      "mode": "fixedIncrements",
      "perLevel": {
        "setting_defined_focus": 1
      }
    }
  }
}
```

99 + 566 = 100 + 565: leave levels 1 and 2, enter level 3 at XP 0; its next cost
is 1558. Exactly floor((3 - 1) / 2) = 1 skill award is required, not a reward for
crossing an even-numbered level. Fixed +1 per level raises focus from 4 to 6 and
leaves resolve at 3. The claim references a genuinely new passive skill Fieldwork.

## Atomic validation and bounded repair

A skillAwards declaration does not itself create skills or change mastery. The real
candidate must fulfill every claim through the existing exact-owner skill reducer,
and every characteristic result through current-world authority before publication.
One new skill counts once; repeated masteryIncrease claims require that many actual
mastery levels gained. A one-level transition requires no skill award, even when it
ends on an even level. Preserve all unrelated characteristics and actor fields.

For npc_progression_skill_award_count, npc_progression_skill_award_invalid, or
npc_progression_skill_award_unfulfilled, repair only the permitted
indexed claim and its matching companion command. For npc_progression_characteristic_delta,
repair absolute characteristicValues against existing policy. Never delete a required
award, switch owner, weaken cadence, rewrite authenticated originals, or invent policy
or a progressionProfile. Missing/malformed authority is a blocker. Follow any required
full-turn resubmission; do not repair a published after-image directly.

These mechanical skillAwards do not replace #1533 private npcSkillClaims in
output/debug_logs.json. A real narrative that claims learning/mastery still needs
its existing exact-owner, kind, narrativeQuote and resolution report. Preserve authored
rows during output-only repair; never synthesize [] to hide a consequence. This example
omits output artifacts deliberately and does not authorize any additional effect,
combat, trade, journal, item, or location changes.
