Source-local worldMapUpdates fragment, not a complete GM response. The location
loc_warehouse must already exist in accepted PRE-TURN Mortal state. Replace it
with the actual exact permanent locationId, never an initialId or guessed alias.
The storage identity must be unused in this location's active and historical
child identities. Player ownership does not override explicit closed access.

The client consumes the command, adds canonical metadata/current projection and
one storage_addition transition, and updates effective access in the same accepted
publication. Original location materialization/receipt remain immutable.
Do not author history, receipts, seals or storage_access.json entries. Do not
combine this birth with storageUpdates/storagesToRemove for the same coordinate.
This route currently accepts empty contents only: no nonempty cargo, measurements
or same-turn newly created location. Use an independently admitted new location's
own complete locationStorages declaration for storage born with that location.
An invalid field is repaired only in the indexed raw operation; never rewrite
canonical originals to make it pass.

admitted currentLocationData declaration with initialId locref_current, route
current_scene_creation, source turn 42 and populated storageMetadata section.
It is not a complete location or GM response. It does not authorize a remote birth
or a nonempty storagesToAdd operation. The exact source coordinate is
locref_current:storage_supply. No permanent item or location ID is authored.

One direct single-unit noncontainer occupies one slot. Its physical volume 0.01 dm3
exactly equals this storage's volume limit, so no cargoMeasurements row is needed
or allowed. A container or multi-unit stack instead requires a complete explicit
whole-stack measurement with the existing measuredConfiguration schema; the complete
measured vehicle example demonstrates that shared schema. A changed shape/count/
