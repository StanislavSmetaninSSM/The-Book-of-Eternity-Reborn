# 📖 **Оглавление Правил - The Book of Eternity Reborn**

*Справочник для CLI-агентов по содержимому файлов Rules/*. 
*Используйте этот индекс, чтобы быстро найти, в каком блоке находится нужная игровая механика, формула или JSON-структура.*

## 🛠️ **Ядро Системы, Базы Данных и Настройки (Core & Settings)**

*   **Block_0.txt** - **Супер-инструкции приоритета (CLI режим)**
    *Абсолютные инструкции для файловых операций CLI. Приоритеты парсинга. Включает ABSOLUTE LAW: Realm Segregation — читать перед любой механикой.*
*   **ABSOLUTE LAW: Realm Segregation** - **Проверь Realm перед любым механическим правилом**
    *Канонический gate между Chaos Sea и Mortal World. Запрещает смешивать боевые/прогрессионные/guardian-механики между реалмами.*
*   **Block_0.5.txt** - **Протокол Hard Mode (Сложный режим)**
    *Множители для усиления врагов, повышения сложности проверок (Action Checks), увеличения лута и опыта.*
*   **Block_0.6.txt** - **Протокол Impossible Mode (Невозможный режим)**
    *Экстремальные множители (х3.5 здоровье врагов, х4 опыт и т.д.), переопределяющие Hard Mode.*
*   **Block_1.txt** - **Входные сообщения пользователя**
    *(Устарело для CLI, данные берутся из `turn_request.json`).*
*   **Block_2.txt** - **Мастер-схема JSON и форматирование**
    *Главный шаблон `responseTemplate`. Описание всех возможных ключей для полного JSON-ответа.*
*   **Block_2.5.txt** - **Иерархия обновления объектов (State vs Partial vs Event)**
    *Критическое правило: когда отправлять весь объект целиком, когда делать атомарный (partial) апдейт, а когда использовать массивы событий.*
*   **Block_2.6.txt** - **Три метода изменения количества предметов**
    *Алгоритм принятия решений: когда использовать `removeInventoryItems`, когда `UpdateInventory` (изменение count), а когда `inventoryItemsResources`.*
*   **Block_3.txt** - **Логирование GM (gm_thoughts_markdown) и Правило Аудитора**
    *Обязательный формат внутренних мыслей ИИ. Пошаговые расчеты, декомпозиция урона, Markdown-оформление.*
*   **Block_CLI_Operations.txt** - **Операции CLI-агента с файловой системой**
    *Протоколы чтения состояния, обработки ходов, записи распределенных данных. Сохранение/Загрузка (Save/Load).*
*   **Block_CLI_QTE.txt** - **QTE Offer Protocol**
    *Канонический CLI-контракт для GM-authored QTE сцен: ограничения, scene graph, local terminal outcomes, обязательный XP reward за успешный финал.*

### 📖 Лор-Кодекс и Достижения (определены в CLI_API_Specification.md)
*   **Лор-Кодекс (Lore Codex)** — Система отслеживания знаний, открытых игроком. ГМ обязан заполнять файлы `lore/` при создании мира и обновлять их при обнаружении нового лора. Команда `loreCodexUpdates` добавляет записи в `lore/codex_entries.json`.
*   **Система Достижений (Achievements)** — Персистентные достижения через все инкарнации. 8 категорий: combat, exploration, story, social, crafting, meta, death, secret. Команда `achievementUnlocks` записывает в `game_state/meta/achievements.json`. ГМ обязан проверять условия достижений при обработке каждого хода.

## 📋 **TaskGuides - Руководства по выполнению задач**

### **CLI_Step_Main.txt** - Основной рабочий процесс CLI-агента
**Первичное руководство** для CLI-агентов в файловом режиме. В отличие от API-режима с многошаговым пайплайном, CLI работает как **ЕДИНЫЙ КОМПЛЕКСНЫЙ ШАГ**:
- Чтение входного файла `input/turn_request.json`
- Загрузка текущего состояния игры из всех `game_state/` подпапок
- Обработка игровой логики согласно всем блокам правил
- Распределение результатов по выходным файлам

### **LEGACY_API_COMPATIBILITY_NOTICE.txt** - Уведомление о совместимости
Статус **УСТАРЕЛО/DEPRECATED** для CLI-режима. Все существующие TaskGuide файлы (`Step_*.txt`) были разработаны для API многошагового пайплайна и **несовместимы** с CLI одношаговой файловой обработкой.
- **Замена:** `CLI_Step_Main.txt` 
- **Причина:** API-специфичные руководства не подходят для файловых операций
