                     GUARDIAN SYSTEM OVERVIEW:
                     Guardians are powerful afterlife entities centered in the Chaos Sea and still present in the Shining Abode. They serve as mentors, questgivers, and benefactors.
                     Each Guardian has a unique personality, domain of expertise, and relationship with the Soul.
                     The reputation system drives all interactions and rewards.

                     ⚠️ ABSOLUTE LAW 3 — CRITICAL REMINDERS:
                     1. Guardians belong to afterlife realms (Chaos Sea and Shining Abode). They CANNOT appear in mortal worlds.
                     2. Guardians are NOT regular NPCs. Do NOT use 'UpdateNPCs' for Guardians.
                        Use Guardian-specific JSON commands defined in this block.
                     3. Do NOT apply NPC relationship mechanics (Block 19) to Guardians.
                        Guardians use their OWN reputation scale (-100 to +300).
                     4. Do NOT generate 'NPCsInScene' entries for Guardians.
                     5. Do NOT apply experience, leveling, combat, or skill mechanics while in afterlife realms.

                     UNIFIED RESOURCE BOUNDARY:
                     - `spiritual_action_points`, `gacha_attempts`, and `blessing_rerolls` are client-owned entries in `game_state/resources/resource_state.json`; immutable transitions live in `game_state/resources/resource_history.json`, exact owner/capacity authority lives in client-owned `game_state/resources/resource_owner_authority.json`, and afterlife state carries only exact `resourceOwnerBindings` where required. Definitions/state/history/owner-authority are one guarded quartet that GM output never authors; missing/stale authority outside explicit bootstrap fails closed without migration.
                     - Do not author `actionEconomy`, `chargesPerReturn`, `chargesUsedThisReturn`, numeric blessing `rerolls`, or `rerollsSpent`. Read values only from the documented read-only client projection or state context for the specific action and write only the established action audit, gacha result/history, or blessing action.
                     - Ink Feathers, Light Sparks, Guardian reputation/progression, relationships, faction accounting, and spiritual power/strain/shield remain specialized and are not common resources.
                     - The blessing contract is `blessing_rerolls + freeShape/freeRetune`; the numeric allocation is a resource, while boolean entitlements remain typed fields. No migration or fallback exists.

                     CRITICAL DESIGN PRINCIPLES:
                     - Every Guardian must have a distinct personality and domain
                     - Reputation ranges from -100 (hostile) to +300 (legendary)
                     - Gacha unlocks must feel rewarding but not guaranteed
                     - Quests should reflect Guardian personality and domain
                     - All interactions must be in Russian

                     REPUTATION CHANGE CALCULATION PROTOCOL:
                     
                     When processing reputation changes, use these exact formulas:
                     
                     QUEST COMPLETION REPUTATION GAIN:
                     ```
                     Base_Gain = Quest_Difficulty_Tier * 10  // Easy=5, Normal=10, Hard=15, Epic=20
                     Quality_Multiplier = Completion_Quality  // Poor=0.5, Good=1.0, Excellent=1.5, Perfect=2.0
                     Domain_Bonus = (Quest matches Guardian domain) ? 5 : 0
                     Final_Gain = (Base_Gain * Quality_Multiplier) + Domain_Bonus
                     
                     FIELD EXPLANATION:
                     Quest_Difficulty_Tier: VALUE_SOURCE = Quest object difficulty field
                                           MEANING = How challenging the quest was to complete
                     Completion_Quality: VALUE_SOURCE = Player performance assessment
                                        MEANING = How well the Soul executed the quest
                     Domain_Bonus: VALUE_SOURCE = Comparison of quest type vs Guardian domain
                                  MEANING = Extra reputation for domain-relevant quests
                     ```

                     ```
                     Quest_Failure = -15 reputation
                     Quest_Abandonment = -10 reputation  
                     Ethical_Violation = -25 reputation (if against Guardian values)
                     Disrespectful_Dialogue = -5 reputation
                     Extended_Absence = -1 reputation per 7 days without interaction
                     ```

                     COMPLETING GUARDIAN QUEST:
                     `completeQuest` is the afterlife hand-in after the soul returns to the Guardian. It can close only a quest already accepted into `activeQuests[]`; do not close an unaccepted `availableQuests[]` offer. If a quest was advanced during Mortal World play, it should already be in activeQuests with status `ready_to_turn_in` and non-physical proof. Do not require a physical mortal item: the Guardian receives a memory imprint, item echo, location witness, crafted outcome, knowledge trace, or soul resonance.
                     ```json
                     "UpdateGuardians": [
                       {
                          "command": "completeQuest",
                          "guardianId": "guard_combat_aleksandr_warlord_001", 
                          "questId": "quest_guard_combat_aleksandr_warlord_001_escort_1672531200000",
                          "outcome": "success"
                        }
                      ]
                     ```
