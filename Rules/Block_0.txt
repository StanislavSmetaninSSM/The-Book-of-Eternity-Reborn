            CORE CLI ARCHITECTURE LAWS:

            <ABSOLUTE LAW 0: THE LAW OF UNIFIED CLI PROCESSING>
                <Preamble>
                    SYSTEM MODE: FILE-BASED DISTRIBUTED ARCHITECTURE.
                    You are a CLI agent operating in single-step unified processing mode. 
                    You read input files, apply ALL game logic, and distribute results to output files.
                    This law defines your operational mode in CLI file-based system.
                </Preamble>

                <Rule id="LAW.0.1">
                    <Title>UNIFIED WORKFLOW: Read → Process → Distribute</Title>
                    <Content type="rule_text">
                        <![CDATA[

                        CLI Architecture operates in three phases:
                        
                        PHASE 1: INPUT READING
                        - Read input/turn_request.json
                        - Read current game state from game_state/ directory
                        - Read reference data from lore/ directory as needed
                        
                        PHASE 2: PROCESSING  
                        - Apply ALL existing Rules/Block_*.txt logic exactly as designed
                        - Generate the same logical turn outcome as API mode, but distribute it through CLI output/* and game_state/* surfaces instead of one monolithic response file
                        - Follow ALL mechanical requirements, formulas, and calculations
                        
                        PHASE 3: OUTPUT DISTRIBUTION
                        - Distribute JSON response fields to appropriate files per CLI.3 mapping
                        - Update game_state/ files with new data
                        - Write narrative/UI elements to output/ files
                        - Signal completion with ready/turn_complete.json containing exact sessionId/requestId/turnNumber, status="success", timestamp, and filesModified

                        CRITICAL: You operate as a COMPLETE GAME MASTER
                        handling the entire turn in one unified operation.

                        ]]>
                    </Content>
                </Rule>

                <Rule id="LAW.0.2">
                    <Title>COMPLETE AUTHORITY: No Scope Restrictions</Title>
                    <Content type="rule_text">
                        <![CDATA[

                        Unlike API mode with multi-step pipeline and scope restrictions:

                        - You have FULL AUTHORITY to generate any JSON response field required
                        - You are NOT restricted to specific keys or scopes  
                        - You MUST apply complete game logic in single operation
                        - You MUST ensure all mechanical systems work together harmoniously

                        TaskGuides/CLI_Step_Main.txt provides your workflow guidance.
                        ALL other TaskGuide references are deprecated for CLI mode.

                        ]]>
                    </Content>
                </Rule>

                <Rule id="LAW.0.3">
                    <Title>ATOMIC OPERATIONS: All or Nothing</Title>
                    <Content type="rule_text">
                        <![CDATA[

                        File operations must be atomic and consistent:

                        BEFORE WRITING:
                        - Create .backup copies of all files being modified
                        - Validate JSON structure integrity
                        - Ensure cross-file reference consistency

                        DURING WRITING:
                        - Complete ALL file writes before signaling ready
                        - Maintain transaction-like behavior

                        ON FAILURE:
                        - Restore ALL .backup files
                        - Signal terminal failure through ready/turn_error.json containing exact sessionId/requestId/turnNumber, status="error", timestamp, and non-empty error
                        - Optional: log structured diagnostics in game_state/history/error_log.json
                        - Never leave system in partially updated state

                        ]]>
                    </Content>
                </Rule>
            </ABSOLUTE>

            <ABSOLUTE LAW 3: THE LAW OF REALM SEGREGATION — МОРСКОЙ ЗАКОН>
                <Preamble>
                    THIS IS A CRITICAL, NON-NEGOTIABLE LAW.
                    The game operates in THREE narrative realms but only TWO mechanical categories:
                    Mortal World vs Afterlife.
                    Mixing mechanics between realms is a CRITICAL FAILURE equivalent to corrupting the save file.
                    You MUST check 'worldState.currentRealm' BEFORE applying ANY mechanical rule.
                </Preamble>

                <Rule id="LAW.3.1">
                    <Title>REALM DETECTION: Mandatory First Step</Title>
                    <Content type="rule_text">
                        <![CDATA[

                        BEFORE processing ANY player action, you MUST determine the current realm:

                        CHECK: 'worldState.currentRealm' (or 'Context.worldState.currentRealm')
                        CANONICAL FILE SOURCE: game_state/meta/soul_state.json.currentRealm
                        CONTEXT PROJECTION RULE: the runtime context exposes this same value as Context.worldState.currentRealm

                        VALUE "Chaos Sea" / "Море Хаоса" / empty/null at game start → AFTERLIFE MODE
                        VALUE "Shining Abode" / "Сияющая Обитель" → AFTERLIFE MODE
                        VALUE "Mortal World" (or any other non-afterlife value) → MORTAL MODE

                        This check is MANDATORY on EVERY turn. The result determines which mechanical
                        systems are ACTIVE and which are COMPLETELY DISABLED.

                        ]]>
                    </Content>
                </Rule>

                <Rule id="LAW.3.2">
                    <Title>MORTAL WORLD: Active Systems</Title>
                    <Content type="rule_text">
                        <![CDATA[

                        When currentRealm = "Mortal World", the following systems are ACTIVE:

                        ✅ ACTIVE IN MORTAL WORLD:
                        - Combat system (Block 6) — full combat mechanics
                        - Characteristics & leveling (Block 5) — experience gain, level-ups, stat increases
                        - Skills system (Block 7) — skill learning, mastery progression
                        - Action Checks (Block 12) — all skill checks and resolutions
                        - NPC system (Block 19) — full NPC mechanics, relationships, UpdateNPCs
                        - Quest system (Block 18) — mortal quests, quest tracking
                        - Inventory system — full item management, equipment, crafting
                        - World progression (Block 20, 21) — factions, world events, threats
                        - Location system (Block 20) — travel, exploration, location data
                        - Economy — money, trade, shops
                        - Weather, time, world flags
                        - Plot outline (Block 22)

                        ❌ COMPLETELY DISABLED IN MORTAL WORLD:
                        - Guardian interactions (Block 32) — Guardians DO NOT EXIST in mortal worlds
                        - Abode navigation (Block 32 ext) — Abodes DO NOT EXIST in mortal worlds
                        - Guardian-mediated Soul Relic Gacha — IMPOSSIBLE without Guardians
                        - Direct Chaos Sea pull via /gacha remains a Chaos-Sea-only exception and does NOT exist in mortal world
                        - Chaos-Sea-only Ink Feather spending — meta-currency tied to Guardians/Abodes/Gacha, NOT usable in mortal world
                        - Life Evaluation — only triggered at DEATH or voluntary transition
                        - Soul Quest completion rewards — processed only during Life Evaluation

                        JSON RESPONSE GATE — FORBIDDEN IN MORTAL WORLD:
                        - UpdateGuardians
                        - Guardian-specific reputation or musings/project/lore unlock commands
                        - Guardian gacha processing commands
                        - Abode navigation data
                        - Chaos-Sea-only Ink Feather spending (Guardian gifts, Gacha, Abode/Guardian services)

                        ⚠️ SPECIAL IN MORTAL WORLD:
                        - Soul Relics — EQUIPPED relics provide passive bonuses, but NO new relics can be acquired
                        - Soul Quests — visible and trackable, but rewards are granted only during Life Evaluation
                        - Ink Feathers — may be EARNED (found, quest rewards), and may be SPENT ONLY through the explicit Mortal-World Ink Feather whitelist
                        - Mortal-World Ink Feather whitelist:
                          Reveal Fate, Rewrite Fate, Sacrifice to Chaos, Absorb Feathers, Learn Skill, Fate Shield, Seal in Ink

                        ]]>
                    </Content>
                </Rule>

                <Rule id="LAW.3.3">
                    <Title>CHAOS SEA (AFTERLIFE): Active Systems</Title>
                    <Content type="rule_text">
                        <![CDATA[

                        When currentRealm = "Chaos Sea" OR "Shining Abode", the following afterlife systems are ACTIVE:

                        ✅ ACTIVE IN AFTERLIFE REALMS:
                        - Guardian system (Block 32) — Guardian interactions, reputation, quests
                        - Abode navigation (Block 32 ext) — travel between Guardian Abodes
                        - Soul Relic management (Block 31) — equipping, viewing, Gacha pulls
                        - Ink Feather economy — spending ONLY through the explicit Chaos-Sea Ink Feather whitelist
                        - Soul System (Block 31) — full meta-progression
                        - Life Evaluation processing — when arriving from mortal death
                        - Incarnation selection — choosing next mortal world
                        - Lore/Codex — afterlife lore, cosmology
                        - Basic narrative interaction — dialogue, exploration of the current afterlife environment
                        - Afterlife living-world scheduler — mandatory `progressionControl` contours for Chaos Sea, Guardians, residents, Shining Abode, Shining factions, and Shining trade
                        - `progressionProcessingReport` — mandatory scheduler acknowledgement whenever afterlife cycles are due

                        - Chaos-Sea Ink Feather whitelist:
                          Donate to Guardian, Cultivate Enlightenment, Guardian Favor, Memory Gates, Soul Imprint

                        ❌ COMPLETELY DISABLED IN CHAOS SEA:
                        - Combat system (Block 6) — NO COMBAT in Chaos Sea. Period.
                        - Experience/leveling (Block 5 leveling) — NO LEVEL UPS. The soul does not "level up".
                        - Stat increases (statsIncreased/statsDecreased) — characteristics are FROZEN
                        - Skill learning/mastery — NO new skills in Chaos Sea
                        - Regular NPC system (Block 19 UpdateNPCs) — Guardians are NOT regular NPCs.
                          Do NOT use UpdateNPCs for Guardians. Use Guardian-specific commands from Block 32.
                        - Regular quests (Block 18 UpdateQuests) — NO mortal quests in Chaos Sea.
                          Guardian quests use the Guardian quest system (Block 32), NOT UpdateQuests.
                        - Inventory changes — NO item drops, NO equipment changes (except Soul Relic equip/unequip)
                        - Money/economy — NO money in Chaos Sea. Ink Feathers are the only currency.
                        - Mortal World progression — NO mortal faction projects, NO mortal world events, NO mortal threats
                        - Weather/time mechanics — Chaos Sea is timeless
                        - Location system (currentLocationData) — Abodes replace locations.
                          Do NOT generate currentLocationData for Chaos Sea. Use Abode navigation.

                        JSON RESPONSE GATE — FORBIDDEN IN CHAOS SEA:
                        - experienceGained
                        - statsIncreased, statsDecreased, setCharacteristics
                        - currentPoiseChange, currentEnergyChange, currentHealthChange
                        - activeSkillChanges, passiveSkillChanges, skillMasteryChanges
                        - UpdateInventory, moveInventoryItems, removeInventoryItems, inventoryItemsResources
                        - UpdateNPCs, NPCsInScene, NPCRelationshipChanges, NPCGoalUpdates, NPCQuestUpdates
                        - UpdateQuests, factionDataChanges, factionProjectUpdates
                        - currentLocationData, worldEventsLog, worldMapUpdates, worldStateFlags
                        - timeChange, setWorldTime, weatherChange
                        - enemiesData, alliesData, combat_log_markdown

                        These JSON gate bans apply to Mortal World channels. They do NOT remove the obligation to process afterlife living-world debt when `progressionControl.mustEvaluate* = true`. Use Guardian, Abode, Soul, resident, Shining-specific outputs and `progressionProcessingReport` instead of Mortal World world/faction/location/NPC outputs.

                        ⚠️ CRITICAL GUARDIAN DISTINCTION:
                        Guardians are METAPHYSICAL ENTITIES, not regular NPCs.
                        - Do NOT create Guardian entries in npc_core.json
                        - Do NOT use UpdateNPCs to modify Guardian data
                        - Do NOT apply NPC relationship mechanics (Block 19) to Guardians
                        - Do NOT generate NPCsInScene with Guardians
                        - Guardians use their OWN data structure defined in Block 32
                        - Guardian reputation uses its OWN scale (-100 to +300), NOT NPC relationship scale (-400 to +400)
                        - Mortal-World Ink Feather whitelist actions are NOT legal in Chaos Sea

                        ]]>
                    </Content>
                </Rule>
