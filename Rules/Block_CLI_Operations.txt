  <rule id="CLI.2">
   <title>
    Turn Processing Workflow
   </title>
   <description>
    Defines the step-by-step process for CLI Agent turn execution.
   </description>
   <content type="rule_text">
    <![CDATA[

                    The CLI Agent processes turns using this workflow:

                    **PHASE 1: TRIGGER DETECTION**
                    1. Monitor input/turn_request.json for new file creation or modification
                    2. Validate turn_request.json schema and content
                    3. Set processing lock to prevent concurrent execution

                    **PHASE 2: STATE LOADING**
                    1. Read all relevant files from game_state/ directories
                    2. Construct complete game context object (equivalent to API request context)
                    3. Validate data integrity and cross-references
                    4. If needed, write optional structured diagnostics (for example game_state/history/error_log.json), but the authoritative terminal error path is still ready/turn_error.json

                    **PHASE 3: RULE APPLICATION**
                    1. Apply existing TaskGuides (Step_0, Step_1, Step_2) using loaded context
                    2. Use ALL existing rule blocks (1-32) exactly as written
                    3. Generate complete response object as if processing API request
                    4. Log all calculations in output/debug_logs.json

                    **PHASE 4: STATE DISTRIBUTION**
                    1. Parse response object according to CLI.3 (File Distribution Protocol)
                    2. Update affected files in game_state/ directories using atomic operations
                    3. Create backup files before any modifications (.backup extension)
                    4. Validate written data against schemas

                    **PHASE 5: CLIENT COMMUNICATION**
                    1. Generate output/narrative_response.json for client display
                    2. Generate output/interface_updates.json only if this turn actually changes dialogueOptions and/or image_prompt
                    3. Update output/debug_logs.json with GM thoughts
                    3.A. Treat output/*.json as fresh per-turn transient artifacts for the CURRENT sessionId/requestId/turnNumber only
                        - rewrite current-turn payloads fully
                        - do NOT append cross-turn history there
                        - do NOT leave stale previous-turn payloads in place as if they were still valid
                    4. Create ready/turn_complete.json signal file
                    5. Clean up backup files on successful completion

                    **ERROR HANDLING:**
                    - If any phase fails, restore all .backup files
                    - Optionally log detailed diagnostics in game_state/history/error_log.json
                    - Create ready/turn_error.json with error details (authoritative client channel)
                    - Never leave the system in a partial update state

                    - game_state/meta/soul_state.json
