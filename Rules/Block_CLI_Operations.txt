 <title>
  CLI Agent File System Operations
 </title>
 <description>
  This block defines how the CLI Agent operates with the file-based game system. It provides protocols for reading game state, 
  processing turns, and writing distributed game data to maintain full compatibility with existing rule blocks.
 </description>
 <instructiontext>
  <![CDATA[

            The CLI Agent operates as a Game Master in a file-based environment. Instead of receiving a single JSON request and returning a single JSON response, 
            the CLI Agent monitors file system changes, reads distributed game state, processes turns using existing rule blocks, 
            and writes results back to distributed JSON files.

            ALL EXISTING RULE BLOCKS (1-32) REMAIN FULLY APPLICABLE. The CLI Agent simply adapts the input/output mechanism 
            while preserving all game logic, calculations, formulas, and narrative rules.

            ]]>

   <description>
    Defines the standard folder structure and file organization for CLI-based game sessions.
   </description>
   <content type="rule_text">
    <![CDATA[

                    The CLI Agent operates within a standardized folder structure:

                    game_session/
                    ├── input/                      # Entry point for new turns
                    │   └── turn_request.json       # Main turn processing trigger
                    ├── game_state/                 # Distributed game data (55+ JSON files)
                    │   ├── core/                   # Narrative & player status (3 files)
                    │   ├── player/                 # Player character data (10 files)
                    │   ├── inventory/              # Item system (8 files)
                    │   ├── world/                  # World state (7 files)
                    │   ├── quests/                 # Quest management (3 files)
                    │   ├── npcs/                   # NPC system (14 files)
                    │   ├── combat/                 # Combat state (3 files)
                    │   ├── factions/               # Faction system (6 files)
                    │   ├── meta/                   # Soul System & Guardians (5 files)
                    │   ├── misc/                   # Vehicles & storage (5 files)
                    │   ├── control/                # Game flow control (3 files)
                    │   └── history/                # Chat and interaction history (3 files)
                    ├── lore/                       # Lore and active world dossiers
                    │   ├── chaos_sea/              # Persistent meta-lore across incarnations
                    │   ├── current_world/          # Current incarnation world lore
                    ├── world_profiles/            # Reusable mortal-world profiles (one file = one profile)
                    ├── mods/                       # Global system mods (one file = one mod)
                    ├── saves/                      # Save/load system
                    │   ├── autosaves/              # Automatic saves
                    │   ├── manual_saves/           # Player manual saves
                    │   └── checkpoint_saves/       # Life transition saves
                    ├── output/                     # Client communication
                    │   ├── narrative_response.json # Main narrative
                    │   ├── interface_updates.json  # UI updates
                    │   └── debug_logs.json         # GM thoughts for debugging
                    ├── ready/                      # Processing completion signals
                    │   ├── turn_complete.json     # Signals processing is done
                    │   └── turn_error.json        # Signals processing error
                    └── rules/                      # Symbolic links to rule blocks (readonly)
                        ├── Block_1.txt → ../../../Rules/Block_1.txt
                        ├── Block_2.txt → ../../../Rules/Block_2.txt
                        └── ... (all rule blocks)

                    CRITICAL: The CLI Agent MUST NOT modify files in the rules/ directory. These are readonly references.

  <rule id="CLI.2">
   <title>
    Turn Processing Workflow
   </title>
   <description>
    Defines the step-by-step process for CLI Agent turn execution.
   </description>
   <content type="rule_text">
    <![CDATA[

                    The CLI Agent processes turns using this workflow:

                    **PHASE 1: TRIGGER DETECTION**
                    1. Monitor input/turn_request.json for new file creation or modification
                    2. Validate turn_request.json schema and content
                    3. Set processing lock to prevent concurrent execution

                    **PHASE 2: STATE LOADING**
                    1. Read all relevant files from game_state/ directories
                    2. Construct complete game context object (equivalent to API request context)
                    3. Validate data integrity and cross-references
                    4. If needed, write optional structured diagnostics (for example game_state/history/error_log.json), but the authoritative terminal error path is still ready/turn_error.json

                    **PHASE 3: RULE APPLICATION**
                    1. Apply existing TaskGuides (Step_0, Step_1, Step_2) using loaded context
                    2. Use ALL existing rule blocks (1-32) exactly as written
                    3. Generate complete response object as if processing API request
                    4. Log all calculations in output/debug_logs.json

                    **PHASE 4: STATE DISTRIBUTION**
                    1. Parse response object according to CLI.3 (File Distribution Protocol)
                    2. Update affected files in game_state/ directories using atomic operations
                    3. Create backup files before any modifications (.backup extension)
                    4. Validate written data against schemas

                    **PHASE 5: CLIENT COMMUNICATION**
                    1. Generate output/narrative_response.json for client display
                    2. Generate output/interface_updates.json only if this turn actually changes dialogueOptions and/or image_prompt
                    3. Update output/debug_logs.json with GM thoughts
                    3.A. Treat output/*.json as fresh per-turn transient artifacts for the CURRENT sessionId/requestId/turnNumber only
                        - rewrite current-turn payloads fully
                        - do NOT append cross-turn history there
                        - do NOT leave stale previous-turn payloads in place as if they were still valid
                    4. Create ready/turn_complete.json signal file
                    5. Clean up backup files on successful completion

                    **ERROR HANDLING:**
                    - If any phase fails, restore all .backup files
                    - Optionally log detailed diagnostics in game_state/history/error_log.json
                    - Create ready/turn_error.json with error details (authoritative client channel)
                    - Never leave the system in a partial update state

                    ]]>
